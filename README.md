# THE LAST CARAVAN

THE LAST CARAVAN은 2~4명이 이동식 마을(마차)을 함께 지키는 협동 액션 로그라이크 게임입니다.
이 저장소에는 야영지와 낮과 밤이 이어지는 프로토타입이 있습니다. 방은 야영지에서 시작하고, 모두가 준비하면 원정이 시작됩니다. 플레이어들은 맵 한가운데의 마차를 사흘 밤 동안 몰려오는 몬스터로부터 지킵니다. 낮에는 먼 곳의 채집 지점에서 자원을 모아 마차에 가져다 두고, 그 자원으로 마차 가까이에 감시탑을 세웁니다. 또 몬스터가 지키는 무기 상자를 열어서 무기를 얻습니다. 플레이어는 무기를 두 개까지 가지고 다니며 `Q`로 바꿔 듭니다. 밤에는 감시탑과 함께 몬스터를 막고, 쓰러진 동료를 부활시키고, 손상된 마차를 수리합니다. 전용 서버가 이동, 전투, 채집, 건설, 부활, 수리, 상자 열기, 무기 줍기, 준비와 확인의 결과를 모두 판정합니다.

## 설치하기

아래 명령은 macOS에서 확인했습니다.

1. rustup을 설치합니다. 설치가 끝나면 새 터미널을 엽니다.

   ```sh
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   ```

2. 저장소를 내려받고 저장소 폴더로 이동합니다.

   ```sh
   git clone https://github.com/sky629/the_last_caravan.git
   cd the_last_caravan
   ```

3. 고정된 툴체인을 설치합니다. `rust-toolchain.toml`이 Rust 1.100.0, rustfmt, clippy, `wasm32-unknown-unknown` 타깃을 지정하므로, 저장소 폴더에서 이 명령 하나로 웹 빌드용 타깃까지 설치됩니다.

   ```sh
   rustup toolchain install
   ```

   `rustc --version`이 `rustc 1.100.0`을 출력하고 `rustup target list --installed`에 `wasm32-unknown-unknown`이 있으면 설치가 끝난 것입니다.

4. 웹 빌드 도구인 trunk 0.22.2를 설치합니다. trunk는 처음 웹 빌드를 할 때 `Cargo.lock`에 맞는 버전의 wasm-bindgen을 내려받습니다.

   ```sh
   cargo install --locked trunk --version 0.22.2
   ```

Ubuntu에서 클라이언트를 빌드하려면 Bevy가 링크하는 라이브러리를 먼저 설치합니다. CI가 설치하는 목록과 같습니다.

```sh
sudo apt-get install pkg-config libudev-dev libwayland-dev
```

## 실행하기

### 전용 서버를 실행합니다

클라이언트보다 서버를 먼저 실행합니다. 서버는 `listening on ws://127.0.0.1:7777`을 출력하고, 그 뒤에는 일어난 일만 한 줄씩 출력합니다. 출력하는 일은 플레이어의 입장과 퇴장(방 코드와 인원), 접속이 끊긴 자리의 유지와 복귀, 방의 생성과 제거, 한도 때문에 서버가 닫은 접속과 그 이유, 시작 오류입니다. `Ctrl-C`로 종료합니다.

```sh
cargo run -p caravan_dedicated
```

플레이어 한 명이 방 `test`에 들어갔다가 나가면 출력은 다음과 같습니다. 방 코드를 비우고 들어온 플레이어를 위해 서버가 방 코드를 만들면(다섯 글자) 그 코드가 `test` 자리에 나옵니다. 플레이어의 이름은 이 로그에 남기지 않습니다. `--debug-net`을 켜면 주고받는 메시지를 그대로 출력하므로 이름도 출력됩니다.

```text
listening on ws://127.0.0.1:7777
room test created (seed 8201742364921307566)
player 1 joined room test (1 members)
player 1 left room test (0 members)
room test removed
```

| 옵션 | 설명 |
|---|---|
| `--addr HOST:PORT` | 접속을 받을 주소입니다. 기본값은 `127.0.0.1:7777`입니다. 다른 컴퓨터에서 접속하려면 `0.0.0.0:7777`을 지정합니다. |
| `--debug-net` | 주고받는 모든 메시지를 읽을 수 있는 형태로 출력합니다. 스냅샷은 몬스터 목록을 수로 줄여서 출력합니다. |
| `--stats` | 1초마다 방, 플레이어, 몬스터의 수와 Tick 시간의 평균과 최대를 한 줄씩 출력합니다. 예를 들면 `stats rooms=1 members=2 monsters=87 ticks=20 tick_avg_ms=0.31 tick_max_ms=1.20`입니다. |
| `--waves SIZE,SIZE,.../SIZE,...` | 밤마다 무리의 수와 무리마다 몬스터의 수를 바꿉니다. 밤은 `/`로, 무리는 `,`로 나누고, 밤의 수가 원정의 날 수입니다. `--waves 100,200,300`은 밤 하나에 무리 셋(100마리, 200마리, 300마리)을, `--waves 8,12/20,30,40`은 밤 둘(첫째 밤 8마리와 12마리, 둘째 밤 20마리, 30마리, 40마리)을 정합니다. 적은 수는 네 명이 있을 때의 크기이고, 밤이 시작될 때 방에 있는 사람이 네 명보다 적으면 그 수에 비례해서 줄어듭니다(`--stress`와 함께 쓰면 줄어들지 않습니다). 서버가 시작할 때 출력하는 `wave sizes by night for 4 players`가 이 수입니다. |
| `--stress` | 마차, 감시탑, 플레이어가 죽지 않게 하고, 감시탑을 상한(40개)만큼 미리 세우고, 낮을 한 Tick으로 줄이고, 몬스터를 Tick마다 한 마리씩 등장시킵니다. 새 원정이 시작될 때마다 감시탑이 다시 서 있습니다. 플레이어는 검과 활을 함께 가지고 시작합니다. 사람의 조작 없이 원정이 진행되어야 하므로 야영지를 건너뜁니다. 방은 만들어지자마자 첫날을 시작하고, 결과를 한 Tick만 보여 준 뒤 새 원정을 시작합니다. |
| `--seed N` | 모든 방의 무작위를 씨앗 `N`(0 이상의 정수) 하나로 정합니다. 주지 않으면 방마다, 서버를 실행할 때마다 다른 씨앗을 씁니다. 방을 만들 때 출력하는 `seed` 값을 이 옵션에 주면 같은 상태에서 다시 시작하므로, 판에서 본 일을 다시 만들 수 있습니다. 예를 들어 `--seed 7`이면 첫 원정의 첫날 상자는 (17, 32)에 활, (32, 17)에 소총, (49, 49)에 활이 든 채로 놓입니다. `crates/rules/src/tests/chests.rs`의 `seed_7_places_these_three_chests_on_the_first_day`가 이 값을 고정합니다. |

`--waves`와 `--stress`는 몬스터가 수백 마리일 때 서버의 Tick 시간과 스냅샷의 크기를 재기 위한 부하 시험용 옵션입니다. Tick 시간은 `--stats`를 붙여야 출력됩니다. 부하 시험용 클라이언트가 하나만 접속해도 몬스터가 수백 마리 나오게 하려면 `--stress`를 함께 씁니다. `--stress`가 아닌 서버에서는 무리의 크기가 방의 인원에 비례하기 때문입니다.
부하 시험용 클라이언트(`crates/dedicated/examples/load_client.rs`)는 Bevy 없이 한 방에 접속해서 Tick마다 입력을 보내고, 받은 스냅샷의 크기와 몬스터 수를 1초마다 출력합니다. 야영지에서는 준비 키를, 결과 화면에서는 확인 키를 스스로 누르므로 사람의 조작 없이 원정이 되풀이됩니다. `--stress`가 아닌 서버에서는 준비한 뒤 카운트다운(3초)이 지나야 원정이 시작됩니다.

```sh
cargo run --release -p caravan_dedicated -- --stress --waves 100,200,300 --stats
cargo run --release -p caravan_dedicated --example load_client -- --addr 127.0.0.1:7777 --room load --secs 60
```

부하 시험용 클라이언트의 옵션은 `--addr HOST:PORT`, `--room CODE`, `--name NAME`(기본값 `load`), `--secs SECONDS`, `--passive`, `--bow`입니다. `--passive`를 붙이면 공격하지 않으므로 몬스터가 가장 많이 쌓입니다. `--bow`를 붙이면 원정마다 한 번 활로 바꾸고 탄환을 쏩니다(서버를 `--stress`로 실행해야 활을 가지고 있습니다). 활은 쿨다운이 있으므로 플레이어 넷이 `--bow`로 쏴도 동시에 날아다니는 탄환은 한 자릿수입니다(감시탑 40개가 서 있고 몬스터가 260마리쯤 몰릴 때 측정한 최대는 6개입니다). 탄환이 100개 넘게 날아다니는 부하는 이 시험이 아니라 `cargo test --release -p caravan_rules perf -- --nocapture`의 시험이 만듭니다. 부하 시험용 클라이언트가 출력하는 `projectiles=`와 마지막 줄의 `peak_projectiles`로 날아다니는 탄환의 수를 확인할 수 있습니다. `--secs 60`으로는 몬스터가 181마리까지만 모이므로, 260마리 넘게 모으려면 `--secs 150`이 필요합니다.

### PC 클라이언트를 실행합니다

옵션 없이 실행하면 시작 화면이 나옵니다. 이름(`NAME`)과 방 코드(`ROOM`)를 입력하고 `Enter`를 누르면 입장합니다.

```sh
cargo run -p caravan_client
```

- 방 코드를 비우고 `Enter`를 누르면 서버가 새 방을 만들고 코드를 정합니다. 만들어진 코드는 야영지 화면에 나옵니다.
- 이름은 1~12자의 영문자, 숫자, 공백, `-`, `_`입니다. 앞뒤 공백은 지워집니다. 이름이 겹쳐도 입장할 수 있습니다.
- 방 코드는 1~16자의 `a-z`, `0-9`, `-`, `_`이고 대문자는 소문자로 바뀝니다. 없는 코드를 넣으면 그 코드로 방이 만들어지고, 마지막 사람이 나가면 방이 사라집니다.
- `Tab`으로 칸을 옮기고, `Ctrl+V`(macOS는 `Cmd+V`)로 붙여 넣고, `Backspace`로 지웁니다.
- 입장이 거절되거나 접속이 끊기면 시작 화면으로 돌아오고 이유가 나옵니다. 입력한 이름과 방 코드는 그대로 남아 있습니다.
- 접속이 끊긴 뒤 60초 안에 같은 방 코드로 `Enter`를 누르면 같은 캐릭터로 돌아옵니다(위치, HP, 든 무기가 그대로입니다). 방 코드를 비우고 입장해서 서버가 코드를 정한 방도 같습니다. 끊긴 뒤의 시작 화면에는 그 방 코드가 이미 채워져 있기 때문입니다. 60초가 지났거나 다른 방 코드를 넣었으면 새 플레이어로 입장합니다.
- 같은 자리로 다른 창이 입장하면 먼저 있던 창은 시작 화면으로 돌아오고 `Seat taken over: Another window took over this seat`를 보여 줍니다. 그 창에서 `Enter`를 누르면 자리를 다시 가져옵니다.
- 방 안에서 `Esc`를 누르면 서버에 나간다고 알리고 접속을 버린 뒤 시작 화면으로 돌아옵니다. 서버는 그 자리를 곧바로 내놓고, 이 기기는 그 자리의 표식을 지웁니다. 방 코드는 칸에 남지만, 다시 `Enter`를 누르면 새 플레이어로 입장합니다.
- 야영지에서 `C`를 누르면 방 코드를 클립보드에 복사하고, 친구는 그 코드를 방 코드 칸에 붙여 넣습니다.
- 마지막으로 입장한 이름과 방 코드와 그 방의 자리의 표식은 설정 폴더의 `the-last-caravan/memory.txt`에 저장되고, 이름과 방 코드는 다음 실행에서 칸에 미리 채워집니다. 표식은 그 자리를 이어받는 유일한 자격이므로 링크와 로그에 넣지 않습니다. 설정 폴더는 Windows가 `%APPDATA%`, macOS가 `~/Library/Application Support`, 그 밖의 시스템은 `$XDG_CONFIG_HOME` 또는 `~/.config`입니다. 저장하지 못하면 경고만 남기고 계속 실행합니다.

옵션에 이름과 방 코드를 모두 주면 시작 화면 없이 곧바로 입장합니다. 둘 중 하나만 주면 시작 화면의 해당 칸이 미리 채워집니다. 두 클라이언트를 같은 방에 넣으려면 터미널 두 개에서 같은 방 코드로 실행합니다. 두 창에 같은 맵과 두 캐릭터가 나타나고, 캐릭터 위와 준비 목록에 이름이 보입니다. 두 클라이언트는 같은 컴퓨터의 같은 설정 폴더를 쓰므로 `--profile`로 저장 파일을 나눕니다.

```sh
cargo run -p caravan_client -- --name KANG --room test --profile kang
cargo run -p caravan_client -- --name MIRO --room test --profile miro
```

다른 방 코드로 실행한 클라이언트는 다른 방에 들어가므로, 위의 두 클라이언트와 서로 보이지 않습니다.

```sh
cargo run -p caravan_client -- --name HANA --room other
```

| 옵션 | 설명 |
|---|---|
| `--name NAME` | 이름입니다. 시작 화면의 이름 칸을 미리 채웁니다. |
| `--room CODE` | 방 코드입니다. 시작 화면의 방 코드 칸을 미리 채웁니다. 주지 않으면 이 기기에서 마지막으로 입장한 방 코드가 채워집니다. |
| `--server URL` | 서버 주소입니다. 기본값은 `ws://127.0.0.1:7777`입니다. `ws://`나 `wss://`로 시작해야 합니다. |
| `--debug-net` | 주고받는 메시지를 로그에 출력합니다. |
| `--profile NAME` | 이 기기가 기억하는 것을 `memory-NAME.txt`에 따로 저장합니다(1~16자의 영문자, 숫자, `-`, `_`). 같은 컴퓨터에서 클라이언트 두 개를 실행해 두 사람을 시험할 때 서로 다른 이름을 주면 한 자리를 서로 가져가지 않습니다. 주지 않으면 `memory.txt`입니다. |

옵션이 잘못되었으면 시작 화면에 이유가 나오고 입장할 수 없습니다. 서버에 접속하지 못하면 시작 화면으로 돌아오고, 접속하려 한 서버 주소와 서버가 실행 중인지 확인하라는 안내가 나옵니다. 클라이언트는 1초마다 프레임 속도, 가장 최근에 받은 서버 Tick, 그 스냅샷의 몬스터 수를 로그로 출력합니다.

### 웹 클라이언트를 실행합니다

`crates/client`에서 `trunk serve`를 실행하면 trunk가 클라이언트를 wasm으로 빌드하고 `http://127.0.0.1:8080/`에서 페이지를 제공합니다.

```sh
cd crates/client
trunk serve
```

브라우저에서 `http://127.0.0.1:8080/`를 열면 PC와 같은 시작 화면이 나옵니다. 주소의 쿼리는 PC 클라이언트의 옵션과 같은 규칙으로 해석됩니다. 마지막으로 입장한 이름과 방 코드와 그 방의 자리의 표식은 브라우저의 `localStorage`(`caravan.memory`)에 저장되어, 새로 고침 뒤에도 칸이 채워지고 같은 자리로 돌아올 수 있습니다. 사생활 보호 창처럼 저장소를 막는 곳에서는 저장하지 못하고, 그때는 매번 빈 칸으로 시작하며 접속이 끊기면 새 플레이어로 입장합니다. 같은 브라우저 프로필의 탭은 저장소를 함께 쓰므로 한 자리를 서로 가져갑니다. 한 컴퓨터에서 두 사람을 시험하려면 서로 다른 브라우저 프로필(또는 한쪽은 사생활 보호 창)을 씁니다.

| 쿼리 | 설명 |
|---|---|
| `room=CODE` | 방 코드입니다. 시작 화면의 방 코드 칸을 미리 채웁니다. 주지 않으면 이 브라우저에서 마지막으로 입장한 방 코드가 채워집니다. |
| `name=NAME` | 이름입니다. 시작 화면의 이름 칸을 미리 채웁니다. |
| `server=URL` | 서버 주소입니다. 기본값은 `ws://127.0.0.1:7777`입니다. |
| `debug-net` | 주고받는 메시지를 브라우저 개발자 도구의 콘솔에 출력합니다. |

모든 쿼리를 쓴 주소는 `http://127.0.0.1:8080/?room=test&name=KANG&server=ws://127.0.0.1:7777&debug-net`입니다. `room`과 `name`이 모두 있으면 시작 화면 없이 곧바로 입장합니다. 웹 클라이언트와 PC 클라이언트에 같은 방 코드를 주면 같은 방에서 함께 플레이합니다.

야영지에서 `C`를 누르면 `http://127.0.0.1:8080/?room=k7m2q`처럼 방 코드가 든 링크를 클립보드에 복사합니다(기본이 아닌 서버를 쓰고 있으면 `&server=`가 붙습니다). 친구가 이 링크를 열면 방 코드 칸이 채워진 시작 화면이 나오고, 이름만 넣고 입장하면 됩니다. 시작 화면에서 `Ctrl+V`나 `Cmd+V`를 누르면 브라우저가 클립보드를 읽어도 되는지 한 번 묻고, 거절하면 칸은 그대로이고 안내 한 줄이 나옵니다. 브라우저의 클립보드 기능은 `https://`나 `localhost`, `127.0.0.1`이 아닌 주소(예를 들면 `http://192.168.0.5:8080`)에서는 제공되지 않을 수 있고, 그때는 복사와 붙여 넣기가 되지 않습니다.

### 게임의 진행

방은 야영지에서 시작합니다. 야영지는 원정과 같은 지도이고, 몬스터와 상자와 채집 지점이 없습니다. 마차 동쪽에 허수아비 셋이 한 줄로 서 있고, 마차 북쪽에 무기마다 하나씩 여섯 진열대가 있습니다. 진열대에서 `F`를 누른 순간 그 무기를 집을 수 있고, 진열대에는 무기가 그대로 남습니다. 이미 가진 종류의 진열대에서는 집지 않고, 두 칸이 모두 차 있으면 든 무기를 내주며, 내준 무기는 바닥에 놓이지 않고 사라집니다. 허수아비는 맞아도 사라지지 않고, 맞은 피해가 허수아비 위에 숫자로 뜹니다. 허수아비에게도 무기의 효과가 걸려서 몸통 색이 효과의 색으로 바뀌지만, 야영지에서는 피해를 적용하지 않으므로 출혈은 피해를 주지 않고 출혈의 숫자도 뜨지 않습니다. 야영지에서는 아무도 피해를 받지 않고 건설할 수 없습니다. 화면 오른쪽 위에 방 코드와 `C` 안내(`ROOM k7m2q   C  COPY LINK`), 방에 있는 모든 플레이어의 준비 목록이 `KANG  (YOU)  READY`처럼 이름과 함께 나오고(자리를 비운 사람은 준비했는지와 관계없이 `MIRO  AWAY`입니다), `R`을 누르면 준비를 켜고 끕니다. 방에 있는 모두가 준비하면 `STARTING IN 3`이 3초를 세고 원정이 시작되며, 그 사이에 누가 준비를 끄거나 준비하지 않은 사람이 들어오면 세던 시간이 취소됩니다. 준비한 사람이 방에서 나가는 것은 취소하지 않습니다. 원정이 시작되면 모든 플레이어가 검 하나, 최대 HP로 등장 지점에 서고, 야영지의 허수아비와 진열대는 사라집니다. 원정이 진행되는 방에 들어온 사람은 마차 곁에서 바로 합류합니다. 야영지에서 60초 동안 조작(이동, 조준, 버튼의 바뀜)이 없는 사람은 키를 누르고 있기만 해도 자리를 비운 것으로 보여서 「모두 준비」의 대상에서 빠지고, 나머지가 시작합니다. 그 사람의 자리는 남고, 조작하면 준비하지 않은 상태로 돌아옵니다. 그 사람 없이 시작한 원정에서는 조작할 때까지 캐릭터가 몬스터와 피해로부터 보호받습니다. 접속이 끊겨서 서버가 60초 동안 자리를 유지하는 사람도 같은 방식으로 자리를 비운 것으로 보입니다. 다른 사람의 화면에서 그 캐릭터는 반투명해지고 이름 뒤에 `AWAY`가 붙으며, 결과 화면의 확인 인원(`(1 / 2)`)은 자리를 비운 사람을 세지 않습니다. 방에 자리에 있는 사람이 아무도 없으면 방의 시간이 멈추고, 누군가 돌아오면 멈춘 곳에서 이어집니다.

원정은 첫날의 낮으로 시작하고, 화면 오른쪽 위에 지금이 몇 번째 날의 낮인지 밤인지(`DAY 1 / 3`, `NIGHT 1 / 3`)와 낮의 남은 시간이나 무리의 번호가 나옵니다.

1. 낮은 90초 동안 이어지고, 플레이어들은 이 시간에 감시탑을 세우고 채집 지점에서 자원을 모읍니다. 보관함에는 처음부터 자원이 10 있어서 감시탑 하나를 바로 세울 수 있습니다. 채집 지점은 여덟 곳이고, 지점마다 낮의 몬스터 둘이 곁에서 지킵니다. 낮의 몬스터는 자기 자리에서 6타일 안으로 들어온 플레이어를 쫓고, 플레이어가 자리에서 6타일보다 멀어지면 자리로 돌아갑니다. 낮이 시작될 때 무기 상자 세 개가 후보 자리 여덟 곳 가운데 서로 다른 세 곳에 놓이고, 상자마다 낮의 몬스터 셋이 곁에서 지킵니다. 상자를 열어서 무기를 얻는 방법은 아래의 「무기」에 있습니다.
2. 낮이 끝나면 밤이 시작되고, 처치하지 않은 낮의 몬스터는 자리를 떠나 마차로 향하고, 열지 않은 상자는 사라집니다. 3초 뒤에 첫 무리가 마차에서 18타일 떨어진 곳에 한 마리씩 나타납니다. 무리마다 나타나는 방향이 달라지고, 여덟 방향을 모두 씁니다.
3. 무리의 몬스터를 모두 처치하면 4초 뒤에 그 밤의 다음 무리가 나타납니다. 그 밤의 마지막 무리를 처치하면 4초 뒤에 다음 날의 낮이 시작됩니다. 첫째 밤은 8마리와 12마리, 둘째 밤은 20마리, 30마리, 40마리, 셋째 밤은 60마리, 90마리, 150마리입니다. 이 수는 네 명이 있을 때의 크기입니다. 밤이 시작될 때 방에 있는 사람(자리를 비운 사람 포함)이 네 명보다 적으면 `올림(수 × 인원 / 4)`마리가 나오고, 무리마다 한 마리 이상입니다. 예를 들어 한 명이 있으면 첫째 밤은 2마리와 3마리이고, 두 명이면 4마리와 6마리입니다. 밤 도중에 들어오거나 나가도 그 밤의 무리의 크기는 바뀌지 않습니다. 낮의 몬스터(채집 지점과 상자를 지키는 몬스터)는 인원과 관계없이 같은 수입니다.
4. 다음 낮이 시작될 때 모든 플레이어가 최대 HP의 살아 있는 상태가 됩니다. 쓰러졌거나 사망한 플레이어도 그 자리에서 되살아납니다. 채집 지점은 다시 가득 차고, 낮의 몬스터가 지점마다 다시 놓이고, 무기 상자가 새로 놓입니다. 감시탑과 그 HP, 마차의 HP, 보관함과 플레이어가 든 자원, 땅에 떨어진 자원은 그대로 이어집니다.
5. 셋째 밤을 막으면 `EXPEDITION SUCCESS`가 나옵니다. 마차의 HP가 0이 되거나 모든 플레이어가 쓰러졌거나 사망하면 낮이든 밤이든 `EXPEDITION FAILED`가 나옵니다.
6. 결과 화면이 나오면 세계가 멈추고, 화면 가운데에 원정의 요약과 개인별 기록의 표가 나옵니다. 요약은 `DAYS 3 / 3    TIME 14:32    TOWER KILLS 41`처럼 버틴 날과 걸린 시간(분과 초)과 감시탑이 처치한 몬스터의 수이고, 표는 플레이어마다 한 줄이며 번호가 작은 사람이 위에 있습니다. 표의 칸은 `KILLS`(마지막 피해를 주어 처치한 몬스터), `REVIVES`(끝까지 마친 부활), `DOWNS`(쓰러진 횟수), `DEPOSITED`(보관함에 넣은 자원)입니다. 원정이 끝난 순간 방에 있던 사람은 자리를 비운 사람도 표에 있고, 결과 화면이 열린 뒤에 방을 나가도 그 줄은 남습니다. 요약과 표는 그 원정의 결과가 도착했을 때만 나옵니다. 그 아래에 확인한 사람의 수(`ENTER  BACK TO CAMP  (1 / 2)`)와 야영지로 돌아가기까지 남은 시간이 나옵니다. `Enter`로 각자 확인하고, 방에 있는 모두가 확인하거나 60초가 지나면 같은 사람들과 야영지로 돌아갑니다. 새 원정은 저절로 시작되지 않고, 야영지에서 다시 모두가 준비해야 시작됩니다. 새 원정이 시작되면 감시탑과 보관함과 마차의 HP가 처음으로 돌아갑니다.

살아 있는 플레이어가 마차에서 3타일 안에 있으면 낮이든 밤이든, 공격받는 중이든 HP가 1초에 5씩 회복됩니다. 쓰러진 플레이어는 회복되지 않습니다. 마차의 HP는 날이 바뀌어도 저절로 회복되지 않으므로, 플레이어가 마차 곁에서 `F`를 눌러 수리합니다. 수리는 감시탑을 짓는 것과 같은 보관함의 자원을 씁니다.

한 밤에 동시에 살아 있는 몬스터는 300마리까지이고, 이 수에 이르면 무리의 등장이 멈췄다가 몬스터가 줄면 이어집니다.

### 무기

플레이어는 무기를 두 칸에 가집니다. 원정은 검 하나와 빈 칸 하나로 시작하고, 나머지 무기는 낮에 상자에서 얻습니다. 무기마다 다른 수치는 `crates/rules/src/tuning.rs`의 무기 표(`WeaponTable`)에서 무기 하나가 한 행입니다. 몬스터를 맞혔을 때 거는 효과(`on_hit`)도 같은 행에 있습니다. 부채꼴의 거리는 플레이어의 가장자리에서 몬스터의 가장자리까지 잰 값이고, 각도는 조준 방향의 양쪽으로 잰 절반 각도입니다.

| 무기 | 화면의 이름 | 공격 방식 | 피해량 | 쿨다운 | 닿는 곳 | 맞은 몬스터에 거는 효과 | 상자에서 나옴 |
|---|---|---|---|---|---|---|---|
| 검 | `SWORD` | 부채꼴 | 25 | 0.5초 | 1.0타일, 양쪽으로 60도씩 | 출혈 (3초 동안 1초마다 5) | 아니요 (처음에 듭니다) |
| 대검 | `GREATSWORD` | 부채꼴 | 45 | 1.0초 | 1.3타일, 양쪽으로 90도씩 | 스턴 (0.8초) | 예 |
| 창 | `SPEAR` | 부채꼴 | 30 | 0.6초 | 2.2타일, 양쪽으로 15도씩 | 출혈 (3초 동안 1초마다 6) | 예 |
| 활 | `BOW` | 탄환 | 15 | 0.4초 | 초당 14타일의 속도, 사거리 9타일, 반지름 0.15타일, 한 마리 | 감속 (2초 동안 이동 속도 50%) | 예 |
| 석궁 | `CROSSBOW` | 관통하는 탄환 | 20 | 0.9초 | 초당 18타일의 속도, 사거리 11타일, 반지름 0.15타일, 최대 네 마리 | 감속 (2초 동안 이동 속도 50%) | 예 |
| 소총 | `RIFLE` | 즉시 명중 | 60 | 1.5초 | 사거리 12타일, 선의 굵기 0 | 스턴 (0.8초) | 예 |

몬스터(`Grunt`)의 HP는 60이므로 소총은 한 번에 처치하고, 대검과 창은 두 번, 검과 석궁은 세 번, 활은 네 번 맞혀야 처치합니다.

석궁의 탄환과 소총의 선이 몬스터를 맞히는 규칙은 다음과 같습니다. 두 무기는 몬스터를 앞에서부터 찾는 함수(`sweep::monsters_along`)를 함께 씁니다.

- 석궁의 탄환은 한 Tick에 지나간 선분 위에서 닿는 몬스터를 닿는 순서대로 최대 네 마리까지 맞힙니다. 네 마리 모두 같은 피해를 받고, 한 몬스터는 한 번만 맞습니다. 네 마리째를 맞힌 탄환과 사거리의 끝에 이른 탄환은 사라집니다. 활은 같은 규칙에서 맞힐 수 있는 수가 한 마리입니다.
- 막힌 타일은 탄환과 소총의 선을 막습니다. 몬스터가 막힌 타일과 같은 거리에 있으면 그 몬스터를 먼저 맞힙니다. 탄환과 소총의 선은 플레이어를 지나가고, 맞히는 것은 몬스터뿐입니다.
- 소총은 누른 Tick에 조준한 방향으로 사거리 12타일의 선을 긋고, 선 위에서 처음 닿는 몬스터 한 마리만 맞힙니다. 선의 굵기가 0이므로 선이 몬스터의 몸(반지름 0.4타일)을 지나갈 때만 맞습니다. 막힌 타일 뒤와 사거리 밖의 몬스터는 맞지 않습니다.
- 소총의 선이 끝난 자리(몬스터의 가장자리, 막힌 타일, 사거리의 끝 가운데 가장 가까운 곳)는 서버가 플레이어의 마지막 공격(`LastAttack::trace_end`)에 적고 스냅샷에 싣습니다. 선의 시작은 보내지 않으므로, 클라이언트는 쏜 플레이어가 지금 서 있는 자리에서 그 끝까지 흰 선을 그리고, 이 선은 6 Tick(0.3초) 동안 흐려지다가 사라집니다.

무기를 얻고 가지는 규칙은 다음과 같습니다.

1. 상자는 낮이 시작될 때마다 세 개가 놓입니다. 후보 자리 여덟 곳(`MapSpec::chest_sites`) 가운데 서로 다른 세 곳이 뽑히고, 마을의 범위 밖입니다. 상자 안의 무기는 상자마다 따로, 검을 뺀 무기 가운데 같은 확률로 하나가 정해집니다. 그래서 같은 무기가 두 상자에 들어 있을 수도 있습니다. 어느 자리에 어떤 무기가 든 상자가 놓이는지는 방의 씨앗이 정하므로, 같은 씨앗이면 같고(`--seed`), 화면에는 상자의 안이 보이지 않습니다.
2. 상자는 채집 지점처럼 타일 하나를 막고, 상자마다 낮의 몬스터 셋이 곁에서 지킵니다. 이 몬스터는 채집 지점을 지키는 몬스터와 같은 규칙을 따라서, 자리에서 6타일 안으로 들어온 플레이어를 쫓고 밤이 되면 마차로 향합니다. 열지 않은 상자는 밤이 시작될 때 사라집니다.
3. 상자 곁에서 `F`를 1.5초 끊지 않고 누르고 있으면 상자가 사라지고, 상자가 있던 타일의 중심에 상자 안의 무기가 떨어집니다. 플레이어의 가장자리에서 상자의 가장자리까지 1타일 안이면 상자를 열 수 있습니다. 여는 동안에는 이동과 공격을 할 수 없고, 피해를 받거나 `F`를 놓으면 처음부터 다시 눌러야 합니다. 지키는 몬스터가 살아 있어도 맞지 않는 동안에는 열 수 있습니다. 여는 도중에 동료가 쓰러져도 여는 일은 이어지고, 다 연 뒤에 `F`를 계속 누르고 있으면 부활이 시작됩니다.
4. 바닥의 무기 곁에서 `F`를 누른 순간 무기를 줍습니다. 플레이어의 가장자리에서 무기가 놓인 점까지 1.75타일 안이면 줍습니다. 이 거리는 상자를 열 수 있는 거리(1타일)에 타일의 대각선 절반(약 0.71타일)을 더한 값보다 짧을 수 없으므로(`Tuning::validate`가 거절합니다), 상자를 열 수 있는 어느 자리에서든 걷지 않고 `F`를 한 번 눌러서 그 무기를 주울 수 있습니다. 빈 칸이 있으면 빈 칸에 들어가고, 칸이 모두 차 있으면 든 무기와 바뀌어서 이전에 든 무기가 바닥의 그 자리에 놓입니다. 그래서 상자에서 나온 무기를 동료에게 넘길 수 있습니다. 이전에 든 무기가 시작 무기와 같은 종류(검)이면 바닥에 놓이지 않고 사라집니다.
5. 가진 무기는 쓰러져도, 날이 바뀌어도 유지됩니다. 플레이어가 방에서 나가면 가진 무기가 그 자리에 떨어지지만, 시작 무기와 같은 종류의 무기(기본 수치에서는 검)는 떨어지지 않습니다. 입장하는 플레이어가 공짜로 받는 무기이기 때문입니다. 바닥의 무기는 원정이 끝날 때까지 남고, 새 원정에서는 모든 플레이어가 검 하나로 돌아가며 바닥의 무기와 상자가 사라집니다.

### 몬스터에 걸리는 효과

무기가 몬스터를 맞히면 그 무기의 행(`on_hit`)에 적힌 효과가 맞은 몬스터에게 걸립니다. 부채꼴 공격은 안에 든 몬스터마다, 탄환은 맞힌 몬스터마다, 소총은 선이 맞힌 몬스터에게 효과를 겁니다. 효과를 거는 곳은 서버뿐이고, 같은 Tick에 죽은 몬스터에게는 걸리지 않습니다. 효과는 몬스터가 가진 상태이므로 몬스터가 사라지면 함께 사라집니다.

| 효과 | 걸린 몬스터에게 일어나는 일 | 같은 효과를 다시 받으면 |
|---|---|---|
| 감속 | 스스로 걷는 속도에 정해진 비율(기본 0.5)을 곱합니다. 공격의 쿨다운과 닿는 거리는 그대로입니다. | 비율이 작은 쪽이 남습니다. 비율이 같으면 남은 시간이 긴 쪽이 남고, 그것도 같으면 새 감속이 남습니다. 새 감속이 남으면 비율과 시간이 새 값으로 바뀝니다. |
| 출혈 | 걸린 지 1초 뒤부터 1초마다 정해진 피해를 입고, 시간이 끝나는 Tick의 피해까지 입습니다(3초짜리는 세 번). | 한 번의 피해가 큰 쪽이 남습니다. 피해가 같으면 남은 시간이 긴 쪽이 남고, 그것도 같으면 새 출혈이 남습니다. 새 출혈이 남으면 시간과 피해량과 거는 쪽이 새 값으로 바뀌고, 피해가 나는 간격은 끊기지 않고 이어집니다. |
| 스턴 | 정해진 시간 동안 걷지도 공격하지도 않습니다. 공격의 쿨다운은 계속 줄고, 겹친 몬스터에게서 밀려나는 것은 그대로입니다. | 걸려 있는 동안과 끝난 뒤 2초 동안(면역)에는 걸리지 않습니다. 면역 중에도 감속과 출혈은 걸립니다. |

서로 다른 효과는 함께 걸리고, 같은 효과를 다시 받아도 세기는 겹치지 않습니다. 약한 효과는 센 효과가 걸려 있는 동안 버려지고 따로 기억하지 않으므로, 센 효과가 끝난 뒤에도 걸리지 않습니다. 그래서 창의 출혈(6)이 걸린 몬스터를 검(출혈 5)으로 쳐도 창의 출혈이 남고, 창의 출혈이 끝난 뒤에 다시 쳐야 검의 출혈이 걸립니다. 출혈의 피해는 보통 피해와 같은 곳(`World::apply_hits`)을 지나므로, 그 피해로 몬스터가 죽으면 처치는 칸에 남은 출혈을 건 쪽의 것입니다. 건 쪽이 플레이어이면 그 플레이어의 `KILLS`에 더하고, 이미 방을 나갔으면 셀 사람이 없습니다. 한 Tick에서 몬스터가 먼저 행동하고, 효과의 시간이 한 Tick 줄고, 피해가 적용된 뒤에 이번 Tick에 맞은 몬스터에게 새 효과가 걸립니다. 그래서 새로 걸린 효과는 다음 Tick의 행동부터 몬스터를 바꾸고, `secs`초짜리 효과는 정확히 `secs`초 분량의 Tick 동안 몬스터의 행동을 바꿉니다.

효과의 수치는 무기 표의 `on_hit`과 `EffectTuning`(출혈의 간격 1초, 스턴 뒤의 면역 2초)에 있습니다. 감시탑의 표에도 같은 칸이 있고 기본값은 비어 있으며, 칸을 채우면 감시탑의 사격도 효과를 겁니다. `Tuning::validate`는 감속의 비율이 0 이하이거나 1보다 큰 값, 0 이하의 시간, 간격보다 짧은 출혈, 0인 출혈 피해, 0인 간격과 면역을 무기 표와 감시탑 표에서 모두 거절합니다.

화면에서 효과에 걸린 몬스터와 허수아비의 몸통은 효과의 색입니다(`crates/client/src/config.rs`의 `EFFECT_STUN`, `EFFECT_SLOW`, `EFFECT_BLEED`). 스턴은 흰색, 감속은 하늘색, 출혈은 어두운 자주색이고, 효과가 함께 걸려 있으면 스턴, 감속, 출혈의 순서로 앞선 하나만 보입니다. 스턴이 끝난 뒤의 면역은 보이지 않습니다. 스냅샷에서 효과가 사라지면 몬스터는 원래 색으로 돌아옵니다. 서버는 걸려 있는 효과만 스냅샷에 싣고 남은 시간은 싣지 않으므로, 화면은 효과가 걸려 있는지만 압니다.

스냅샷에서 몬스터 하나는 종류와 효과를 한 바이트에 담습니다(`crates/protocol/src/monster_status.rs`). 아래 네 비트가 종류의 순서이고, 그 위의 비트 하나씩이 스턴, 감속, 출혈이므로, 효과가 걸려도 몬스터 하나는 효과가 없을 때와 같은 9바이트입니다. 몬스터 종류가 16개를 넘으면 빌드가 깨지고, 그때는 이 파일의 배치를 바꿉니다.

### 플레이어가 받는 버프

플레이어는 시간이 지나면 끝나는 버프를 받을 수 있습니다. 버프는 두 가지이고, 서로 다른 버프는 함께 걸립니다.

| 버프 | 화면의 이름 | 받은 플레이어에게 일어나는 일 |
|---|---|---|
| 공격 속도 | `HASTE` | 공격의 쿨다운에 정해진 비율(기본 0.7)을 곱합니다. 검의 쿨다운 0.5초(10 Tick)는 0.35초(7 Tick)가 됩니다. 곱한 값을 Tick 단위로 반올림하므로 실제 비율은 무기마다 조금 다릅니다(활은 8 Tick이 6 Tick, 창은 12 Tick이 8 Tick, 석궁은 18 Tick이 13 Tick). |
| 이동 속도 | `SWIFT` | 걷는 속도에 정해진 비율(기본 1.3)을 곱하고, 달리는 중이면 달리기의 배율(1.6)에도 곱합니다. 걷는 속도 4는 5.2가 되고, 달리면서 받으면 한 Tick에 0.416타일을 갑니다. |

같은 버프를 다시 받으면 남은 시간이 긴 쪽이 남고(같으면 새 버프가 남습니다), 짧은 버프가 긴 버프를 줄이지 않습니다. 세기는 겹치지 않습니다. 세기는 `EffectTuning`(`haste_cooldown_factor`, `swift_speed_factor`)에 있고, 길이는 버프를 거는 쪽이 정합니다. 버프는 살아 있는 플레이어(`Life::Alive`)만 가지므로 플레이어가 쓰러지면 없어지고, 부활한 플레이어와 새 원정을 시작하거나 야영지로 돌아온 플레이어는 버프 없이 시작합니다. 낮이 시작될 때 살아 있던 플레이어의 버프는 이어집니다. 버프의 시간은 자리를 비운 플레이어와 야영지에서도 흐르고, 세계가 멈추는 결과 화면에서는 멈춥니다.

버프를 거는 길은 `Player::grant` 하나이고, 크레이트 밖에 공개하지 않습니다. 이 게임에는 이 함수를 부르는 곳이 없으므로 기본 서버에서는 아무도 버프를 받지 않고(`crates/server/tests/buffs.rs`가 기본 서버에서 야영지와 첫날과 첫 밤을 지나는 동안의 모든 스냅샷에 버프가 없음을 확인합니다), 규칙 테스트만 `Scenario::grant`로 버프를 줍니다. 함수에 붙은 `#[cfg_attr(not(test), expect(dead_code, ...))]`는 게임 코드가 이 함수를 부르기 시작하면 경고를 내므로, 그때 이 속성을 지워야 한다는 것을 컴파일러가 알려 줍니다.

스냅샷에서는 살아 있는 플레이어마다 `WireLife::Alive`의 `buffs`(`WireBuffs`)에 두 버프가 걸려 있는지를 불리언 둘로 싣고, 남은 시간은 싣지 않습니다. 모든 클라이언트가 받지만 화면은 내 버프의 이름만 오른쪽 위의 무기 줄 아래에 보여 줍니다(`HASTE`, `SWIFT`, 둘 다 있으면 `HASTE  SWIFT`). 프로토콜의 버전은 12입니다.

### 조작

| 입력 | 동작 |
|---|---|
| `W` `A` `S` `D` | 화면을 기준으로 위, 왼쪽, 아래, 오른쪽으로 이동합니다. |
| `Shift`를 누르고 있기 | 움직이는 동안 걷는 속도의 1.6배로 달립니다. 달리는 동안 화면 왼쪽 위 HP 아래의 `STAMINA` 막대가 줄고, 키를 떼면 막대가 다시 찹니다. 왼쪽과 오른쪽 `Shift`가 같습니다. |
| 마우스 | 커서가 가리키는 지면 위치로 조준합니다. |
| 왼쪽 클릭 | 들고 있는 무기로 공격합니다. 검, 대검, 창은 조준한 방향의 부채꼴 안에 있는 모든 몬스터를 베고, 활은 조준한 방향으로 탄환을 쏘고, 석궁은 조준한 방향으로 탄환을 쏴서 한 줄로 늘어선 몬스터를 최대 네 마리까지 같은 피해로 꿰뚫고, 소총은 누른 Tick에 조준한 방향의 선 위에서 처음 닿는 몬스터 한 마리를 맞히고 선을 화면에 그립니다. 부채꼴의 거리와 각도, 쿨다운은 무기마다 다릅니다. |
| `Q` | 가진 두 칸의 무기를 서로 바꿉니다. 한 칸만 차 있으면 아무것도 바뀌지 않습니다. 누르고 있어도 한 번만 바뀝니다. 화면 오른쪽 위의 `WEAPON  [SWORD]  -  [Q]`나 `WEAPON  [BOW]  SWORD  [Q]`가 가진 무기를 알려 주고, 대괄호가 든 무기입니다. 부활, 수리, 채집, 건설, 상자 열기 중이거나 쓰러졌을 때는 바뀌지 않습니다. |
| `B`를 누르고 있기 | 바라보는 쪽의 이웃한 타일에 감시탑을 짓습니다(비용 10, 3초). 키를 누르기 전에도 그 타일이 밝은 테두리로 보입니다. 마차에서 10타일 안이어야 하고, 마차로 가는 길을 막을 수 없습니다. 세울 수 없으면 그 타일을 빨간 테두리로 표시하고 이유를 화면 아래에 알립니다. 짓는 동안 이동과 공격을 할 수 없고, 짓는 중에 `B`를 떼거나 쓰러지면 건설이 취소되고 비용을 돌려받습니다. |
| `F`를 누르고 있기 | 가까이 쓰러진 동료가 있으면 부활시키고(5초), 없으면 가까이 있는 손상된 감시탑을 수리하고(1.5초에 HP 30, 자원 1), 그것도 없으면 가까이 있는 손상된 마차를 수리하고(1.5초에 HP 30, 자원 1), 그것도 없으면 가까이 있는 채집 지점에서 자원을 0.5초에 1씩 채집합니다(최대 10). 그것도 없으면 가까이 있는 무기 상자를 1.5초 걸려 엽니다(피해를 받으면 처음으로 돌아갑니다). 그동안 이동과 공격을 할 수 없습니다. 채집한 자원은 마차 곁(1.5타일 안)에 가면 자동으로 보관함에 들어가고, 쓰러지거나 스스로 방을 나가면 그 자리에 떨어지며, 살아 있는 플레이어가 가까이 가면 자동으로 줍습니다. |
| `R` | 야영지에서 준비를 켜고 끕니다. 누르고 있어도 한 번만 바뀝니다. 화면 오른쪽 위에 `R  READY`(준비하지 않았을 때)나 `R  CANCEL READY`(준비했을 때)가 나옵니다. 야영지가 아닐 때는 아무 일도 하지 않습니다. |
| `Enter` | 결과 화면에서 확인합니다. 한 번 확인하면 끌 수 없고, 누르고 있어도 한 번만 반영됩니다. 결과 화면이 아닐 때는 아무 일도 하지 않습니다. |
| `F`를 누른 순간 | 바닥의 무기나 야영지의 진열대 곁(1.75타일 안)에서 누르면 그 무기를 줍습니다. 빈 칸이 있으면 빈 칸에 들어가고, 없으면 든 무기와 바뀌어서 이전에 든 무기가 그 자리에 떨어집니다. 다만 이전에 든 무기가 시작 무기와 같은 종류(검)이면 바닥에 떨어지지 않고 사라집니다. 누르고 있어도 한 번만 줍고, 위의 부활, 수리, 채집, 상자 열기를 할 수 있는 곳에서는 줍지 않습니다. 줍을 수 있는 무기 곁에 서면 `F  TAKE SPEAR` 같은 안내가 나오고, 열 수 있는 상자 곁에서는 `F  OPEN CHEST`가 나옵니다. 상자를 여는 동안에는 `OPENING CHEST` 막대가 진행을 보여 줍니다. |

수리는 한 번(1.5초)마다 보관함에서 자원 1을 내고, 마지막 한 번이 HP를 30보다 적게 회복시켜도 같습니다. HP가 거의 없는 감시탑을 가득 수리하면 자원 10(건설 비용과 같습니다)이 들고, 마차는 17이 듭니다. 여럿이 같은 Tick에 수리하면 번호가 작은 플레이어부터 내고, 보관함이 모자라면 나중 플레이어의 그 수리는 회복시키지 못합니다. 보관함이 비용을 낼 수 없는 동안에도 플레이어는 그 수리를 계속하고 채집으로 바뀌지 않으며, 화면 아래에 `CANNOT REPAIR: NOT ENOUGH IN THE STASH`가 나옵니다. 자원이 생기면 이 문구가 사라지고 다음 수리부터 회복시킵니다. 마차 곁의 회복은 자원을 쓰지 않습니다.

달리기 게이지는 가득 찬 막대로 4초를 달릴 수 있고, 빈 막대가 가득 차는 데 10초가 걸립니다. 서버는 이 게이지를 정수 점수로 세고 스냅샷에는 0에서 100의 백분율 하나만 싣습니다. 달리는 Tick에는 막대가 줄고, `Shift`를 뗀 Tick에는 움직이든 서 있든 막대가 찹니다. `Shift`를 누르고 있지만 달리지 못하는 동안(막대가 비었거나 제자리에 서 있을 때)에는 막대가 줄지도 차지도 않으므로, 빈 막대에서 `Shift`를 누르고 있으면 달리기와 걷기가 번갈아 나오지 않고 걷기만 합니다. 부활, 수리, 채집, 건설을 하는 동안과 쓰러졌을 때는 달릴 수 없습니다. 막대는 입장할 때, 낮이 시작될 때, 새 원정이 시작될 때, 부활한 직후에 가득 찹니다.

카메라는 내 캐릭터를 따라갑니다. 마차가 화면 밖에 있으면 마차가 있는 쪽의 화면 가장자리에 `WAGON 23`처럼 내 캐릭터에서 마차까지의 타일 수가 나옵니다.

## 검사하기

CI(`.github/workflows/ci.yml`)는 `main`에 푸시할 때와 풀 리퀘스트마다 Ubuntu 24.04에서 다음 명령을 모두 실행합니다. 저장소 폴더에서 같은 명령을 실행해서 로컬에서도 확인할 수 있습니다.

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy -p caravan_client --target wasm32-unknown-unknown -- -D warnings
cargo test --workspace
sh scripts/check-deps.sh
cd crates/client && trunk build
```

- `cargo test --workspace`는 게임 규칙, 프로토콜, 서버, 클라이언트 로직을 시험합니다. 대부분의 테스트는 화면과 네트워크 없이 실행되고, `crates/dedicated/tests/real_socket.rs`, `crates/ws_server/tests/roundtrip.rs`, `crates/ws_client/tests/message_limit.rs`만 `127.0.0.1`의 실제 소켓을 씁니다.
- `sh scripts/check-deps.sh`는 계층 사이의 금지된 의존이 없는지 검사하고, 통과하면 `dependency rules hold`를 출력합니다.
- `trunk build`는 웹 클라이언트를 `crates/client/dist`에 빌드합니다.
- 감시탑이 상한만큼 서 있고 몬스터가 300마리 있을 때 Tick 하나의 계산 시간은 릴리스 빌드에서만 한계를 확인합니다. 평균은 Tick 간격(50ms)의 10% 이하, 감시탑을 짓거나 부순 Tick과 상자가 열리는 Tick은 한 간격 이하여야 합니다. `cargo test --release -p caravan_rules perf -- --nocapture`가 시간을 출력하고, 일반 `cargo test`는 이 상황이 말한 대로 만들어졌는지만 확인합니다. 활을 든 플레이어 넷이 쏘는 상황, 탄환 144개가 동시에 날아다니는 상황, 석궁을 든 플레이어 넷이 무리를 꿰뚫는 상황, 소총을 든 플레이어 넷이 쏘는 상황(쿨다운대로, 그리고 한 Tick마다)과 몬스터 300마리가 감속과 출혈과 스턴에 모두 걸린 상황의 시간도 같은 명령이 출력합니다. 석궁의 상황은 탄환 하나가 몬스터를 평균 몇 번 맞혔는지도 출력하고, 1.5번을 넘지 못하면 시험이 실패합니다. 스냅샷의 크기는 `crates/protocol/tests/snapshot_size.rs`와 `crates/server/tests/load.rs`가 확인합니다.
- 측정한 값은 다음과 같습니다. 컴퓨터는 macOS(Mac16,8, 14코어)이고, 릴리스 빌드이며, 같은 명령을 세 번 실행한 값을 실행한 순서대로 적었습니다. 측정하는 동안 컴퓨터에는 다른 작업이 돌고 있었습니다(`uptime`의 부하 평균 약 6).
  - Tick 하나의 평균(감시탑 40개, 몬스터 300마리, 1000 Tick)은 148.2µs, 137.6µs, 130.6µs입니다. 활을 든 플레이어 넷이 쏘면 148.9µs, 151.4µs, 137.6µs이고, 탄환 144개가 날아다니면 157.7µs, 147.7µs, 141.4µs입니다. 석궁을 든 플레이어 넷이 쏘면 104.7µs, 104.0µs, 94.1µs이고(탄환 220개가 몬스터를 880번 맞혀서 탄환마다 4.00번), 소총을 든 플레이어 넷이 쏘면 105.2µs, 104.1µs, 93.5µs이고, 소총 넷이 한 Tick마다 쏘면 108.0µs, 106.3µs, 97.3µs입니다(한 Tick에 네 발, 1000 Tick에 4000번 맞힙니다). 한계는 5ms입니다.
  - 몬스터 300마리가 감속과 출혈과 스턴에 모두 걸린 상황(감시탑 40개, 아무도 죽지 않도록 몬스터의 HP를 가장 크게 한 1000 Tick)의 평균은 108.3µs, 106.8µs, 107.3µs입니다. 한계는 5ms입니다. 이 값은 위의 값과 따로, 같은 컴퓨터에서 같은 방식으로 쟀습니다.
  - 상자가 열리는 Tick(열린 Tick과 다음 Tick 가운데 느린 쪽)은 1.17ms, 1.13ms, 1.04ms입니다. 한계는 50ms입니다. 평균보다 긴 원인은 확인하지 않았습니다.
  - 스냅샷 하나는 `snapshot_size.rs`의 상황(몬스터 300마리, 감시탑 40개, 플레이어 4명, 바닥의 무기 4개)에서 3,425바이트입니다. 소총의 사격 선이 있는 플레이어 넷과 바닥의 무기 아홉 개를 더한 가장 나쁜 경우는 3,471바이트이고, 여기에 탄환 8개를 더하면 3,527바이트입니다(한도 3,600바이트). 플레이어 한 명이 있는 `load.rs`의 실제 규칙 상태에서는 3,368바이트입니다. 몬스터 300마리가 모두 세 효과에 걸려 있어도 크기는 같습니다. 효과가 종류의 바이트에 담기므로 몬스터 하나는 그대로 9바이트입니다. 살아 있는 플레이어마다 버프가 2바이트이고 버프가 있든 없든 같습니다. 플레이어 넷이 모두 살아 있고 두 버프를 가진 경우는 가장 나쁜 경우보다 1바이트 큰 3,528바이트이고, 몬스터 번호가 16384 이상이면 3,766바이트입니다(한도 3,950바이트).
  - 전용 서버와 부하 시험용 클라이언트 하나를 실제 소켓으로 150초 실행했을 때(`--stress --waves 100,200,300 --stats`) 몬스터는 최대 267마리였고 가장 큰 스냅샷은 3,221바이트였습니다. 1초 구간의 Tick 평균은 중앙값 0.25ms, 가장 큰 구간이 0.48ms였고, 구간 안의 가장 느린 Tick은 5.0ms였습니다. 이 실행의 플레이어는 검과 활을 들고 있어서 석궁과 소총은 실제 소켓에서 쏘지 않았습니다.

## Tick 하나의 처리 순서

`Sim::step`(`crates/rules/src/sim.rs`)은 방의 단계(`Stage`)에 따라 다른 일을 합니다. 결과 화면(`Sim::wait_for_confirmations`)에서는 세계가 멈추고, 확인 키(`Enter`)와 결과를 보여 주는 남은 시간만 봅니다. 야영지의 Tick(`Sim::practice`)은 준비 키(`R`)와 카운트다운을 먼저 정하고, 원정이 시작되지 않으면 아래 3번, 4번, 7번, 8번, 10번, 11번만 부릅니다. 이때 건설은 거절되고, 몬스터(허수아비)와 감시탑은 행동하지 않으며, 10번과 11번이 결정한 피해는 적용하지 않고 허수아비가 맞은 기록(`Camp::note_strikes`)만 남깁니다. 다만 10번과 11번이 실은 효과는 허수아비에게 걸고(`effect::apply_debuffs`), 걸려 있는 효과와 플레이어가 받은 버프의 시간은 원정과 같이 흐르며(`effect::advance_effects`), 이때 나는 출혈의 피해는 버립니다. 원정 중의 Tick(`Sim::simulate`)은 다음 순서로 상태를 바꿉니다. 모든 공격과 피해는 같은 상태를 읽고 결정한 뒤 15번에서 한꺼번에 적용합니다.

1. `advance_phase`가 낮, 밤, 새벽의 카운트다운을 줄이고, 때가 되면 밤이나 낮을 시작하거나 몬스터를 한 마리 등장시킵니다. 낮이 시작되면 상자를 놓고 상자마다 몬스터를 세우고(`loot::start_day`), 밤이 시작되면 열지 않은 상자를 치웁니다(`loot::clear_chests`).
2. `Paths::sync`가 마차와 감시탑으로 가는 이동 경로를 필요하면 다시 만듭니다.
3. `MonsterGrid::rebuild`가 몬스터의 위치를 격자에 넣습니다.
4. `update_interactions`가 `F`와 `B`를 처리합니다. 부활, 감시탑 수리, 마차 수리, 채집, 상자 열기의 순서로 대상을 고르고, 수리의 비용을 보관함에서 내고(플레이어 번호 순서), 건설의 시작과 거절을 판정합니다. 부활, 수리, 채집 다음에 상자 열기가 오고, `F`를 누른 순간에 더 높은 순위의 대상이 없으면 가장 가까운 바닥의 무기나 야영지의 진열대의 무기를 줍습니다(플레이어 번호 순서). 거리가 같으면 바닥의 무기가 먼저이고, 진열대에서는 이미 가진 종류를 집지 않습니다.
5. `advance_construction`이 건설을 진행하고 끝내거나 취소합니다.
6. 건설이 이동 경로를 바꿨을 수 있으므로 `Paths::sync`를 한 번 더 부릅니다.
7. `update_sprint`가 플레이어마다 이번 Tick에 달리는지 정하고 달리기 게이지를 줄이거나 채웁니다. 4번과 5번이 정한 하고 있는 일을 읽으므로 그 뒤에 부릅니다.
8. `move_players`가 플레이어를 움직입니다. 한 Tick의 이동이 몸의 반지름 이상이면 반지름보다 짧은 같은 길이의 걸음으로 나누어 옮기므로, 이동 속도가 빨라도 얇은 벽을 건너뛰지 않습니다. 걸음의 수에 끝이 있도록, 가장 빠른 플레이어가 한 Tick에 몸의 반지름의 64배 이상을 움직이는 수치는 `Tuning::validate`가 거절합니다. 걷기도 달리기도 걸음이 하나이고, 달리면서 이동 속도 버프를 받으면 걸음이 둘입니다.
9. `deposit_and_pickup`이 마차 곁의 플레이어가 든 자원을 보관함에 넣고(넣은 양은 그 플레이어의 기록에 더합니다), 땅에 떨어진 자원을 줍게 합니다.
10. `use_weapons`가 `Q`를 누른 플레이어의 무기를 바꾸고, 플레이어의 공격을 결정하고, 들고 있는 무기의 전달 방식에 따라 처리합니다. 검, 대검, 창은 부채꼴 안의 몬스터를 맞히고, 활과 석궁은 탄환을 만들고, 소총은 그 자리에서 조준선 위의 처음 닿는 몬스터를 맞히고 사격 선이 끝난 자리를 플레이어의 마지막 공격에 적습니다. 공격의 쿨다운은 `Player::stats`가 돌려주고, 공격 속도 버프가 있으면 그 비율을 곱한 값입니다.
11. `advance_projectiles`가 날아가는 탄환을 한 Tick만큼 움직입니다. 탄환은 이번 Tick에 쏜 것도 움직이고, 지나간 선분에서 닿는 몬스터를 닿는 순서대로 맞힐 수 있는 수(`pierce`)만큼 맞혀서 피해를 결정하고(같은 몬스터는 한 번만 맞힙니다), 막힌 타일이 몬스터보다 가까우면 그 뒤의 몬스터는 맞히지 못하며, 막힌 타일이나 사거리의 끝에서는 피해 없이 사라집니다. 끝난 탄환은 한 Tick 더 남았다가 다음 Tick의 처음에 지워집니다. 결과 화면 동안에는 날던 탄환이 그 자리에 멈추고, 끝난 탄환은 지워집니다.
12. `towers_fire`가 감시탑의 사격을 결정합니다.
13. `monsters_act`가 몬스터의 이동과 공격을 결정합니다. 낮의 몬스터는 자리를 지키고, 밤의 몬스터는 마차로 향합니다. 몬스터는 이전 Tick까지 걸린 효과로 행동합니다(감속은 걷는 속도에 곱하고, 스턴에 걸린 몬스터는 걷지도 공격하지도 않습니다).
14. `advance_effects`가 몬스터가 가진 효과와 플레이어가 받은 버프의 시간을 한 Tick 줄이고, 이번 Tick에 나는 출혈의 피해를 피해 목록의 끝에 더합니다. 몬스터와 플레이어가 행동한 뒤에 부르므로, 끝나는 효과와 버프는 마지막으로 행동을 바꾼 뒤에 풀립니다.
15. `World::apply_hits`가 이번 Tick의 모든 피해를 적용하고, HP가 0이 된 몬스터와 감시탑을 지우고, 쓰러진 플레이어가 든 자원을 그 자리에 떨어뜨립니다. 상자를 열던 플레이어가 피해를 받으면 열기가 여기서 취소됩니다. 피해(`Hit`)는 준 쪽(`Source`: 플레이어, 감시탑, 몬스터)을 담고, 몬스터의 HP를 0으로 만든 피해가 그 처치의 주인을 정합니다. 플레이어의 처치는 그 플레이어의 기록에, 감시탑의 처치는 원정의 감시탑 처치 수에 더합니다. 탄환은 쏜 플레이어의 것이고, 쏜 플레이어가 이미 방을 나갔으면 셀 사람이 없습니다. 같은 Tick에 여럿이 같은 몬스터를 맞히면 피해를 결정한 순서(10번, 11번, 12번, 14번)에서 HP를 0으로 만든 피해가 주인입니다. 쓰러진 플레이어의 기록(쓰러진 횟수)도 여기서 더합니다. 몬스터를 지운 뒤에는 `effect::apply_debuffs`가 이번 Tick에 맞은 몬스터 가운데 살아남은 몬스터에게 피해가 싣고 온 효과를 겁니다.
16. `recover_near_wagon`이 마차 곁의 살아 있는 플레이어의 HP를 회복합니다. 피해를 적용한 뒤에 부르므로, 같은 Tick의 회복이 쓰러뜨리는 피해를 되돌리지 않습니다.
17. `advance_life_timers`가 부활을 마무리하고(부활시킨 플레이어의 기록에 더합니다) 쓰러진 플레이어의 출혈 시간을 줄입니다.
18. `finish_openings`가 열기를 마친 플레이어의 상자를 열어서 무기를 바닥에 놓습니다. 피해를 적용한 뒤에 부르므로, 열기가 끝나는 Tick에 맞은 플레이어는 열지 못합니다.
19. `settle_outcome`이 원정의 성공과 실패, 무리를 모두 처치했는지를 판정합니다. 원정이 끝났으면 방이 결과 화면으로 넘어가고, 이때 원정의 요약(성공 여부, 버틴 날, 걸린 Tick, 감시탑의 처치)과 방에 있는 플레이어(자리를 비운 플레이어 포함)의 기록이 결과(`Report`)로 한 번 복사됩니다.

## 키 입력 하나가 다른 플레이어의 화면에 그려지기까지

플레이어 A가 `D`를 누르면, 다음 순서를 거쳐 플레이어 B의 화면에서 A의 캐릭터가 움직입니다.

1. `crates/client/src/input.rs`의 `read_controls`가 이번 프레임의 키보드와 마우스 상태를 `Controls`로 읽습니다. 커서의 화면 위치는 지면 위치로 되돌립니다.
2. `crates/client/src/net.rs`의 `send_input`이 `Session::input_due`(`crates/client_core/src/session.rs`)를 부릅니다. `InputSender::poll`(`crates/client_core/src/input.rs`)은 서버 Tick 간격(20 Hz에서 50ms)마다 한 번 `Controls::to_input`으로 순서 번호가 붙은 `InputMsg`를 만들고, 이때 화면 기준의 WASD 방향이 지면의 이동 방향으로 바뀝니다.
3. `WsClient::send`(`crates/ws_client/src/lib.rs`)가 `encode_client`(`crates/protocol/src/codec.rs`)로 메시지를 postcard 바이트로 바꾸고 WebSocket 이진 프레임으로 보냅니다.
4. 서버의 네트워크 스레드에서 `serve_link`(`crates/ws_server/src/lib.rs`)가 프레임을 `decode_client`로 해석하고, 크기가 정해진 채널로 게임 스레드에 넘깁니다.
5. `crates/dedicated/src/main.rs`의 반복이 `GameServer::pump`(`crates/server/src/lib.rs`)를 부릅니다. `pump`는 `WsServer::poll`로 꺼낸 메시지를 `Hub::handle_message`(`crates/server/src/hub.rs`)에 넘기고, 입력은 `Room::submit_input`(`crates/server/src/room.rs`)을 거쳐 `MemberInput::accept`(`crates/server/src/input.rs`)에 쌓입니다. 이미 받은 순서 번호보다 크지 않은 입력은 여기서 버립니다.
6. Tick 시각이 되면(`crates/server/src/clock.rs`의 `TickClock::due`) `Room::tick`이 플레이어마다 `MemberInput::for_tick`으로 이번 Tick의 입력 하나를 정하고 `Sim::step`(`crates/rules/src/sim.rs`)을 한 번 부릅니다.
7. `Sim::step` 안에서 `move_players`(`crates/rules/src/player.rs`)가 이동 방향에 속도(`Player::stats`가 돌려주는 값이고, 달리는 중이면 걷는 속도에 달리기 배율을 곱한 값입니다)와 Tick 길이를 곱해서 캐릭터를 옮기고(이동이 몸의 반지름 이상이면 같은 길이의 걸음으로 나눕니다), `crates/rules/src/collision.rs`가 걸음마다 장애물과 겹친 만큼 캐릭터를 밀어냅니다.
8. `Snapshot::from_sim`(`crates/protocol/src/snapshot.rs`)이 방 전체의 상태를 전송 형식으로 바꿉니다. `Room::tick`은 같은 스냅샷을 방의 모든 접속에 보내라는 `Out::Send`를 돌려주고, `GameServer::apply`가 `WsServer::send`를 불러서 `encode_server`로 바꾼 바이트를 보냅니다.
9. B의 클라이언트에서 `pump_network`(`crates/client/src/net.rs`)가 `WsClient::poll`로 스냅샷을 받고(`decode_server`), `Session::on_event`가 스냅샷을 `SnapshotBuffer`(`crates/client_core/src/interp.rs`)에 넣습니다.
10. `advance_playback`(`crates/client/src/net.rs`)이 재생 시각을 프레임 시간만큼 앞으로 보냅니다. `SnapshotBuffer`는 가장 최근 스냅샷보다 2 Tick(100ms) 이전 시점의 위치를 그 앞뒤 스냅샷 두 개 사이에서 선형으로 보간해서 `Frame`을 만듭니다.
11. `sync_characters`(`crates/client/src/characters.rs`)가 `Frame`의 지면 위치를 `convert::placement`(`crates/client/src/convert.rs`)로 화면 위치와 z 값으로 바꿉니다. 이 변환은 `crates/client_core/src/iso.rs`의 `ground_to_screen`과 `depth`를 씁니다. Bevy가 바뀐 `Transform`대로 도형을 그리면 B의 화면에서 A의 캐릭터가 움직입니다.

## 코드를 읽는 순서

Rust와 게임 개발을 처음 공부한다면 다음 순서로 읽습니다. 규칙에서 시작해서 프로토콜, 서버, 어댑터, 클라이언트 코어, 클라이언트로 나아갑니다.

1. `crates/rules/src/tuning.rs`에서는 게임의 모든 수치가 한 구조체에 모인 모습과, `Default` 트레이트 구현, 그리고 초를 정수 Tick으로 바꾸는 `Tuning::ticks`를 봅니다.
2. `crates/rules/src/sim.rs`의 `Sim::step`은 방의 단계에 따라 Tick의 일을 나누고, 원정의 Tick(`simulate`)은 Tick 하나의 처리 순서를 나열하며, `world`만 가변 참조로 넘기고 `tuning`과 `paths` 같은 다른 필드는 `Ctx`에 공유 참조로 빌려 주는 방식이 구조체 필드를 따로 빌리는 소유권 규칙의 첫 예입니다.
3. `crates/rules/src/player.rs`의 `Life`는 데이터를 가지는 열거형의 예이고, 쓰러진 플레이어가 HP나 쿨다운을 가지는 상태를 타입으로 표현할 수 없게 만듭니다. `crates/rules/src/loadout.rs`의 `Loadout`은 무기 두 칸을 타입으로 표현합니다. 든 무기(`held`)가 `Option`이 아니라서 「칸이 둘 다 빈 상태」를 만들 수 없고, 필드가 비공개라서 상태를 바꾸는 방법이 `swap`(`Q`)과 `take`(`F`로 줍기) 둘뿐입니다. `crates/rules/src/weapon.rs`는 공격을 두 단계(`decide`가 공격을 모으고, `deliver`가 `Delivery`의 값에 따라 전달합니다)로 나누고, 무기마다 다른 수치는 `crates/rules/src/tuning.rs`의 무기 표(`WeaponTable`) 한 행에 둡니다. `crates/rules/src/projectile.rs`는 탄환을 쏜 플레이어와 따로 세계의 개체 목록에 두고, `crates/rules/src/sweep.rs`는 한 Tick에 움직인 선분 전체를 검사해서 빠른 탄환이 얇은 몬스터를 건너뛰지 못하게 하고, 탄환과 소총의 선이 몬스터를 앞에서부터 찾는 순서(`monsters_along`)를 정합니다. 소총은 `weapon.rs`의 `shoot`가 누른 Tick에 이 함수와 막힌 타일 검사를 한 번씩 부릅니다. `crates/rules/src/stamina.rs`의 `Stamina`는 정수 하나를 새 타입(newtype)으로 감싸서, 달리기 게이지를 소수 없이 정수 점수로 세는 방법을 한 곳에 모읍니다. `crates/rules/src/effect.rs`의 `MonsterEffects`는 효과마다 필드가 하나이고 필드가 비공개라서 값을 바꾸는 길이 `apply`와 `advance` 둘뿐이므로, 스턴이 걸려 있거나 면역인 몬스터에게 스턴을 거는 것 같은 규칙 위반을 다른 파일에서 만들 수 없습니다. 같은 파일의 `PlayerBuffs`는 `Life::Alive`만 가지므로, 쓰러진 플레이어가 버프를 가지는 상태도 만들 수 없습니다.
4. `crates/rules/src/world/tiles.rs`의 `TileMap`은 어디가 막혔는지 아는 유일한 곳이고, `crates/rules/src/build.rs`는 감시탑을 놓을 수 있는 조건을 한 함수(`check_site`)로 판정합니다. `crates/rules/src/expedition.rs`는 낮, 밤, 새벽의 단계를 열거형(`Phase`)으로 두고 단계를 바꾸는 곳을 두 함수로 모았으며, 낮이 시작될 때 일어나는 일은 `begin_day` 하나에 있습니다. 그 위의 단계인 야영지, 원정, 결과 화면은 `crates/rules/src/stage.rs`의 `Stage`가 열거형 하나로 두고, 단계마다 그 단계에서만 의미 있는 값을 가지며, 단계를 바꾸는 곳은 `Sim`의 세 함수(`begin_expedition`, `conclude`, `enter_camp`)뿐입니다. `crates/rules/src/camp.rs`는 준비와 카운트다운을 다루고, 카운트다운은 Tick마다 「모두가 준비했는가」를 다시 보고 정하므로 모두가 준비하지 않은 채로 남아 있을 수 없습니다. `crates/rules/src/debrief.rs`는 결과 화면의 확인과 남은 시간, 그리고 원정이 끝난 순간에 복사한 결과(`Report`)를 다루고, 두 파일이 「모두가 동의해야 하는 사람」을 `camp::who_must_agree` 한 곳에서 고릅니다. 개인별 기록(`Player::record`)은 규칙 크레이트 안에서만 보이므로, 프로토콜 크레이트가 기록을 스냅샷에 실으면 컴파일되지 않습니다. 밤의 무리의 크기는 `NightTuning::wave_size` 한 곳에서 정하고, 인원은 밤이 시작될 때 단계(`Phase::Night`의 `party`)에 담깁니다. `crates/rules/src/loot.rs`는 무기 상자와 바닥의 무기를 다루고, 규칙에서 난수를 쓰는 곳은 이 모듈의 `dice` 하나입니다(상자의 자리와 내용을 씨앗에서 뽑습니다). `Chest`의 내용(`contents`)은 규칙 크레이트 안에서만 보이므로, 프로토콜 크레이트가 상자 안의 무기를 읽어서 스냅샷에 실으면 컴파일되지 않습니다. `crates/rules/src/resources.rs`는 자원이 채집 지점, 플레이어의 손, 땅, 보관함 가운데 한 곳에만 있도록 옮기는 규칙입니다. `crates/rules/src/monster.rs`, `crates/rules/src/nav.rs`, `crates/rules/src/spatial.rs`에서는 몬스터의 명령(`Order`: 낮에는 자리를 지키고 밤에는 마차로 향합니다), 목표 선택, 흐름장(flow field)으로 장애물을 피하는 경로 탐색, 균일 격자로 주변 몬스터를 찾는 방법을 배웁니다.
5. `crates/rules/src/tests/support.rs`와 같은 폴더의 테스트는 화면과 네트워크 없이 개체를 원하는 자리에 놓고 `step`을 반복해서 규칙을 시험하는 방법을 보여 줍니다. 상자는 `chests.rs`(자리와 내용, 씨앗, 지키는 몬스터)와 `opening.rs`(여는 일)가, 바닥의 무기는 `loot.rs`가 시험합니다. 야영지의 준비와 연습은 `camp.rs`, 무기 진열대는 `racks.rs`, 결과 화면의 확인은 `debrief.rs`가 시험하고, 몬스터에게 걸리는 효과는 `effects.rs`가 무기로 거는 것부터 시간이 끝나는 Tick까지 시험하고, 플레이어의 버프는 `buffs.rs`가 시험합니다.
6. `crates/protocol/src/messages.rs`의 `ClientMsg`와 `ServerMsg`는 serde의 derive로 직렬화하는 열거형이며, 클라이언트가 보낼 수 있는 게임 정보가 입력뿐이라는 서버 권위 방식이 이 타입에 드러납니다.

## 현재의 한계

- 클라이언트 예측이 없습니다. 내 캐릭터도 서버의 스냅샷으로만 움직이므로, 키를 누른 뒤 서버까지의 왕복 시간과 보간 지연(100ms)이 지나야 화면에서 움직입니다.
- 접속이 끊기면 시작 화면으로 돌아오고 이유가 표시됩니다. 서버는 그 플레이어의 자리를 60초 동안 유지하고, 그 안에 `Enter`를 누르면 같은 캐릭터로 돌아옵니다. 클라이언트가 자동으로 다시 접속하지는 않습니다. 같은 방에 사람이 하나뿐이어도 자리가 유지되는 동안 방은 멈춰 있을 뿐 사라지지 않고, 60초가 지나면 자리와 방이 함께 없어집니다.
- 서버는 Tick마다 방 전체의 스냅샷(모든 플레이어, 몬스터, 시설, 날아가는 탄환, 상자, 바닥의 무기)을 방의 모든 접속에 보냅니다. 바뀐 부분만 보내지 않습니다.
- 브라우저 탭이 백그라운드로 가면 브라우저가 페이지의 실행을 제한해서 입력 전송이 멈춥니다. 서버는 입력 없이 10 Tick(0.5초)보다 오래 지나면 그 캐릭터를 아무것도 누르지 않은 상태로 움직이고, 3초가 지나면 그 사람을 자리를 비운 것으로 보고, 메시지 없이 30초가 지나면 접속을 닫습니다. 자리는 마지막 메시지부터 60초 동안 남습니다. 다만 같은 주소(IPv6는 같은 /64 대역)가 동시에 유지시킬 수 있는 자리는 8개까지이고(`max_held_seats_per_ip`), 한 주소에서 그보다 많은 자리가 동시에 끊기면 넘친 자리는 유지되지 않고 곧바로 없어집니다. 서버 전체에서 유지하는 자리도 128개까지이고(`max_held_seats`), 이미 128개를 유지하는 동안 새로 끊긴 자리는 유지되지 않고 곧바로 없어집니다(이미 유지 중인 자리는 그대로입니다). 약속을 어겨서(입장 전의 입력, 두 번째 입장 요청) 서버가 닫은 접속의 자리는 곧바로 없어집니다. 한도(1초의 메시지 수, 메시지의 크기, 느린 읽기)를 넘어서 닫힌 접속의 자리는 끊긴 접속처럼 유지합니다. 네트워크가 4초보다 길게 멈췄다가 풀리면 밀린 입력이 한꺼번에 도착해서 메시지 수의 한도에 닿으므로, 그 사람은 접속이 닫힌 뒤 `Enter`로 돌아와야 합니다. 접속이 닫힌 탭으로 돌아오면 시작 화면이 나와 있고, 60초 안에 `Enter`를 누르면 같은 캐릭터로 돌아옵니다.
- 서버는 TLS를 처리하지 않으므로 `ws://` 접속만 받습니다.
- 서버의 기본 주소와 `trunk serve`의 주소(`crates/client/Trunk.toml`)는 `127.0.0.1`이므로, 기본 설정에서는 같은 컴퓨터에서만 접속할 수 있습니다.
- 한 방의 최대 인원은 4명입니다(`crates/rules/src/tuning.rs`의 `max_players`). 가득 찬 방에 접속한 클라이언트는 거절되고 화면에 이유가 표시됩니다.
- 접속이 끊긴 자리는 접속 수의 한도(`max_links`, `max_links_per_ip`)에 들지 않으므로, 서버는 접속자가 없는 방을 주소마다 유지하는 자리의 수(`max_held_seats_per_ip`, 기본 8)와 서버 전체의 유지하는 자리의 수(`max_held_seats`, 기본 128)로 묶습니다. 주소는 IPv4는 전체이고 IPv6는 앞 64비트(/64)입니다(`crates/protocol/src/transport.rs`의 `PeerKey::of`, 접속 수를 세는 `caravan_ws_server`도 같은 함수를 씁니다). 방 전체의 수는 256개까지입니다(`max_rooms`). 끊긴 자리의 한도는 방의 한도보다 작으므로 접속자가 없는 방만으로 새 방을 막을 수 없습니다. 이 한도들은 `crates/protocol/src/limits.rs`에 있고, 방의 한도에 닿으면 새 방을 만드는 입장이 거절되고 화면에 이유가 표시됩니다. 있는 방에는 계속 들어갈 수 있습니다. 리버스 프록시 뒤에서는 모든 접속이 주소 하나로 보이므로 `max_links_per_ip`와 `max_held_seats_per_ip`를 함께 올려야 합니다.
- 방 목록이 없으므로 같은 방에 모이려면 방 코드나 링크를 서로 알려 주어야 합니다. 서버는 같은 이름을 막지 않으므로 한 방에 같은 이름이 둘 있을 수 있습니다.
- 맵은 64 x 64 타일 하나이고, 원정의 몬스터는 한 종류(야영지의 허수아비는 따로), 시설은 감시탑 하나, 자원은 한 종류입니다.
- 화면의 문구는 영어입니다. Bevy의 기본 글꼴이 한글을 표시하지 못하기 때문입니다. 무기의 이름도 영어입니다.
- 몬스터에게 걸린 효과는 몸통 색으로만 보이고 남은 시간은 화면에 나오지 않습니다. 효과가 함께 걸려 있어도 색은 하나만 보입니다.
- 플레이어가 받은 버프는 내 화면에 이름으로만 보이고 남은 시간은 나오지 않으며, 다른 플레이어의 버프는 보이지 않습니다. 이 게임에는 버프를 거는 곳이 없으므로 버프는 테스트에서만 나타납니다.
- 탄환과 공격 효과와 소총의 사격 선은 선으로 그리고, 상자와 바닥의 무기는 단순한 도형으로 그립니다.
