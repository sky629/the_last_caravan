# THE LAST CARAVAN

THE LAST CARAVAN은 2~4명이 이동식 마을(마차)을 함께 지키는 협동 액션 로그라이크 게임입니다.
이 저장소에는 야영지와 낮과 밤이 이어지는 프로토타입이 있습니다. 방은 야영지에서 시작하고, 모두가 준비하면 원정이 시작됩니다. 플레이어들은 맵 한가운데의 마차를 사흘 밤 동안 몰려오는 몬스터로부터 지킵니다. 낮에는 먼 곳의 채집 지점에서 자원을 모아 마차에 가져다 두고, 그 자원으로 마차 가까이에 포탑을 세웁니다. 포탑은 다섯 종류이고 `E`로 고릅니다. 또 몬스터가 지키는 무기 상자를 열어서 무기를 얻습니다. 플레이어는 무기를 두 개까지 가지고 다니며 `Q`로 바꿔 들고 `G`로 버립니다. 밤에는 포탑과 함께 몬스터를 막고, 쓰러진 동료를 부활시키고, 손상된 마차를 수리합니다. 전용 서버가 이동, 전투, 채집, 건설, 부활, 수리, 상자 열기, 무기 줍기와 버리기, 준비와 확인의 결과를 모두 판정합니다.

## 설치하기

아래 명령은 macOS에서 확인했습니다.

1. rustup을 설치합니다. 설치가 끝나면 새 터미널을 엽니다.

   ```sh
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   ```

2. 저장소를 내려받고 저장소 폴더로 이동합니다.

   ```sh
   git clone https://github.com/sky629/the_last_caravan.git
   cd the_last_caravan
   ```

3. 고정된 툴체인을 설치합니다. `rust-toolchain.toml`이 Rust 1.100.0, rustfmt, clippy, `wasm32-unknown-unknown` 타깃을 지정하므로, 저장소 폴더에서 이 명령 하나로 웹 빌드용 타깃까지 설치됩니다.

   ```sh
   rustup toolchain install
   ```

   `rustc --version`이 `rustc 1.100.0`을 출력하고 `rustup target list --installed`에 `wasm32-unknown-unknown`이 있으면 설치가 끝난 것입니다.

4. 웹 빌드 도구인 trunk 0.22.2를 설치합니다. trunk는 처음 웹 빌드를 할 때 `Cargo.lock`에 맞는 버전의 wasm-bindgen을 내려받습니다.

   ```sh
   cargo install --locked trunk --version 0.22.2
   ```

Ubuntu에서 클라이언트를 빌드하려면 Bevy가 링크하는 라이브러리를 먼저 설치합니다. CI가 설치하는 목록과 같습니다.

```sh
sudo apt-get install pkg-config libudev-dev libwayland-dev
```

## 실행하기

### 전용 서버를 실행합니다

클라이언트보다 서버를 먼저 실행합니다. 서버는 `listening on ws://127.0.0.1:7777`을 출력하고, 그 뒤에는 일어난 일만 한 줄씩 출력합니다. 출력하는 일은 플레이어의 입장과 퇴장(방 코드와 인원), 접속이 끊긴 자리의 유지와 복귀, 방의 생성과 제거, 한도 때문에 서버가 닫은 접속과 그 이유, 시작 오류입니다. `Ctrl-C`로 종료합니다.

```sh
cargo run -p caravan_dedicated
```

플레이어 한 명이 방 `test`에 들어갔다가 나가면 출력은 다음과 같습니다. 방 코드를 비우고 들어온 플레이어를 위해 서버가 방 코드를 만들면(다섯 글자) 그 코드가 `test` 자리에 나옵니다. 플레이어의 이름은 이 로그에 남기지 않습니다. `--debug-net`을 켜면 주고받는 메시지를 그대로 출력하므로 이름도 출력됩니다.

```text
listening on ws://127.0.0.1:7777
room test created (seed 8201742364921307566)
player 1 joined room test (1 members)
player 1 left room test (0 members)
room test removed
```

| 옵션 | 설명 |
|---|---|
| `--addr HOST:PORT` | 접속을 받을 주소입니다. 기본값은 `127.0.0.1:7777`입니다. 다른 컴퓨터에서 접속하려면 `0.0.0.0:7777`을 지정합니다. |
| `--web-dir DIR` | 같은 포트로 오는 HTTP 요청에 폴더 `DIR`(웹 빌드의 출력)의 파일을 내줍니다. 서버가 켜질 때 폴더 바로 아래의 `.html`, `.js`, `.wasm` 파일만 메모리에 읽어 두므로, 하위 폴더, 심볼릭 링크, 이름이 `.`으로 시작하는 파일, 다른 확장자의 파일은 내주지 않고 폴더 밖의 파일에는 닿을 방법이 없습니다. 폴더의 파일을 다시 빌드하면 서버를 다시 켜야 합니다. 주지 않으면 파일을 내주지 않고, HTTP 요청에는 답하지 않고 접속을 닫습니다. 시작할 때 `serving the web client from DIR at http://주소/`를 출력합니다. |
| `--public-url https://HOST` | 이 서버로 들어오는 공개 주소(터널의 주소)입니다. `--web-dir`이 필요하고, `http(s)://호스트[:포트]`의 글자(영문자, 숫자, `-`, `.`)만 받으며 경로를 붙일 수 없습니다. 서버는 내주는 `index.html`의 `{{public_url}}` 자리를 이 주소로 바꾸고(주지 않으면 빈 글자로 바꿉니다), 웹 클라이언트는 이 주소로 초대 링크를 만듭니다. 시작할 때 `invite links point to 주소/`를 출력합니다. |
| `--debug-net` | 주고받는 모든 메시지를 읽을 수 있는 형태로 출력합니다. 스냅샷은 몬스터 목록을 수로 줄여서 출력합니다. |
| `--stats` | 1초마다 방, 플레이어, 몬스터의 수와 Tick 시간의 평균과 최대를 한 줄씩 출력합니다. 예를 들면 `stats rooms=1 members=2 monsters=87 ticks=20 tick_avg_ms=0.31 tick_max_ms=1.20`입니다. |
| `--waves SIZE,SIZE,.../SIZE,...` | 밤마다 무리의 수와 무리마다 몬스터의 수를 바꿉니다. 밤은 `/`로, 무리는 `,`로 나누고, 밤의 수가 원정의 날 수입니다. `--waves 100,200,300`은 밤 하나에 무리 셋(100마리, 200마리, 300마리)을, `--waves 8,12/20,30,40`은 밤 둘(첫째 밤 8마리와 12마리, 둘째 밤 20마리, 30마리, 40마리)을 정합니다. 적은 수는 네 명이 있을 때의 크기이고, 밤이 시작될 때 방에 있는 사람이 네 명보다 적으면 그 수에 비례해서 줄어듭니다(`--stress`와 함께 쓰면 줄어들지 않습니다). 서버가 시작할 때 출력하는 `wave sizes by night for 4 players`가 이 수입니다. 이 옵션은 무리의 몬스터 수만 정하므로 모든 무리가 기본 몬스터 한 묶음이고(돌격병과 파괴병이 섞이지 않습니다), 보스의 졸개는 이 옵션과 관계없이 기본 수치 그대로 돌격병입니다. |
| `--stress` | 마차, 포탑, 플레이어가 죽지 않게 하고, 감시탑을 상한(40개)만큼 미리 세우고, 낮을 한 Tick으로 줄이고, 몬스터를 Tick마다 한 마리씩 등장시킵니다. 새 원정이 시작될 때마다 감시탑이 다시 서 있습니다. 플레이어는 검과 활을 함께 가지고 시작합니다. 기본 수치의 무리에 섞인 돌격병과 파괴병도 모두 기본 몬스터로 바꾸므로 부하의 기준은 기본 몬스터 한 종류입니다(몬스터의 수는 그대로입니다). 마지막 무리를 처치하면 보스 없이 원정이 끝나므로, 보스가 나오기 전의 기준으로 서버의 Tick 시간과 스냅샷의 크기를 잽니다. 사람의 조작 없이 원정이 진행되어야 하므로 야영지를 건너뜁니다. 방은 만들어지자마자 첫날을 시작하고, 결과를 한 Tick만 보여 준 뒤 새 원정을 시작합니다. |
| `--seed N` | 모든 방의 무작위를 씨앗 `N`(0 이상의 정수) 하나로 정합니다. 주지 않으면 방마다, 서버를 실행할 때마다 다른 씨앗을 씁니다. 방을 만들 때 출력하는 `seed` 값을 이 옵션에 주면 같은 상태에서 다시 시작하므로, 판에서 본 일을 다시 만들 수 있습니다. 예를 들어 `--seed 7`이면 첫 원정의 첫날 상자는 (17, 32)에 활, (32, 17)에 소총, (49, 49)에 활이 든 채로 놓입니다. `crates/rules/src/tests/chests.rs`의 `seed_7_places_these_three_chests_on_the_first_day`가 이 값을 고정합니다. |

`--waves`와 `--stress`는 몬스터가 수백 마리일 때 서버의 Tick 시간과 스냅샷의 크기를 재기 위한 부하 시험용 옵션입니다. Tick 시간은 `--stats`를 붙여야 출력됩니다. 부하 시험용 클라이언트가 하나만 접속해도 몬스터가 수백 마리 나오게 하려면 `--stress`를 함께 씁니다. `--stress`가 아닌 서버에서는 무리의 크기가 방의 인원에 비례하기 때문입니다.
부하 시험용 클라이언트(`crates/dedicated/examples/load_client.rs`)는 Bevy 없이 한 방에 접속해서 Tick마다 입력을 보내고, 받은 스냅샷의 크기와 몬스터 수를 1초마다 출력합니다. 야영지에서는 준비 키를, 결과 화면에서는 확인 키를 스스로 누르므로 사람의 조작 없이 원정이 되풀이됩니다. `--stress`가 아닌 서버에서는 준비한 뒤 카운트다운(3초)이 지나야 원정이 시작됩니다.

```sh
cargo run --release -p caravan_dedicated -- --stress --waves 100,200,300 --stats
cargo run --release -p caravan_dedicated --example load_client -- --addr 127.0.0.1:7777 --room load --secs 60
```

부하 시험용 클라이언트의 옵션은 `--addr HOST:PORT`, `--room CODE`, `--name NAME`(기본값 `load`), `--secs SECONDS`, `--passive`, `--bow`입니다. `--passive`를 붙이면 공격하지 않으므로 몬스터가 가장 많이 쌓입니다. `--bow`를 붙이면 원정마다 한 번 활로 바꾸고 탄환을 쏩니다(서버를 `--stress`로 실행해야 활을 가지고 있습니다). 활은 쿨다운이 있으므로 플레이어 넷이 `--bow`로 쏴도 동시에 날아다니는 탄환은 한 자릿수입니다(감시탑 40개가 서 있고 몬스터가 260마리쯤 몰릴 때 측정한 최대는 6개입니다). 탄환이 100개 넘게 날아다니는 부하는 이 시험이 아니라 `cargo test --release -p caravan_rules perf -- --nocapture`의 시험이 만듭니다. 부하 시험용 클라이언트가 출력하는 `projectiles=`와 마지막 줄의 `peak_projectiles`로 날아다니는 탄환의 수를 확인할 수 있습니다. `--secs 60`으로는 몬스터가 181마리까지만 모이므로, 260마리 넘게 모으려면 `--secs 150`이 필요합니다.

### PC 클라이언트를 실행합니다

옵션 없이 실행하면 시작 화면이 나옵니다. 이름(`NAME`)과 방 코드(`ROOM`)를 입력하고 `Enter`를 누르면 입장합니다.

```sh
cargo run -p caravan_client
```

- 방 코드를 비우고 `Enter`를 누르면 서버가 새 방을 만들고 코드를 정합니다. 만들어진 코드는 야영지 화면에 나옵니다.
- 이름은 1~12자의 영문자, 숫자, 공백, `-`, `_`입니다. 앞뒤 공백은 지워집니다. 이름이 겹쳐도 입장할 수 있습니다.
- 방 코드는 1~16자의 `a-z`, `0-9`, `-`, `_`이고 대문자는 소문자로 바뀝니다. 없는 코드를 넣으면 그 코드로 방이 만들어지고, 마지막 사람이 나가면 방이 사라집니다.
- `Tab`으로 칸을 옮기고, `Ctrl+V`(macOS는 `Cmd+V`)로 붙여 넣고, `Backspace`로 지웁니다.
- 입장이 거절되거나 접속이 끊기면 시작 화면으로 돌아오고 이유가 나옵니다. 입력한 이름과 방 코드는 그대로 남아 있습니다.
- 접속이 끊긴 뒤 60초 안에 같은 방 코드로 `Enter`를 누르면 같은 캐릭터로 돌아옵니다(위치, HP, 든 무기가 그대로입니다). 방 코드를 비우고 입장해서 서버가 코드를 정한 방도 같습니다. 끊긴 뒤의 시작 화면에는 그 방 코드가 이미 채워져 있기 때문입니다. 60초가 지났거나 다른 방 코드를 넣었으면 새 플레이어로 입장합니다.
- 같은 자리로 다른 창이 입장하면 먼저 있던 창은 시작 화면으로 돌아오고 `Seat taken over: Another window took over this seat`를 보여 줍니다. 그 창에서 `Enter`를 누르면 자리를 다시 가져옵니다.
- 방 안(야영지, 원정, 결과 화면)에서 `Esc`를 누르면 바로 나가지 않고 화면 가운데에 `LEAVE THE ROOM?`과 `ENTER  LEAVE      ESC  STAY`가 뜹니다. 그때 `Enter`를 누르면 서버에 나간다고 알리고 접속을 버린 뒤 시작 화면으로 돌아오고, `Esc`를 다시 누르면 창이 닫힙니다. 서버가 게임을 계속 진행하므로 창이 떠 있는 동안에도 이동과 공격은 그대로 됩니다. 창이 떠 있는 동안의 `Enter`는 나가기로만 쓰이고, 결과 화면의 확인으로 보내지 않습니다. 방을 나가거나 접속이 끊겨서 방이 바뀌면 창의 상태는 남지 않습니다. 나갈 때 서버는 그 자리를 곧바로 내놓고, 이 기기는 그 자리의 표식을 지웁니다. 방 코드는 칸에 남지만, 다시 `Enter`를 누르면 새 플레이어로 입장합니다. 방에 들어가기 전(접속하는 중이거나 입장 안내를 기다리는 중)의 `Esc`는 잃을 것이 없으므로 확인 없이 곧바로 시작 화면으로 돌아옵니다.
- 야영지에서 `C`를 누르면 방 코드를 클립보드에 복사하고, 친구는 그 코드를 방 코드 칸에 붙여 넣습니다.
- 마지막으로 입장한 이름과 방 코드와 그 방의 자리의 표식은 설정 폴더의 `the-last-caravan/memory.txt`에 저장되고, 이름과 방 코드는 다음 실행에서 칸에 미리 채워집니다. 표식은 그 자리를 이어받는 유일한 자격이므로 링크와 로그에 넣지 않습니다. 설정 폴더는 Windows가 `%APPDATA%`, macOS가 `~/Library/Application Support`, 그 밖의 시스템은 `$XDG_CONFIG_HOME` 또는 `~/.config`입니다. 저장하지 못하면 경고만 남기고 계속 실행합니다.

옵션에 이름과 방 코드를 모두 주면 시작 화면 없이 곧바로 입장합니다. 둘 중 하나만 주면 시작 화면의 해당 칸이 미리 채워집니다. 두 클라이언트를 같은 방에 넣으려면 터미널 두 개에서 같은 방 코드로 실행합니다. 두 창에 같은 맵과 두 캐릭터가 나타나고, 캐릭터 위와 준비 목록에 이름이 보입니다. 두 클라이언트는 같은 컴퓨터의 같은 설정 폴더를 쓰므로 `--profile`로 저장 파일을 나눕니다.

```sh
cargo run -p caravan_client -- --name KANG --room test --profile kang
cargo run -p caravan_client -- --name MIRO --room test --profile miro
```

다른 방 코드로 실행한 클라이언트는 다른 방에 들어가므로, 위의 두 클라이언트와 서로 보이지 않습니다.

```sh
cargo run -p caravan_client -- --name HANA --room other
```

| 옵션 | 설명 |
|---|---|
| `--name NAME` | 이름입니다. 시작 화면의 이름 칸을 미리 채웁니다. |
| `--room CODE` | 방 코드입니다. 시작 화면의 방 코드 칸을 미리 채웁니다. 주지 않으면 이 기기에서 마지막으로 입장한 방 코드가 채워집니다. |
| `--server URL` | 서버 주소입니다. 기본값은 `ws://127.0.0.1:7777`입니다. `ws://`나 `wss://`로 시작해야 합니다. |
| `--debug-net` | 주고받는 메시지를 로그에 출력합니다. |
| `--profile NAME` | 이 기기가 기억하는 것을 `memory-NAME.txt`에 따로 저장합니다(1~16자의 영문자, 숫자, `-`, `_`). 같은 컴퓨터에서 클라이언트 두 개를 실행해 두 사람을 시험할 때 서로 다른 이름을 주면 한 자리를 서로 가져가지 않습니다. 주지 않으면 `memory.txt`입니다. |

옵션이 잘못되었으면 시작 화면에 이유가 나오고 입장할 수 없습니다. 서버에 접속하지 못하면 시작 화면으로 돌아오고, 접속하려 한 서버 주소와 서버가 실행 중인지 확인하라는 안내가 나옵니다. 클라이언트는 1초마다 프레임 속도, 가장 최근에 받은 서버 Tick, 그 스냅샷의 몬스터 수를 로그로 출력합니다.

### 웹 클라이언트를 실행합니다

`crates/client`에서 `trunk serve`를 실행하면 trunk가 클라이언트를 wasm으로 빌드하고 `http://127.0.0.1:8080/`에서 페이지를 제공합니다.

```sh
cd crates/client
trunk serve
```

브라우저에서 `http://127.0.0.1:8080/`를 열면 PC와 같은 시작 화면이 나옵니다. 주소의 쿼리는 PC 클라이언트의 옵션과 같은 규칙으로 해석됩니다. 마지막으로 입장한 이름과 방 코드와 그 방의 자리의 표식은 브라우저의 `localStorage`(`caravan.memory`)에 저장되어, 새로 고침 뒤에도 칸이 채워지고 같은 자리로 돌아올 수 있습니다. 사생활 보호 창처럼 저장소를 막는 곳에서는 저장하지 못하고, 그때는 매번 빈 칸으로 시작하며 접속이 끊기면 새 플레이어로 입장합니다. 같은 브라우저 프로필의 탭은 저장소를 함께 쓰므로 한 자리를 서로 가져갑니다. 한 컴퓨터에서 두 사람을 시험하려면 서로 다른 브라우저 프로필(또는 한쪽은 사생활 보호 창)을 씁니다.

| 쿼리 | 설명 |
|---|---|
| `room=CODE` | 방 코드입니다. 시작 화면의 방 코드 칸을 미리 채웁니다. 주지 않으면 이 브라우저에서 마지막으로 입장한 방 코드가 채워집니다. |
| `name=NAME` | 이름입니다. 시작 화면의 이름 칸을 미리 채웁니다. |
| `server=URL` | 서버 주소입니다. 주지 않으면 `trunk serve`가 내준 페이지는 `ws://127.0.0.1:7777`에 접속하고, 게임 서버가 내준 페이지(아래의 「친구와 함께 플레이테스트를 합니다」)는 페이지를 연 주소의 서버에 접속합니다(`https://` 페이지는 `wss://`, `http://` 페이지는 `ws://`이고 포트는 그대로입니다). 주면 어느 페이지에서나 그 주소가 우선합니다. |
| `debug-net` | 주고받는 메시지를 브라우저 개발자 도구의 콘솔에 출력합니다. |

모든 쿼리를 쓴 주소는 `http://127.0.0.1:8080/?room=test&name=KANG&server=ws://127.0.0.1:7777&debug-net`입니다. `room`과 `name`이 모두 있으면 시작 화면 없이 곧바로 입장합니다. 웹 클라이언트와 PC 클라이언트에 같은 방 코드를 주면 같은 방에서 함께 플레이합니다.

야영지에서 `C`를 누르면 `http://127.0.0.1:8080/?room=k7m2q`처럼 방 코드가 든 링크를 클립보드에 복사합니다(그 페이지가 기본으로 접속하는 서버가 아닌 서버를 쓰고 있으면 `&server=`가 붙습니다). 친구가 이 링크를 열면 방 코드 칸이 채워진 시작 화면이 나오고, 이름만 넣고 입장하면 됩니다. 시작 화면에서 `Ctrl+V`나 `Cmd+V`를 누르면 브라우저가 클립보드를 읽어도 되는지 한 번 묻고, 거절하면 칸은 그대로이고 안내 한 줄이 나옵니다. 브라우저의 클립보드 기능은 `https://`나 `localhost`, `127.0.0.1`이 아닌 주소(예를 들면 `http://192.168.0.5:8080`)에서는 제공되지 않을 수 있고, 그때는 복사와 붙여 넣기가 되지 않습니다.

### 친구와 함께 플레이테스트를 합니다

내 컴퓨터에서 게임을 켜고, https 링크 하나를 친구에게 보내서 브라우저로 함께 원정을 할 수 있습니다. 친구는 아무것도 설치하지 않습니다. `scripts/playtest.sh`가 서버(`caravan-dedicated`)와 Cloudflare의 빠른 터널(`cloudflared tunnel`, 계정이 필요 없습니다)을 함께 켭니다. 서버가 웹 클라이언트의 파일을 게임 접속과 같은 포트로 내주므로 터널과 링크가 하나뿐입니다. TLS는 터널이 처리하고, 스크립트는 서버가 `127.0.0.1`에서만 듣게 켭니다.

켜는 방법은 다음과 같습니다.

1. `cloudflared`를 설치합니다. 스크립트는 아무것도 설치하지 않습니다. `cloudflared`가 없으면 스크립트가 아무것도 빌드하거나 켜지 않고 설치 명령(`brew install cloudflared`)을 알리고 끝납니다. 웹 빌드 도구인 trunk도 필요합니다(「설치하기」의 4번).
2. 저장소 폴더에서 `sh scripts/playtest.sh`를 실행합니다. 스크립트는 웹 클라이언트와 서버를 릴리스로 빌드하고, 터널을 켜서 주소를 받고, 그 주소를 알려 주면서 서버를 켭니다. 웹 빌드는 `target/playtest/web`에 만들고, 개발용 `crates/client/dist`는 쓰지 않습니다. 터널과 서버의 로그는 `target/playtest/tunnel.log`와 `target/playtest/server.log`에 남습니다.
3. 스크립트가 출력한 링크(`https://....trycloudflare.com/`)는 친구가 열 서버의 주소입니다.
4. 나는 브라우저에서 `http://127.0.0.1:7777/`를 열고 이름을 넣어서 방을 만듭니다. 내 접속은 터널을 지나지 않습니다.
5. 야영지에서 `C`를 눌러 초대 링크를 복사해서 친구에게 보냅니다. `127.0.0.1`로 열었어도 복사되는 링크는 터널의 https 주소와 방 코드(`https://....trycloudflare.com/?room=k7m2q`)입니다.
6. 끝나면 스크립트를 실행한 터미널에서 `Ctrl+C`를 누릅니다. 서버와 터널이 함께 꺼집니다. 서버나 터널 가운데 하나가 스스로 끝나면 스크립트가 다른 하나도 끄고 끝납니다.

친구가 들어오는 방법은 다음과 같습니다.

1. 받은 링크를 PC의 브라우저로 엽니다.
2. 시작 화면의 방 코드 칸에 코드가 채워져 있습니다. 이름을 넣고 `Enter`를 누르면 같은 야영지에 들어옵니다.

친구는 서버 주소를 입력하지 않습니다. 페이지를 연 주소가 곧 서버의 주소이기 때문입니다. `PLAYTEST_PORT=7778 sh scripts/playtest.sh`처럼 환경 변수 `PLAYTEST_PORT`로 서버의 포트를 바꿀 수 있고, 그 포트에서 듣는 프로그램이 이미 있으면 스크립트는 터널을 켜기 전에 알리고 끝납니다. 스크립트가 쓰는 서버의 옵션은 `--addr 127.0.0.1:7777 --web-dir target/playtest/web --public-url <터널의 주소>`입니다.

터널을 지나는 크기와 시간을 한 번 잰 값은 다음과 같습니다(`cloudflared` 2026.11.2, 터널이 붙은 Cloudflare의 지점은 서울).

- 릴리스 웹 빌드의 `.wasm`은 원본이 44,825,197바이트입니다. 서버는 압축하지 않고 내주고, 터널이 gzip으로 압축해서 브라우저에는 11,001,598바이트가 전송됩니다. `index.html`과 `.js`는 터널을 지나도 내용이 바뀌지 않습니다.
- 이 컴퓨터에서 터널의 링크로 보낸 요청이 첫 응답을 받기까지의 시간은 가운데 값 41.0ms(가장 짧은 값 31.1ms, 가장 긴 값 51.2ms, 12번)이고, `127.0.0.1`로 보낸 같은 요청은 0.1ms입니다. 친구의 조작은 친구의 회선에서 이 터널을 지나는 왕복 시간만큼 더 늦게 화면에 나타납니다. 친구의 회선에서 잰 값은 아닙니다. 서버는 `.wasm`을 압축하지 않고 터널 프로그램에 넘기고 압축은 Cloudflare의 지점에서 일어나는 것으로 보이므로, 친구 한 명이 페이지를 열 때 내 컴퓨터의 올리는 회선으로 약 45MB가 나갑니다(추정이고 재지 않았습니다).

스크립트를 쓰지 않는 개발 방식(`trunk serve`와 `caravan-dedicated`를 따로 켜기)은 그대로 동작합니다. `trunk serve`가 내준 페이지에는 서버의 공개 주소가 없으므로, `?server=` 없이도 `ws://127.0.0.1:7777`의 서버에 접속하고 초대 링크는 그 페이지의 주소로 만들어집니다.

터널이 켜져 있는 동안은 이 컴퓨터의 서버 포트가 인터넷에 공개됩니다. 서버가 내주는 것은 `--web-dir` 폴더의 `.html`, `.js`, `.wasm` 파일과 게임 접속뿐이고, 링크를 아는 사람은 누구나 서버에 접속할 수 있으며 방에 들어오려면 방 코드가 필요합니다. 비밀번호나 접속 허용 목록은 없습니다. 플레이를 마치면 반드시 `Ctrl+C`로 끕니다. 스크립트를 `kill -9`로 끝냈다면 터널과 서버를 끄지 못하므로 `cloudflared`와 `caravan-dedicated`의 프로세스를 직접 끕니다.

### 게임의 진행

방은 야영지에서 시작합니다. 야영지는 원정과 같은 지도이고, 몬스터와 상자와 채집 지점이 없습니다. 마차 동쪽에 허수아비 셋이 한 줄로 서 있고, 마차 북쪽에 무기마다 하나씩 여섯 진열대가 있습니다. 진열대에서 `F`를 누른 순간 그 무기를 집을 수 있고, 진열대에는 무기가 그대로 남습니다. 이미 가진 종류의 진열대에서는 집지 않고, 두 칸이 모두 차 있으면 든 무기를 내주며, 내준 무기는 바닥에 놓이지 않고 사라집니다. 야영지에서는 무기를 버리는 키(`G`)도 아무 일도 하지 않으므로 바닥에 무기가 쌓이지 않습니다. 허수아비는 맞아도 사라지지 않고, 맞은 피해가 허수아비 위에 숫자로 뜹니다. 허수아비에게도 무기의 효과가 걸려서 몸통 색이 효과의 색으로 바뀌지만, 야영지에서는 피해를 적용하지 않으므로 출혈은 피해를 주지 않고 출혈의 숫자도 뜨지 않습니다. 야영지에서는 아무도 피해를 받지 않고 건설할 수 없습니다. 화면 오른쪽 위에 방 코드와 `C` 안내(`ROOM k7m2q   C  COPY LINK`), 방에 있는 모든 플레이어의 준비 목록이 `KANG  (YOU)  READY`처럼 이름과 함께 나오고(자리를 비운 사람은 준비했는지와 관계없이 `MIRO  AWAY`입니다), `R`을 누르면 준비를 켜고 끕니다. 방에 있는 모두가 준비하면 `STARTING IN 3`이 3초를 세고 원정이 시작되며, 그 사이에 누가 준비를 끄거나 준비하지 않은 사람이 들어오면 세던 시간이 취소됩니다. 준비한 사람이 방에서 나가는 것은 취소하지 않습니다. 원정이 시작되면 모든 플레이어가 검 하나, 최대 HP로 등장 지점에 서고, 야영지의 허수아비와 진열대는 사라집니다. 원정이 진행되는 방에 들어온 사람은 마차 곁에서 바로 합류합니다. 야영지에서 60초 동안 조작(이동, 조준, 버튼의 바뀜)이 없는 사람은 키를 누르고 있기만 해도 자리를 비운 것으로 보여서 「모두 준비」의 대상에서 빠지고, 나머지가 시작합니다. 그 사람의 자리는 남고, 조작하면 준비하지 않은 상태로 돌아옵니다. 그 사람 없이 시작한 원정에서는 조작할 때까지 캐릭터가 몬스터와 피해로부터 보호받습니다. 접속이 끊겨서 서버가 60초 동안 자리를 유지하는 사람도 같은 방식으로 자리를 비운 것으로 보입니다. 다른 사람의 화면에서 그 캐릭터는 반투명해지고 이름 뒤에 `AWAY`가 붙으며, 결과 화면의 확인 인원(`(1 / 2)`)은 자리를 비운 사람을 세지 않습니다. 방에 자리에 있는 사람이 아무도 없으면 방의 시간이 멈추고, 누군가 돌아오면 멈춘 곳에서 이어집니다.

원정은 첫날의 낮으로 시작하고, 화면 오른쪽 위에 지금이 몇 번째 날의 낮인지 밤인지(`DAY 1 / 3`, `NIGHT 1 / 3`)와 낮의 남은 시간이나 무리의 번호가 나옵니다. 마지막 무리를 처치한 뒤의 경고 동안에는 `BOSS IN 5s`가, 보스와 싸우는 동안에는 `BOSS`가 나옵니다.

1. 낮은 90초 동안 이어지고, 플레이어들은 이 시간에 포탑을 세우고 채집 지점에서 자원을 모읍니다. 보관함에는 처음부터 자원이 10 있어서 감시탑 하나를 바로 세울 수 있습니다. 채집 지점은 여덟 곳이고, 지점마다 낮의 몬스터 둘이 곁에서 지킵니다. 낮의 몬스터는 자기 자리에서 6타일 안으로 들어온 플레이어를 쫓고, 플레이어가 자리에서 6타일보다 멀어지면 자리로 돌아갑니다. 낮이 시작될 때 무기 상자 세 개가 후보 자리 여덟 곳 가운데 서로 다른 세 곳에 놓이고, 상자마다 낮의 몬스터 셋이 곁에서 지킵니다. 상자를 열어서 무기를 얻는 방법은 아래의 「무기」에 있습니다.
2. 낮이 끝나면 밤이 시작되고, 처치하지 않은 낮의 몬스터는 자리를 떠나 마차로 향하고, 열지 않은 상자는 사라집니다. 3초 뒤에 첫 무리가 마차에서 18타일 떨어진 곳에 한 마리씩 나타납니다. 무리마다 나타나는 방향이 달라지고, 여덟 방향을 모두 씁니다. 파괴병만은 같은 무리의 다른 몬스터가 나타나는 방향의 반대쪽에서 나타납니다.
3. 무리의 몬스터를 모두 처치하면 4초 뒤에 그 밤의 다음 무리가 나타납니다. 그 밤의 마지막 무리를 처치하면 4초 뒤에 다음 날의 낮이 시작됩니다. 마지막 밤에는 다음 날이 없으므로 5번처럼 끝납니다. 무리는 한 종류가 아니라 종류가 섞여 있을 수 있고, 밤마다의 구성은 아래 「몬스터의 종류」의 표에 있습니다. 밤마다 몬스터의 수는 첫째 밤 20마리, 둘째 밤 90마리, 셋째 밤 300마리입니다. 이 수는 네 명이 있을 때의 크기입니다. 밤이 시작될 때 방에 있는 사람(자리를 비운 사람 포함)이 네 명보다 적으면 묶음마다 `올림(수 × 인원 / 4)`마리가 나오고, 무리의 크기는 그 합이며, 그 인원에서 나오는 묶음은 인원이 몇 명이어도 한 마리 이상입니다. 파괴병은 방에 2명 이상 있을 때만 나오고, 한 명이 있으면 그 수만큼 기본 몬스터가 대신 나오므로 무리의 크기는 그대로입니다(아래 「몬스터의 종류」). 예를 들어 한 명이 있으면 첫째 밤은 2마리와 3마리이고, 두 명이면 4마리와 6마리입니다. 둘째 밤의 둘째 무리(기본 몬스터 20마리와 돌격병 10마리)는 한 명이면 기본 몬스터 5마리와 돌격병 3마리이고, 두 명이면 10마리와 5마리입니다. 묶음마다 올림하므로 기본 몬스터의 묶음 21마리와 돌격병의 묶음 3마리를 한 명이 맞으면 6마리와 1마리로 7마리이고, 둘을 합친 24마리를 올림한 6마리가 아닙니다. 밤 도중에 들어오거나 나가도 그 밤의 무리의 크기는 바뀌지 않습니다. 낮의 몬스터(채집 지점과 상자를 지키는 몬스터)는 인원과 관계없이 같은 수입니다.
4. 다음 낮이 시작될 때 모든 플레이어가 최대 HP의 살아 있는 상태가 됩니다. 쓰러졌거나 사망한 플레이어도 그 자리에서 되살아납니다. 채집 지점은 다시 가득 차고, 낮의 몬스터가 지점마다 다시 놓이고, 무기 상자가 새로 놓입니다. 포탑과 그 HP, 마차의 HP, 보관함과 플레이어가 든 자원, 땅에 떨어진 자원은 그대로 이어집니다.
5. 셋째 밤의 마지막 무리를 처치하면 낮이 오지 않고, 화면 가운데에 `THE BOSS IS COMING  5`가 5초부터 줄어들며 나옵니다. 경고가 끝나면 보스가 나타나고(아래 「보스」), 보스를 쓰러뜨리면 `EXPEDITION SUCCESS`가 나옵니다. 경고와 보스와 싸우는 동안에도 플레이어는 움직이고, 싸우고, 부활과 수리와 건설을 할 수 있습니다(보스의 돌진에 맞아 밀려나는 0.3초 동안은 할 수 없습니다). 마차의 HP가 0이 되거나 모든 플레이어가 쓰러졌거나 사망하면 낮이든 밤이든 경고 중이든 보스와 싸우는 중이든 `EXPEDITION FAILED`가 나옵니다.
6. 결과 화면이 나오면 세계가 멈추고, 화면 가운데에 원정의 요약과 개인별 기록의 표가 나옵니다. 요약은 `DAYS 3 / 3    TIME 14:32    TOWER KILLS 41`처럼 버틴 날과 걸린 시간(분과 초)과 포탑이 처치한 몬스터의 수이고, 표는 플레이어마다 한 줄이며 번호가 작은 사람이 위에 있습니다. 표의 칸은 `KILLS`(마지막 피해를 주어 처치한 몬스터), `REVIVES`(끝까지 마친 부활), `DOWNS`(쓰러진 횟수), `DEPOSITED`(보관함에 넣은 자원)입니다. 원정이 끝난 순간 방에 있던 사람은 자리를 비운 사람도 표에 있고, 결과 화면이 열린 뒤에 방을 나가도 그 줄은 남습니다. 요약과 표는 그 원정의 결과가 도착했을 때만 나옵니다. 그 아래에 확인한 사람의 수(`ENTER  BACK TO CAMP  (1 / 2)`)와 야영지로 돌아가기까지 남은 시간이 나옵니다. `Enter`로 각자 확인하고, 방에 있는 모두가 확인하거나 60초가 지나면 같은 사람들과 야영지로 돌아갑니다. 새 원정은 저절로 시작되지 않고, 야영지에서 다시 모두가 준비해야 시작됩니다. 새 원정이 시작되면 포탑과 보관함과 마차의 HP가 처음으로 돌아갑니다.

살아 있는 플레이어가 마차에서 3타일 안에 있으면 낮이든 밤이든, 공격받는 중이든 HP가 1초에 5씩 회복됩니다. 쓰러진 플레이어는 회복되지 않습니다. 마차의 HP는 날이 바뀌어도 저절로 회복되지 않으므로, 플레이어가 마차 곁에서 `F`를 눌러 수리합니다. 수리는 포탑을 짓는 것과 같은 보관함의 자원을 씁니다.

한 밤에 동시에 살아 있는 몬스터는 300마리까지이고, 이 수에 이르면 무리의 등장이 멈췄다가 몬스터가 줄면 이어집니다.

### 몬스터의 종류

밤에 나오는 몬스터는 기본 몬스터(`Grunt`), 돌격병(`Runner`), 파괴병(`Sapper`) 세 종류이고(보스와 야영지의 허수아비는 따로입니다), 낮에 채집 지점과 상자를 지키는 몬스터는 기본 몬스터입니다. 종류마다 수치와 무엇을 쫓는지(`Prey`)와 포탑에 주는 피해의 비율(`siege_percent`)과 포탑이 준 피해를 받는 비율(`Resist::tower_damage_percent`)과 무리의 어느 쪽에서 나타나는지(`SpawnSide`)가 `crates/rules/src/tuning.rs`의 종류표(`MonsterTable`)의 한 행에 있고, 규칙은 종류를 보고 갈라지지 않고 그 값을 읽습니다(`monster::raid_goal`, `Monster::damage_to`, `World::apply_hits`). 나타나는 쪽은 밤의 무리와 보스와 보스의 졸개가 종류의 `spawn_side`를 `SpawnPlan::night_spot`에 넘겨서 정합니다. 종류가 몇 명 이상의 방에서 나오는지는 종류표가 아니라 무리의 묶음(`Pack::joins`)이 정합니다. 나오지 않는 방에서는 그 묶음의 수가 같은 무리에서 방의 인원과 관계없이 나오는 다른 종류의 묶음으로 가고, 무리의 크기는 그대로입니다. 보스의 졸개는 무리의 묶음이 아니므로 이 규칙을 따르지 않고, 졸개의 종류(`SummonTuning::kind`)는 방의 인원과 관계없이 나옵니다.

| 종류 | 화면 | HP | 걷는 몸 | 속도 | 피해 (1초마다) | 쫓는 것 |
|---|---|---|---|---|---|---|
| 기본 몬스터 `Grunt` | 빨강, 12 x 20 픽셀 | 60 | 0.4타일 | 2.2 | 10 | `Prey::Nearby`: 마차로 가다가 5타일 안의 가장 가까운 플레이어나 걸어서 5걸음 안의 포탑을 쫓습니다. |
| 돌격병 `Runner` | 밝은 주황, 9 x 15 픽셀 | 30 | 0.3타일 | 3.2 | 8 | `Prey::Wagon`: 아무것도 쫓지 않고 마차로 곧장 가서 마차를 때립니다. |
| 파괴병 `Sapper` | 어두운 갈색, 17 x 26 픽셀 | 120 | 0.4타일 | 1.7 | 10 (포탑에는 40) | `Prey::Towers`: 플레이어를 쫓지 않고, 걸어서 닿는 가장 가까운 포탑으로 가서 그 포탑을 때립니다. 닿는 포탑이 없으면 마차로 갑니다. 포탑이 준 피해는 30%만 받고, 같은 무리의 다른 몬스터와 반대쪽에서 나타납니다. 방에 2명 이상 있을 때만 나옵니다. |

- 돌격병은 길 곁의 플레이어와 포탑을 지나치고, 플레이어와 포탑에게 맞아도 대상을 바꾸지 않습니다. 몬스터는 목표를 기억하지 않고 Tick마다 종류의 `prey`로 새로 고르기 때문입니다.
- 돌격병의 속도 3.2는 기본 몬스터(2.2)보다 빠르고, 걷는 플레이어(4.0)보다 느립니다. 마차에서 12타일 떨어진 같은 곳에서 출발하면 돌격병은 72 Tick에, 기본 몬스터는 103 Tick에 마차를 때립니다(`a_runner_is_faster_than_a_grunt_and_slower_than_a_walking_player_and_has_less_hp`).
- 돌격병의 HP가 30이므로 소총, 대검, 창은 한 번에, 검, 활, 석궁은 두 번 맞혀서 처치합니다. 감속, 스턴, 출혈은 기본 몬스터와 같이 듣습니다.
- 돌격병은 포탑이 준 피해의 25%(올림)만 받습니다(`Resist::tower_damage_percent`이고, 보스의 저항과 같은 방식입니다). 감시탑의 사격 15는 4가 되므로 실제 비율은 약 27%이고, 감시탑이 돌격병 한 마리를 처치하려면 사격이 여덟 번 필요합니다(기본 몬스터는 네 번이고, 줄이지 않으면 돌격병은 두 번입니다). 플레이어의 무기가 주는 피해와 무기의 효과는 줄지 않습니다. 마차로 곧장 달려가는 몬스터를 감시탑이 모두 먼저 처치하면 마차를 지키는 사람이 필요 없습니다. 그래서 돌격병은 포탑으로 막기 어렵고 사람이 처치해야 하는 몬스터가 되도록 이 값을 정했습니다(`a_tower_hit_takes_a_quarter_of_the_damage_off_a_runner_rounded_up_and_all_of_it_off_a_grunt`, `a_watchtower_shot_takes_four_hp_off_a_runner_and_fifteen_off_a_grunt`). 감시탑만으로 돌격병을 얼마나 막는지, 그리고 플레이어가 마차를 지키면 얼마나 달라지는지는 아래 「현재의 한계」에 있습니다.
- 돌격병의 걷는 몸(0.3)과 걷는 몸에 공격 거리를 더한 값(0.8)은 기본 몬스터(0.4와 0.9) 이하입니다. 그래서 모든 종류의 최댓값을 읽는 `largest_radius`와 `longest_engage_distance`는 돌격병이 있어도 기본 몬스터의 값이고, 몬스터가 나타나는 자리, 도착하는 타일, 건설의 길 막힘 검사도 기본 몬스터의 값으로 정해집니다(`a_runner_adds_nothing_to_the_largest_body_or_the_longest_reach_the_rules_read`).
- 화면에서 돌격병은 기본 몬스터보다 작고 밝은 주황(`crates/client/src/config.rs`의 `RUNNER`)입니다. 이 색은 기본 몬스터, 허수아비, 보스, 플레이어, 쓰러진 플레이어, 효과(스턴, 감속, 출혈), 마차, 바닥의 색에서 `config.rs`의 테스트가 확인하는 거리(sRGB 공간에서 0.25 이상)만큼 떨어져 있습니다. 글자나 아이콘은 없고 색과 크기로만 구분합니다.
- 파괴병은 플레이어를 쫓지 않고 포탑으로 갑니다(`Prey::Towers`). 서 있는 포탑 가운데 걸어서 닿을 수 있고 길을 따라 가장 가까운 포탑을 고르고, 거리의 한계가 없으므로 마을 건너편의 포탑도 노립니다. 길 곁의 플레이어를 지나치고, 플레이어에게 맞아도 목표를 바꾸지 않습니다. 목표를 Tick마다 새로 고르므로 때리던 포탑이 부서지면 그다음으로 가까운 포탑으로 갑니다(`a_sapper_walks_past_a_player_beside_its_way_to_a_tower_far_beyond_a_grunts_chase_range_and_hits_only_the_tower`, `a_sapper_that_a_player_hits_does_not_turn_on_the_player_and_goes_on_to_the_tower`, `a_sapper_walks_to_the_tower_nearest_by_path_not_by_straight_line_however_far_it_is`, `a_sapper_goes_on_to_the_next_nearest_tower_when_the_one_it_was_hitting_falls`).
- 걸어서 닿는 포탑이 없으면 파괴병은 마차로 가서 기본 몬스터와 같은 피해(10)로 마차를 때립니다. 마지막 포탑이 부서진 뒤에도 마찬가지입니다(`a_sapper_with_no_tower_to_hit_goes_to_the_wagon_and_hits_it_for_a_grunts_damage`, `a_sapper_whose_last_tower_falls_walks_on_to_the_wagon`). 짓는 중인 포탑은 목표가 아닙니다. 파괴병은 짓는 중인 포탑을 지나쳐서 마차로 가고, 그 포탑이 다 지어져서 서면 마차로 걷던 파괴병도 돌아서서 그 포탑을 때립니다(`a_tower_that_is_still_being_built_is_not_a_target_for_a_sapper`, `a_tower_that_stands_at_last_becomes_a_target_for_a_sapper_that_was_walking_to_the_wagon`). 포탑이 지어지거나 부서져서 마을의 모양이 바뀌면 포탑으로 가는 길의 계산(포탑 흐름장)이 다시 만들어집니다.
- 파괴병은 같은 무리의 다른 몬스터와 반대쪽에서 나타납니다(`MonsterTuning::spawn_side`가 `SpawnSide::OppositeWave`입니다). 무리마다 나타나는 방향이 하나 정해지고, 다른 종류는 그 방향의 자리에 서고 파괴병은 정반대 방향의 자리에 섭니다. 정반대 방향에 자리가 없는 맵에서는 가장 반대에 가까운 방향에 서고, 같은 거리이면 앞의 방향입니다. 자리는 무리의 순번과 몬스터의 순번과 종류의 수치만으로 정해지는 순수 함수(`SpawnPlan::night_spot`)이므로 원정의 진행에 저장하는 상태가 없습니다. 종류의 `spawn_side`는 기본 몬스터, 돌격병, 보스, 허수아비에서 `SpawnSide::WithWave`이고, 보스가 부르는 졸개도 그 종류의 값을 따릅니다. 반대쪽에서 나타나는 것과 포탑이 준 피해를 일부만 받는 것은 함께 정한 값입니다. 이유와 측정은 아래 「현재의 한계」에 있습니다(`a_sapper_comes_from_the_side_of_the_wagon_opposite_the_rest_of_its_wave`, `where_the_wagon_has_no_spots_on_some_sides_a_sapper_comes_from_the_nearest_side_to_the_opposite`, `only_the_sapper_stands_opposite_the_rest_of_its_wave_at_the_default_numbers`).
- 포탑에 주는 피해는 기본 피해에 포탑 피해 비율(`siege_percent`)을 곱한 값입니다. 파괴병의 비율은 400이므로 포탑에 1초마다 40을 주고(기본 몬스터는 10), 감시탑(HP 300)을 여덟 번째 공격에 부숩니다(기본 몬스터는 서른 번째입니다). 마차와 플레이어에게는 기본 피해 10을 그대로 줍니다. 기본 몬스터, 돌격병, 보스의 비율은 100입니다. 곱한 값은 올림하고, 이 계산은 `Monster::damage_to` 한 곳에서 합니다(`a_sapper_breaks_a_watchtower_in_eight_hits_where_a_grunt_needs_thirty`, `a_monster_hits_a_tower_for_its_damage_times_its_siege_percent_and_the_wagon_and_a_player_for_its_damage`, `the_siege_percent_rounds_up_so_that_a_hit_that_does_any_damage_takes_something_off_a_tower`, `only_the_sapper_hits_a_tower_harder_than_it_hits_the_wagon_at_the_default_numbers`).
- 파괴병의 속도 1.7은 기본 몬스터(2.2)보다 느리고 걷는 플레이어(4.0)보다 훨씬 느립니다. 마차에서 12타일 떨어진 같은 곳에서 출발하면 파괴병은 133 Tick에, 기본 몬스터는 103 Tick에 마차를 때립니다(`a_sapper_is_slower_than_a_grunt_and_has_more_hp_and_hits_the_wagon_later_from_the_same_start`). 파괴병의 HP 120은 기본 몬스터의 두 배입니다. 파괴병은 플레이어의 피해를 줄이지 않고 모두 받고, 포탑이 준 피해는 30%(올림)만 받습니다. 감시탑의 사격 15는 5가 되므로 감시탑이 파괴병 한 마리를 처치하려면 사격이 스물네 번 필요합니다(기본 몬스터는 네 번입니다). 감시탑은 0.8초마다 쏘므로 스물네 번을 쏘는 데 약 18초가 걸리고, 파괴병은 같은 감시탑을 약 7초에 부숩니다. 그래서 감시탑 하나만으로는 파괴병을 막지 못합니다(`a_sapper_takes_thirty_percent_of_a_towers_damage_rounded_up_and_all_of_a_players_damage`, `a_watchtower_shot_takes_five_hp_off_a_sapper`). 감속, 스턴, 출혈은 기본 몬스터와 같이 듣습니다(`a_slowed_sapper_walks_at_the_slowed_speed_for_the_time_of_the_slow`, `a_stunned_sapper_stands_still_for_the_time_of_the_stun`, `a_bleeding_sapper_loses_hp_once_a_second`).
- 파괴병의 걷는 몸(0.4)과 걷는 몸에 공격 거리를 더한 값(0.9)은 기본 몬스터와 같습니다. 그래서 `largest_radius`와 `longest_engage_distance`는 파괴병이 있어도 그대로이고, 몬스터가 나타나는 자리, 도착하는 타일, 건설의 길 막힘 검사도 달라지지 않습니다(`a_sapper_adds_nothing_to_the_largest_body_or_the_longest_reach_the_rules_read`). 건설 규칙이 허락하는 가장 빽빽한 마을에서도 파괴병이 포탑이나 마차를 때리지 못하고 서 있는 자리는 없습니다. 이 시험은 포탑의 상한을 풀고 네 가지 순서(마차에 가까운 곳부터, 먼 곳부터, 줄을 따라, 섞은 순서)로 마을을 가득 채우고(포탑 368개에서 405개), 마차에서 13타일 안의 비어 있는 모든 타일(106개에서 143개)에 파괴병을 하나씩 놓아서 1200 Tick 안에 포탑이나 마차를 때리는지 봅니다(`a_sapper_hits_a_tower_or_the_wagon_from_every_free_tile_of_the_densest_village_the_build_rules_allow`).
- 화면에서 파괴병은 기본 몬스터보다 크고(17 x 26 픽셀이고, 보스는 40 x 56 픽셀입니다) 어두운 갈색(`crates/client/src/config.rs`의 `SAPPER`)입니다. 이 색도 기본 몬스터, 돌격병, 허수아비, 보스, 플레이어, 쓰러진 플레이어, 효과, 마차, 바닥의 색에서 `config.rs`의 테스트가 확인하는 거리(sRGB 공간에서 0.25 이상)만큼 떨어져 있습니다. 글자나 아이콘은 없고 색과 크기로만 구분합니다.

밤마다의 구성은 다음과 같습니다(수는 네 명이 있을 때의 크기이고, 밤마다의 합은 20, 90, 300입니다).

|---|---|---|---|
| 첫째 | 기본 8 | 기본 12 | |

한 무리 안의 종류는 번갈아 나타납니다. 순서는 「아직 나오지 않은 비율이 가장 큰 묶음을 고르고, 같으면 목록의 앞쪽」이고, 순수 함수 `Wave::kind_at`이 묶음마다의 수와 몇 번째인지만으로 정하므로 원정의 진행(`NightStep::Fighting`)에 저장하는 상태가 없고 같은 입력이면 언제나 같은 순서입니다. 기본 20과 돌격병 10이면 기본, 돌격병, 기본, 기본, 돌격병, 기본, 기본, 돌격병의 순으로 시작해서 기본 두 마리에 돌격병 한 마리가 이어집니다. 몇 번째인지는 무리 전체에서 세므로 나타나는 자리는 한 종류뿐인 무리와 같은 규칙으로 정해집니다. 한 종류뿐인 무리는 그 종류가 무리의 크기만큼 이어지고, 크기는 `올림(수 × 인원 / 4)`입니다. 묶음마다 나올 수는 방의 인원으로 바꾼 수이고, 그 방에 나오지 않는 묶음의 수는 대신 나올 종류의 묶음에 더합니다(`Wave::counts`). 무리의 크기(`Wave::size`)와 종류의 순서(`Wave::kind_at`)가 이 같은 수를 읽습니다.

파괴병은 셋째 밤의 둘째 무리와 셋째 무리에만, 방에 2명 이상 있을 때만 나옵니다. 2명이면 5마리와 10마리, 3명이면 8마리와 15마리, 4명이면 10마리와 20마리입니다. 한 명이 있으면 파괴병이 나오지 않고 그 수(3마리와 5마리)만큼 기본 몬스터가 더 나옵니다. 그래서 둘째 무리와 셋째 무리의 기본 몬스터는 18마리와 28마리이고, 무리의 크기는 23마리와 38마리로 파괴병이 나올 때와 같습니다(`sappers_come_only_in_the_second_and_third_wave_of_the_third_night_to_rooms_of_two_or_more`, `where_the_sappers_do_not_come_grunts_come_in_their_place_and_the_wave_is_as_big_as_with_them`). 첫째 밤과 둘째 밤에는 나오지 않습니다.

「몇 명 이상의 방에서 나오는가」와 「나오지 않을 때 그 수가 어느 종류로 가는가」는 묶음의 수치(`Joins::FromParty { min_party, instead }`)이고, 파괴병의 묶음은 `min_party`가 2이고 `instead`가 기본 몬스터입니다. 그러므로 규칙에는 종류나 인원을 보고 갈라지는 곳이 없고, 같은 규칙을 다른 종류나 다른 인원에 적용할 수 있습니다(`a_pack_that_joins_from_a_party_comes_to_rooms_of_that_party_or_more_and_hands_its_count_over_below_it`). 대신 나올 종류의 묶음이 같은 무리에 여럿이면 목록의 가장 앞의 묶음으로 갑니다(`a_pack_that_does_not_join_hands_its_count_to_the_first_pack_that_joins_everywhere_of_its_kind`). `Tuning::validate`는 대신 나올 종류가 같은 무리에서 방의 인원과 관계없이 나오는 묶음에 없는 묶음을 거절합니다(`a_pack_that_joins_from_a_party_needs_a_pack_of_the_kind_it_stands_in_with_that_joins_everywhere`). 이 조건을 지키면 어느 인원의 방에서도 무리가 비지 않습니다. 방의 정원보다 큰 `min_party`는 그 방에서 한 번도 나오지 않을 뿐이므로 거절하지 않습니다. 인원은 무리의 크기가 쓰는 값(`Phase::Night`의 `party`, 밤이 시작될 때 방에 있는 사람)과 같으므로, 밤 도중에 사람이 들어오거나 나가도 그 밤에 나오는 종류는 바뀌지 않습니다.

### 무기

플레이어는 무기를 두 칸에 가집니다. 원정은 검 하나와 빈 칸 하나로 시작하고, 나머지 무기는 낮에 상자에서 얻습니다. 무기마다 다른 수치는 `crates/rules/src/tuning.rs`의 무기 표(`WeaponTable`)에서 무기 하나가 한 행입니다. 몬스터를 맞혔을 때 거는 효과(`on_hit`)도 같은 행에 있습니다. 부채꼴의 거리는 플레이어의 가장자리에서 몬스터의 가장자리까지 잰 값이고, 각도는 조준 방향의 양쪽으로 잰 절반 각도입니다.

| 무기 | 화면의 이름 | 공격 방식 | 피해량 | 쿨다운 | 닿는 곳 | 맞은 몬스터에 거는 효과 | 상자에서 나옴 |
|---|---|---|---|---|---|---|---|
| 검 | `SWORD` | 부채꼴 | 25 | 0.5초 | 1.0타일, 양쪽으로 60도씩 | 출혈 (3초 동안 1초마다 5) | 아니요 (처음에 듭니다) |
| 대검 | `GREATSWORD` | 부채꼴 | 45 | 1.0초 | 1.3타일, 양쪽으로 90도씩 | 스턴 (0.8초) | 예 |
| 창 | `SPEAR` | 부채꼴 | 30 | 0.6초 | 2.2타일, 양쪽으로 15도씩 | 출혈 (3초 동안 1초마다 6) | 예 |
| 활 | `BOW` | 탄환 | 15 | 0.4초 | 초당 14타일의 속도, 사거리 9타일, 반지름 0.15타일, 한 마리 | 감속 (2초 동안 이동 속도 50%) | 예 |
| 석궁 | `CROSSBOW` | 관통하는 탄환 | 20 | 0.9초 | 초당 18타일의 속도, 사거리 11타일, 반지름 0.15타일, 최대 네 마리 | 감속 (2초 동안 이동 속도 50%) | 예 |
| 소총 | `RIFLE` | 즉시 명중 | 60 | 1.5초 | 사거리 12타일, 선의 굵기 0 | 스턴 (0.8초) | 예 |

몬스터(`Grunt`)의 HP는 60이므로 소총은 한 번에 처치하고, 대검과 창은 두 번, 검과 석궁은 세 번, 활은 네 번 맞혀야 처치합니다. 돌격병(`Runner`)의 HP는 30이므로 소총, 대검, 창은 한 번에, 검, 석궁, 활은 두 번 맞혀서 처치합니다. 파괴병(`Sapper`)의 HP는 120이므로 소총은 두 번, 대검은 세 번, 창은 네 번, 검은 다섯 번, 석궁은 여섯 번, 활은 여덟 번 맞혀야 처치합니다(효과로 주는 피해는 세지 않았습니다).

석궁의 탄환과 소총의 선이 몬스터를 맞히는 규칙은 다음과 같습니다. 두 무기는 몬스터를 앞에서부터 찾는 함수(`sweep::monsters_along`)를 함께 씁니다.

- 석궁의 탄환은 한 Tick에 지나간 선분 위에서 닿는 몬스터를 닿는 순서대로 최대 네 마리까지 맞힙니다. 네 마리 모두 같은 피해를 받고, 한 몬스터는 한 번만 맞습니다. 네 마리째를 맞힌 탄환과 사거리의 끝에 이른 탄환은 사라집니다. 활은 같은 규칙에서 맞힐 수 있는 수가 한 마리입니다.
- 막힌 타일은 탄환과 소총의 선을 막습니다. 몬스터가 막힌 타일과 같은 거리에 있으면 그 몬스터를 먼저 맞힙니다. 탄환과 소총의 선은 플레이어를 지나가고, 맞히는 것은 몬스터뿐입니다.
- 소총은 누른 Tick에 조준한 방향으로 사거리 12타일의 선을 긋고, 선 위에서 처음 닿는 몬스터 한 마리만 맞힙니다. 선의 굵기가 0이므로 선이 몬스터의 몸(기본 몬스터와 파괴병은 반지름 0.4타일, 돌격병은 0.3타일)을 지나갈 때만 맞습니다. 막힌 타일 뒤와 사거리 밖의 몬스터는 맞지 않습니다.
- 소총의 선이 끝난 자리(몬스터의 가장자리, 막힌 타일, 사거리의 끝 가운데 가장 가까운 곳)는 서버가 플레이어의 마지막 공격(`LastAttack::trace_end`)에 적고 스냅샷에 싣습니다. 선의 시작은 보내지 않으므로, 클라이언트는 쏜 플레이어가 지금 서 있는 자리에서 그 끝까지 흰 선을 그리고, 이 선은 6 Tick(0.3초) 동안 흐려지다가 사라집니다.

무기를 얻고 가지는 규칙은 다음과 같습니다.

1. 상자는 낮이 시작될 때마다 세 개가 놓입니다. 후보 자리 여덟 곳(`MapSpec::chest_sites`) 가운데 서로 다른 세 곳이 뽑히고, 마을의 범위 밖입니다. 상자 안의 무기는 상자마다 따로, 검을 뺀 무기 가운데 같은 확률로 하나가 정해집니다. 그래서 같은 무기가 두 상자에 들어 있을 수도 있습니다. 어느 자리에 어떤 무기가 든 상자가 놓이는지는 방의 씨앗이 정하므로, 같은 씨앗이면 같고(`--seed`), 화면에는 상자의 안이 보이지 않습니다.
2. 상자는 채집 지점처럼 타일 하나를 막고, 상자마다 낮의 몬스터 셋이 곁에서 지킵니다. 이 몬스터는 채집 지점을 지키는 몬스터와 같은 규칙을 따라서, 자리에서 6타일 안으로 들어온 플레이어를 쫓고 밤이 되면 마차로 향합니다. 열지 않은 상자는 밤이 시작될 때 사라집니다.
3. 상자 곁에서 `F`를 1.5초 끊지 않고 누르고 있으면 상자가 사라지고, 상자가 있던 타일의 중심에 상자 안의 무기가 떨어집니다. 플레이어의 가장자리에서 상자의 가장자리까지 1타일 안이면 상자를 열 수 있습니다. 여는 동안에는 이동과 공격을 할 수 없고, 피해를 받거나 `F`를 놓으면 처음부터 다시 눌러야 합니다. 지키는 몬스터가 살아 있어도 맞지 않는 동안에는 열 수 있습니다. 여는 도중에 동료가 쓰러져도 여는 일은 이어지고, 다 연 뒤에 `F`를 계속 누르고 있으면 부활이 시작됩니다.
4. 바닥의 무기 곁에서 `F`를 누른 순간 무기를 줍습니다. 플레이어의 가장자리에서 무기가 놓인 점까지 1.75타일 안이면 줍습니다. 이 거리는 상자를 열 수 있는 거리(1타일)에 타일의 대각선 절반(약 0.71타일)을 더한 값보다 짧을 수 없으므로(`Tuning::validate`가 거절합니다), 상자를 열 수 있는 어느 자리에서든 걷지 않고 `F`를 한 번 눌러서 그 무기를 주울 수 있습니다. 빈 칸이 있으면 빈 칸에 들어가고, 칸이 모두 차 있으면 든 무기와 바뀌어서 이전에 든 무기가 바닥의 그 자리에 놓입니다. 그래서 상자에서 나온 무기를 동료에게 넘길 수 있습니다. 이전에 든 무기가 시작 무기와 같은 종류(검)이면 바닥에 놓이지 않고 사라집니다.
5. 든 무기를 `G`를 누른 순간 버립니다. 다른 칸에 무기가 있으면 든 무기가 플레이어가 선 자리의 바닥에 놓이고 다른 칸의 무기를 들며, 버린 칸은 빕니다. 무기가 하나뿐이면 맨손이 되므로 버릴 수 없고 아무 일도 일어나지 않습니다. 칸이 모두 찬 채로 줍기만 하면 이전에 든 무기가 줍는 무기와 같은 자리에 놓여서 무기가 겹칩니다. `G`로 원하는 자리에서 칸을 먼저 비우면 `F`가 빈 칸에 줍기만 하므로 무기가 겹치지 않습니다. 시작 무기와 같은 종류(검)는 줍기의 맞바꿈과 같이 바닥에 놓이지 않고 사라집니다. 그래서 바닥의 무기는 계속 모두 상자에서 나온 것이고, 그 수가 상자에서 나온 무기의 수(원정 하나에 9개)를 넘지 않으므로 스냅샷의 상한이 지켜집니다. 버린 무기는 다른 바닥의 무기와 같은 규칙으로 누구나 줍습니다. Tick이 시작될 때 살아 있고 자리에 있고 하고 있는 일(부활, 수리, 채집, 건설, 상자 열기, 밀려남)이 없는 플레이어만 버릴 수 있습니다. 버리는 플레이어는 그 Tick에 새 일을 시작하지 않으므로, 같은 Tick에 `G`와 `F`나 `B`를 함께 누르면 버리기만 하고 부활, 수리, 채집, 상자 열기, 줍기, 건설이 시작되지 않습니다. 그래서 버린 무기를 곧바로 다시 줍지 않으며, `F`나 `B`를 누르고 있으면 다음 Tick에 시작됩니다. 버릴 수 없을 때(무기가 하나뿐일 때, 야영지와 결과 화면)의 `G`는 `F`와 `B`를 막지 않습니다. 이미 하고 있는 일이 있는 플레이어의 `G`는 아무 일도 하지 않고, 그 일이 이 Tick에 끝나더라도 같습니다. 같은 Tick에 `Q`를 함께 누르면 바꾸기 전에 든 무기를 버리고, `Q`는 바꿀 무기가 없어서 아무 일도 하지 않습니다. 공격의 쿨다운은 무기가 아니라 플레이어에게 있으므로 버린 뒤에도 이어지고(대검을 휘두른 직후에 버리면 새로 든 활은 대검의 쿨다운이 끝날 때까지 쏘지 못합니다), 쿨다운이 없을 때 버린 Tick의 공격은 새로 든 무기로 합니다. 야영지의 바닥에는 무기가 놓이지 않아야 하므로 야영지와 결과 화면에서는 `G`가 아무 일도 하지 않습니다. 버릴 수 있을 때, 곧 서버가 실제로 버려 줄 때만 화면 오른쪽 위의 무기 줄 아래에 `G  DROP`이 나옵니다.
6. 가진 무기는 쓰러져도, 날이 바뀌어도 유지됩니다. 플레이어가 방에서 나가면 가진 무기가 그 자리에 떨어지지만, 시작 무기와 같은 종류의 무기(기본 수치에서는 검)는 떨어지지 않습니다. 입장하는 플레이어가 공짜로 받는 무기이기 때문입니다. 바닥의 무기는 원정이 끝날 때까지 남고, 새 원정에서는 모든 플레이어가 검 하나로 돌아가며 바닥의 무기와 상자가 사라집니다.

### 포탑의 종류

포탑은 다섯 종류이고, 낮에 `E`로 종류를 고른 뒤 `B`로 짓습니다. 종류마다 다른 수치는 `crates/rules/src/tuning.rs`의 포탑 표(`StructureTable`)에서 종류 하나가 한 행입니다. 한 행은 모든 종류가 같은 칸(`StructureTuning`: 최대 HP, 사거리, 건설 비용, 건설 시간, 수리)과 종류마다 다른 동작(`TowerAction`)으로 나뉩니다. 동작은 네 가지입니다. `Shoot`은 쿨다운마다 가장 가까운 몬스터 한 마리에게 피해를 주고, `Afflict`는 쿨다운마다 효과가 걸릴 가장 가까운 몬스터 한 마리에게 피해 없이 효과를 걸고, `Pulse`는 간격마다 범위 안의 모든 몬스터에게 피해 없이 효과를 걸고, `Aura`는 범위 안에 있는 살아 있는 플레이어가 버프를 가지게 합니다.

| 종류 | 동작 | 사거리 | 비용 | 주기 | 효과 | 화면의 색 |
|---|---|---|---|---|---|---|
| 감시탑 | `Shoot` | 6타일 | 10 | 쿨다운 0.8초 | 피해 15 | 파랑 |
| 감속 포탑 | `Pulse` | 4타일 | 15 | 0.5초마다 | 감속 비율 0.7을 1.0초 동안 | 하늘색 |
| 스턴 포탑 | `Afflict` | 5타일 | 20 | 쿨다운 2.0초 | 스턴 0.8초 | 흰색 |
| 공격 속도 포탑 | `Aura` | 3타일 | 15 | Tick마다 | 공격 속도 버프(`HASTE`) 2.0초 | 장미색 |
| 이동 속도 포탑 | `Aura` | 3타일 | 15 | Tick마다 | 이동 속도 버프(`SWIFT`) 2.0초 | 연두색 |

모든 종류의 최대 HP는 300, 건설 시간은 3초이고 수리의 수치도 같습니다. 포탑의 상한(40개)은 종류를 합친 수입니다. 이 표의 수치는 기본값이고 `Tuning`으로 바꿀 수 있습니다.

- 쿨다운은 Tick마다 줄고, 대상이 있어서 포탑이 동작했을 때만 다시 채워집니다. 대상이 없으면 포탑은 아무것도 쓰지 않습니다. 그래서 쿨다운이 끝난 포탑은 대상이 들어오는 Tick에 곧바로 동작하고, 쿨다운이 남아 있는 포탑은 쿨다운이 끝난 Tick에 동작합니다. 스턴 포탑에게 대상은 스턴이 걸릴 수 있는 몬스터입니다. 스턴이 걸려 있거나 면역 중인 몬스터는 대상이 아닙니다.
- 같은 Tick에 스턴 포탑이 둘 이상이면 서로 다른 몬스터를 고릅니다. 포탑은 번호 순서로 고르고, 앞선 포탑이 고른 몬스터는 뒤의 포탑이 고르지 않습니다.
- 감속 포탑은 범위에 몬스터가 있으면 0.5초마다 범위 안의 모든 몬스터에게 감속을 겁니다. 범위를 나가면 남은 감속 시간(최대 1초)이 지난 뒤에 원래 속도로 돌아갑니다. 펄스의 간격은 포탑마다 하나이므로, 두 펄스 사이에 범위에 들어온 몬스터는 다음 펄스까지 최대 0.5초 동안 원래 속도로 걷습니다. 마지막 펄스에서 0.5초가 지난 포탑은 몬스터가 들어온 Tick에 곧바로 펄스를 걸고, 효과는 포탑이 동작한 뒤에 걸리므로 그 몬스터는 첫 Tick(50ms)만 원래 속도로 걷습니다. 더 센 감속(석궁의 0.5)이 걸려 있던 몬스터는 그 감속이 끝난 뒤 다음 펄스까지 최대 0.5초 동안 원래 속도로 걷습니다.
- 효과를 거는 포탑의 효과는 피해 목록(`Hit`)이 아니라 효과 목록(`Affliction`)에 모였다가 `World::apply_hits` 뒤에 걸립니다. 그래서 피해와 처치 기록이 생기지 않고, 효과를 받는 규칙은 무기의 효과와 같습니다. 센 효과가 걸려 있으면 약한 효과는 버려지므로, 석궁의 감속 비율 0.5가 걸린 몬스터에게 감속 포탑의 0.7은 걸리지 않습니다.
- 버프 포탑(`Aura`)은 `towers_act`가 아니라 Tick의 끝에서 `hold_auras`가 동작시킵니다. 서 있는 버프 포탑마다 범위(포탑의 중심에서 플레이어의 중심까지 잰 3타일) 안에 있는 살아 있는 플레이어에게 Tick마다 버프를 주므로, 범위 안에 있는 동안 버프가 끊기지 않고 범위를 나가면 정확히 2초 분량의 Tick 동안 남습니다. 같은 종류의 포탑 둘의 범위가 겹쳐도 버프의 세기는 하나이고, 이미 가진 버프가 2초보다 길면 줄지 않습니다. 짓는 중인 포탑은 버프를 주지 않고, 부서진 포탑은 모음에서 지워지므로 주지 않습니다. 쓰러졌거나 사망한 플레이어는 받지 않고, 자리를 비운 플레이어는 범위 안에 있으면 받습니다.
- `Tuning::validate`는 사거리가 유한하지 않거나 0 이하인 포탑, 건설 비용이 0인 포탑, 쿨다운이 음수인 `Shoot`, 쿨다운이 0 이하인 `Afflict`, 간격이 0 이하인 `Pulse`, 출혈을 거는 `Afflict`와 `Pulse`, 스턴을 거는 `Pulse`, 효과의 시간보다 간격이 긴 `Pulse`, 길이가 유한하지 않거나 0 이하인 버프를 주는 `Aura`를 거절합니다.

### 몬스터에 걸리는 효과

무기가 몬스터를 맞히면 그 무기의 행(`on_hit`)에 적힌 효과가 맞은 몬스터에게 걸립니다. 부채꼴 공격은 안에 든 몬스터마다, 탄환은 맞힌 몬스터마다, 소총은 선이 맞힌 몬스터에게 효과를 겁니다. 효과를 거는 곳은 서버뿐이고, 같은 Tick에 죽은 몬스터에게는 걸리지 않습니다. 효과는 몬스터가 가진 상태이므로 몬스터가 사라지면 함께 사라집니다.

| 효과 | 걸린 몬스터에게 일어나는 일 | 같은 효과를 다시 받으면 |
|---|---|---|
| 감속 | 스스로 걷는 속도에 정해진 비율(기본 0.5)을 곱합니다. 공격의 쿨다운과 닿는 거리는 그대로입니다. | 비율이 작은 쪽이 남습니다. 비율이 같으면 남은 시간이 긴 쪽이 남고, 그것도 같으면 새 감속이 남습니다. 새 감속이 남으면 비율과 시간이 새 값으로 바뀝니다. |
| 출혈 | 걸린 지 1초 뒤부터 1초마다 정해진 피해를 입고, 시간이 끝나는 Tick의 피해까지 입습니다(3초짜리는 세 번). | 한 번의 피해가 큰 쪽이 남습니다. 피해가 같으면 남은 시간이 긴 쪽이 남고, 그것도 같으면 새 출혈이 남습니다. 새 출혈이 남으면 시간과 피해량과 거는 쪽이 새 값으로 바뀌고, 피해가 나는 간격은 끊기지 않고 이어집니다. |
| 스턴 | 정해진 시간 동안 걷지도 공격하지도 않습니다. 공격의 쿨다운은 계속 줄고, 겹친 몬스터에게서 밀려나는 것은 그대로입니다. | 걸려 있는 동안과 끝난 뒤 2초 동안(면역)에는 걸리지 않습니다. 면역 중에도 감속과 출혈은 걸립니다. |

보스에게는 효과가 일부 다르게 걸립니다(아래 「보스」의 저항). 서로 다른 효과는 함께 걸리고, 같은 효과를 다시 받아도 세기는 겹치지 않습니다. 약한 효과는 센 효과가 걸려 있는 동안 버려지고 따로 기억하지 않으므로, 센 효과가 끝난 뒤에도 걸리지 않습니다. 그래서 창의 출혈(6)이 걸린 몬스터를 검(출혈 5)으로 쳐도 창의 출혈이 남고, 창의 출혈이 끝난 뒤에 다시 쳐야 검의 출혈이 걸립니다. 출혈의 피해는 보통 피해와 같은 곳(`World::apply_hits`)을 지나므로, 그 피해로 몬스터가 죽으면 처치는 칸에 남은 출혈을 건 쪽의 것입니다. 건 쪽이 플레이어이면 그 플레이어의 `KILLS`에 더하고, 이미 방을 나갔으면 셀 사람이 없습니다. 한 Tick에서 몬스터가 먼저 행동하고, 효과의 시간이 한 Tick 줄고, 피해가 적용된 뒤에 이번 Tick에 맞은 몬스터에게 새 효과가 걸립니다. 그래서 새로 걸린 효과는 다음 Tick의 행동부터 몬스터를 바꾸고, `secs`초짜리 효과는 정확히 `secs`초 분량의 Tick 동안 몬스터의 행동을 바꿉니다.

효과의 수치는 무기 표의 `on_hit`과 `EffectTuning`(출혈의 간격 1초, 스턴 뒤의 면역 2초)에 있습니다. 포탑의 사격(`ShootTuning`)에도 같은 칸이 있고 감시탑은 기본값이 비어 있으며, 칸을 채우면 감시탑의 사격도 효과를 겁니다. `Tuning::validate`는 감속의 비율이 0 이하이거나 1보다 큰 값, 0 이하의 시간, 간격보다 짧은 출혈, 0인 출혈 피해, 0인 간격과 면역을 무기 표와 포탑의 동작에서 모두 거절합니다.

화면에서 효과에 걸린 몬스터와 허수아비의 몸통은 효과의 색입니다(`crates/client/src/config.rs`의 `EFFECT_STUN`, `EFFECT_SLOW`, `EFFECT_BLEED`). 스턴은 흰색, 감속은 하늘색, 출혈은 어두운 자주색이고, 효과가 함께 걸려 있으면 스턴, 감속, 출혈의 순서로 앞선 하나만 보입니다. 스턴이 끝난 뒤의 면역은 보이지 않습니다. 스냅샷에서 효과가 사라지면 몬스터는 원래 색으로 돌아옵니다. 서버는 걸려 있는 효과만 스냅샷에 싣고 남은 시간은 싣지 않으므로, 화면은 효과가 걸려 있는지만 압니다.

스냅샷에서 몬스터 하나는 종류와 효과를 한 바이트에 담습니다(`crates/protocol/src/monster_status.rs`). 아래 네 비트가 종류의 순서이고, 그 위의 비트 하나씩이 스턴, 감속, 출혈이므로, 효과가 걸려도 몬스터 하나는 효과가 없을 때와 같은 9바이트입니다. 몬스터 종류(지금은 기본 몬스터, 허수아비, 보스, 돌격병, 파괴병의 다섯)가 16개를 넘으면 빌드가 깨지고, 그때는 이 파일의 배치를 바꿉니다. 새 종류는 순서 번호가 뒤에 붙으므로 이미 있는 종류의 바이트는 바뀌지 않습니다.

### 플레이어가 받는 버프

플레이어는 시간이 지나면 끝나는 버프를 받을 수 있습니다. 버프는 두 가지이고, 서로 다른 버프는 함께 걸립니다.

| 버프 | 화면의 이름 | 받은 플레이어에게 일어나는 일 |
|---|---|---|
| 공격 속도 | `HASTE` | 공격의 쿨다운에 정해진 비율(기본 0.7)을 곱합니다. 검의 쿨다운 0.5초(10 Tick)는 0.35초(7 Tick)가 됩니다. 곱한 값을 Tick 단위로 반올림하므로 실제 비율은 무기마다 조금 다릅니다(활은 8 Tick이 6 Tick, 창은 12 Tick이 8 Tick, 석궁은 18 Tick이 13 Tick). |
| 이동 속도 | `SWIFT` | 걷는 속도에 정해진 비율(기본 1.3)을 곱하고, 달리는 중이면 달리기의 배율(1.6)에도 곱합니다. 걷는 속도 4는 5.2가 되고, 달리면서 받으면 한 Tick에 0.416타일을 갑니다. |

같은 버프를 다시 받으면 남은 시간이 긴 쪽이 남고(같으면 새 버프가 남습니다), 짧은 버프가 긴 버프를 줄이지 않습니다. 세기는 겹치지 않습니다. 세기는 `EffectTuning`(`haste_cooldown_factor`, `swift_speed_factor`)에 있고, 길이는 버프 포탑의 행(`AuraTuning`)이 정합니다. 버프는 살아 있는 플레이어(`Life::Alive`)만 가지므로 플레이어가 쓰러지면 없어지고, 부활한 플레이어는 쓰러지기 전의 버프를 이어받지 않습니다(버프 포탑의 범위 안에서 부활하면 부활한 Tick의 끝에 다시 받습니다). 새 원정을 시작하거나 야영지로 돌아온 플레이어는 버프 없이 시작합니다. 낮이 시작될 때 살아 있던 플레이어의 버프는 이어집니다. 버프의 시간은 자리를 비운 플레이어와 야영지에서도 흐르고, 세계가 멈추는 결과 화면에서는 멈춥니다.

버프를 거는 길은 `Player::grant` 하나이고, 크레이트 밖에 공개하지 않습니다. 이 함수를 부르는 곳은 버프 포탑(`structures::hold_auras`)뿐이므로, 버프 포탑이 없으면 아무도 버프를 받지 않습니다(`crates/server/tests/buffs.rs`가 기본 서버에서 야영지와 첫날과 첫 밤을 지나는 동안의 모든 스냅샷에 버프가 없음을 확인합니다. 이 시험의 두 사람은 `E`를 누르지 않으므로 감시탑만 짓습니다). 규칙 테스트는 버프의 규칙을 버프 포탑 없이 시험할 때 `Scenario::grant`로 버프를 줍니다.

스냅샷에서는 살아 있는 플레이어마다 `WireLife::Alive`의 `buffs`(`WireBuffs`)에 두 버프가 걸려 있는지를 불리언 둘로 싣고, 남은 시간은 싣지 않습니다. 모든 클라이언트가 받지만 화면은 내 버프의 이름만 오른쪽 위의 무기 줄 아래에 보여 줍니다(`HASTE`, `SWIFT`, 둘 다 있으면 `HASTE  SWIFT`). 프로토콜의 버전은 19입니다.

### 보스

마지막 밤(기본 수치에서는 셋째 밤)의 마지막 무리를 처치하면 보스가 하나 나타납니다. 보스를 쓰러뜨려야 원정이 성공하고, 그동안 마차의 HP가 0이 되거나 모든 플레이어가 쓰러지거나 사망하면 원정은 실패합니다. 보스가 없는 수치표(`NightTuning::finale`이 `Finale::LastWave`)에서는 마지막 무리를 처치하는 순간 원정이 성공합니다. 부하 시험(`--stress`)이 이 수치표를 씁니다. 보스의 수치는 `crates/rules/src/tuning.rs`의 `BossTuning`과 몬스터 종류표의 `boss` 행에 있습니다.

1. 마지막 무리를 처치하면 경고가 5초(`warning_secs`) 이어집니다. 화면 가운데에 `THE BOSS IS COMING  5`가 나오고 오른쪽 위의 시간은 `BOSS IN 5s`입니다. 몬스터는 하나도 없고, 플레이어는 이 시간에 포탑을 짓고 수리하고 부활시킬 수 있습니다.
2. 경고가 끝나면 보스가 나타납니다. 자리는 밤의 무리가 나타나는 여덟 방향 가운데 마지막 무리 다음 순번의 방향이고, 마차에서 18타일 떨어진 곳입니다. 화면 위쪽 가운데에 HP 막대(`BOSS  12000 / 12000`)가 나오고, 보스가 화면 밖에 있으면 화면 가장자리에 `BOSS 17`처럼 내 캐릭터에서 보스까지의 타일 수가 나옵니다.
3. 보스의 HP는 기본 12,000이고 네 명이 있을 때의 크기입니다. 밤이 시작될 때 방에 있는 사람이 네 명보다 적으면 `올림(HP × 인원 / 4)`이 됩니다(한 명이면 3,000). 밤 도중에 들어오거나 나가도 이미 나타난 보스의 HP는 바뀌지 않습니다.
4. 보스는 대상을 향해 걷고, 걷는 시간 3초(`rest_secs`)가 지난 뒤 대상이 8타일(`target_range`) 안에 있으면 행동 하나를 합니다. 행동은 `BossTuning::script`의 순서대로 되풀이하고, 기본은 내려찍기(`Move::Slam`), 돌진(`Move::Charge`), 내려찍기, 졸개 부르기(`Move::Summon`)입니다. 보스는 근접 공격을 하지 않고, 대상 곁(0.5타일)에 이르면 멈춥니다. 행동이 끝나면 걷는 시간이 다시 시작하고, 그 시간이 시작될 때 보스의 HP가 최대 HP의 절반 이하이면 걷는 시간이 2초(`enraged_rest_secs`)로 줄어듭니다. 걷는 시간이 시작된 뒤에 HP가 바뀌어도 이미 정해진 시간은 바뀌지 않습니다.
5. 대상은 Tick마다 다시 정합니다. 보스에게서 8타일 안에 있는 살아 있고 자리에 있는 플레이어 가운데 최근 5초(`threat_secs`) 동안 보스에게 가장 많은 피해를 준 플레이어입니다. 출혈의 피해도 그 출혈을 건 플레이어의 것으로 셉니다. 포탑이 준 피해는 세지 않습니다. 피해의 양이 같으면 이미 대상인 플레이어가 그대로 대상이고, 그렇지 않으면 번호가 작은 플레이어입니다. 그런 플레이어가 없으면 마차입니다. 대상이 된 플레이어의 머리 위에 붉은 삼각형이 나옵니다.
6. 내려찍기는 대상이 서 있던 자리에 반지름 2.5타일의 원을 1.5초(`windup_secs`) 동안 예고하고, 시간이 지나면 원 안의 것에 피해를 줍니다. 플레이어에게 50, 포탑에게 100, 마차에게 60입니다. 화면에서는 붉은 테두리 안에서 원이 안쪽부터 차오르고, 가득 찬 바로 다음 Tick에 피해가 납니다. 원의 자리와 차오르는 정도는 서버가 정해서 스냅샷에 싣고 클라이언트는 계산하지 않으므로, 모든 플레이어가 같은 시각에 같은 원을 봅니다. 예고하는 동안 보스는 서 있고 원은 움직이지 않으므로, 원 밖으로 걸어 나가면 피합니다. 원의 한가운데에서 걸어 나가는 데 0.65초가 걸리므로 원이 나타난 뒤 0.85초까지 늦게 움직여도 피합니다. 플레이어는 중심점이 원 안에 있으면 맞고, 포탑과 마차는 사각형이 원과 조금이라도 겹치면 맞습니다. 쓰러졌거나 사망했거나 자리를 비운 플레이어와 짓는 중인 포탑은 맞지 않습니다. 원이 터지는 Tick에 이미 원 밖으로 나간 플레이어는 맞지 않습니다.
7. 돌진은 대상 쪽으로 뻗는 띠(폭 2타일 `width`)를 1.5초(`windup_secs`) 동안 예고한 뒤, 보스가 띠를 따라 초당 14타일(`speed`)로 달립니다. 보스의 중심은 가장 멀리 10타일(`length`)을 달리고, 띠는 보스의 몸이 덮는 곳까지 보이도록 그보다 반폭(1타일)만큼 깁니다. 예고한 뒤에 띠의 가운데 선 곁에 포탑이 서서 보스가 비켜 가야 하게 되면, 보스는 띠를 벗어나지 않고 그 앞에서 멈춥니다. 띠의 방향은 예고가 시작될 때 한 번 정하고 끝날 때까지 바뀌지 않으므로 대상이 움직여도 띠는 같은 자리에 있습니다. 띠는 지나갈 수 없는 지형, 포탑, 마차, 맵의 끝 앞에서 끊기고, 보스는 거기서 멈추며, 멈춘 자리의 포탑과 마차는 돌진의 피해를 받습니다. 달리는 보스의 몸이 지나가면서 띠 안의 플레이어, 포탑, 마차에 닿으면 대상마다 한 번만 피해를 줍니다. 플레이어에게 40, 포탑에게 100, 마차에게 80입니다. 예고하는 동안 띠 옆으로 1타일 넘게 걸어서 벗어난 플레이어는 맞지 않습니다. 화면에서는 붉은 테두리의 띠가 보스 쪽에서 끝쪽으로 차오르고, 달리는 동안에는 가득 찬 띠가 남습니다.
8. 돌진에 맞은 살아 있는 플레이어는 돌진의 방향으로 3타일(`push_tiles`)을 0.3초(`push_secs`) 동안 밀려납니다. 밀려나는 동안에는 이동, 공격, 건설, 부활, 수리 조작이 듣지 않고, 하던 일은 취소됩니다(건설 중이었다면 낸 자원이 보관함으로 돌아옵니다). 밀려나는 길은 걸을 때와 같은 충돌 규칙을 쓰므로 지나갈 수 없는 지형, 포탑, 마차, 맵의 끝 앞에서 멈추고 그 안으로 들어가지 않습니다. 막혀서 나아가지 못해도 조작이 듣지 않는 시간은 0.3초 그대로입니다. 쓰러진 플레이어와 몬스터와 포탑은 밀려나지 않습니다. 밀려나는 플레이어는 스냅샷의 `WireInteraction::Knocked`로 모두에게 알려지고, 클라이언트는 앞뒤 스냅샷의 위치를 섞어서 그리므로 순간 이동하지 않고 미끄러집니다.
9. 졸개 부르기는 보스가 멈춰서 2초(`roar_secs`) 동안 포효하고, 포효가 끝나면 돌격병(`SummonTuning::kind`, 기본은 `Runner`)이 밤의 무리와 같은 자리(마차에서 18타일)와 같은 간격(0.3초에 한 마리)으로 나타나 마차로 곧장 달려갑니다. 돌격병은 포탑의 피해를 줄여서 받으므로(위의 「몬스터의 종류」) 포탑이 졸개를 모두 처치해 주지 못하고, 플레이어가 마차를 지켜야 합니다. 기본 수는 12마리이고 네 명이 있을 때의 크기이며, 밤이 시작될 때 방에 있는 사람이 네 명보다 적으면 `올림(수 × 인원 / 4)`마리입니다. 부를 때마다 나타나는 방향이 달라지고, 동시에 살아 있는 몬스터의 상한(300마리)을 밤의 무리와 함께 지킵니다. 보스가 쓰러지면 원정이 그 순간 성공으로 끝나고, 아직 나타나지 못한 졸개는 나타나지 않으며 이미 나타난 졸개는 남습니다. 화면에서는 포효하는 동안 보스 둘레에 고리가 퍼집니다.
10. 보스의 몸은 둘입니다. 걷는 몸(반지름 `radius` 0.4타일)은 길 찾기와 충돌과 건설이 보고, 맞는 몸(`hit_radius()`, 반지름 1타일)은 무기와 탄환과 소총의 선과 포탑의 사거리와 화면의 몸통이 봅니다. 그래서 보스는 포탑 사이의 한 칸 폭의 길도 지나가면서, 검은 보스의 중심에서 1타일 떨어진 가장자리까지 닿습니다. 검, 대검, 창의 부채꼴은 보스의 중심이 부채꼴 밖에 있어도 중심에서 맞는 몸의 여유(0.6타일)만큼 떨어진 곳이 부채꼴에 닿으면 맞습니다. 기본 몬스터, 돌격병, 파괴병은 맞는 몸의 여유(`hit_margin`)가 0이므로 달라지지 않습니다. 좁은 곳에서 보스의 몸통이 벽이나 포탑과 겹쳐 보일 수 있습니다.
11. 보스는 저항(`Resist`)을 가집니다. 포탑이 주는 피해는 10%(올림)만 들어가고(감시탑의 사격 15는 2), 스턴에 걸리지 않고, 감속은 절반만 걸립니다(0.7이 0.85가 됩니다). 출혈은 그대로 걸립니다. 스턴 포탑은 스턴에 걸리지 않는 보스를 고르지 않고 쿨다운도 쓰지 않으며, 사거리 안에 스턴에 걸리는 다른 몬스터가 있으면 보스보다 멀어도 그 몬스터를 고릅니다. 플레이어가 주는 피해는 줄지 않습니다. 이 저항 때문에 포탑이 보스를 대신 잡아 주지 못하고 플레이어가 싸워야 합니다.

스냅샷에서는 경고가 `WireNightStep::Warning { secs_left }`로, 보스와 싸우는 동안이 `WireNightStep::Boss(WireBoss)`로 실립니다. `WireBoss`는 보스의 최대 HP(`max_hp`)와 대상(`WireAim`: 플레이어 번호나 마차)과 하는 일(`WireBossAct`)을 담습니다. 하는 일은 걷는 중(`Walking`), 내려찍기의 원의 중심과 진행도(`Slam`), 돌진의 띠의 시작과 끝과 진행도(`Charge`), 달리는 중인 띠의 시작과 끝(`Dash`), 포효의 진행도(`Roar`) 가운데 하나입니다. 보스의 몸은 몬스터 목록의 한 항목(`WireMonsterKind::Boss`)입니다. 원의 반지름과 띠의 폭은 입장 안내(`WorldInfo::boss`의 `BossInfo`)에서 읽습니다. 보스가 쓰러지는 Tick에 `NightStep::Boss`가 끝나므로, 클라이언트는 보스의 단계에 보스의 몸이 없는 스냅샷을 보지 못합니다.

|---|---|

| `Shift`를 누르고 있기 | 움직이는 동안 걷는 속도의 1.6배로 달립니다. 달리는 동안 화면 왼쪽 위 HP 아래의 `STAMINA` 막대가 줄고, 키를 떼면 막대가 다시 찹니다. 왼쪽과 오른쪽 `Shift`가 같습니다. |

| `Q` | 가진 두 칸의 무기를 서로 바꿉니다. 한 칸만 차 있으면 아무것도 바뀌지 않습니다. 누르고 있어도 한 번만 바뀝니다. 화면 오른쪽 위의 `WEAPON  [SWORD]  -  [Q]`나 `WEAPON  [BOW]  SWORD  [Q]`가 가진 무기를 알려 주고, 대괄호가 든 무기입니다. 부활, 수리, 채집, 건설, 상자 열기 중이거나 쓰러졌을 때는 바뀌지 않습니다. |
| `G` | 든 무기를 선 자리의 바닥에 버리고 다른 칸의 무기를 듭니다. 무기가 하나뿐이면 맨손이 되므로 아무 일도 일어나지 않습니다. 시작 무기와 같은 종류(검)는 바닥에 놓이지 않고 사라집니다. 누르고 있어도 한 번만 버리고, 같은 Tick에 `F`나 `B`를 함께 누르면 버리기만 하고 그 Tick에는 새 일을 시작하지 않으며, `Q`를 함께 누르면 바꾸기 전에 든 무기를 버립니다. 원정 중에 Tick이 시작될 때 살아 있고 부활, 수리, 채집, 건설, 상자 열기, 밀려남 중이 아닐 때만 버려지고, 쓰러졌거나 자리를 비웠을 때와 야영지와 결과 화면에서는 아무 일도 하지 않습니다. 버릴 수 있을 때 화면 오른쪽 위의 무기 줄 아래에 `G  DROP`이 나옵니다. |
| `E` | 지을 포탑의 종류를 다음 것으로 바꿉니다. 종류의 순서는 감시탑, 감속 포탑, 스턴 포탑, 공격 속도 포탑, 이동 속도 포탑이고 마지막 다음은 처음입니다. 누르고 있어도 한 번만 바뀝니다. 고른 종류는 플레이어마다 따로이고 새 원정과 새 입장은 감시탑에서 시작하므로, `E`를 누르지 않으면 `B`는 감시탑을 짓습니다. 원정 중에 살아 있는 플레이어만 바꿀 수 있고, 야영지에서는 아무것도 바뀌지 않습니다. 이미 짓고 있는 포탑의 종류는 바뀌지 않고, 같은 Tick에 `E`와 `B`를 누르면 바뀐 종류를 짓습니다. 화면 오른쪽 위의 무기 줄 아래에 `BUILD  SLOW TOWER  15`처럼 고른 종류의 이름과 비용이 나오고, 원정 중에 내 것만 보입니다. |
| `B`를 누르고 있기 | 바라보는 쪽의 이웃한 타일에 고른 종류의 포탑을 짓습니다(비용은 감시탑 10, 감속 포탑 15, 스턴 포탑 20, 공격 속도 포탑 15, 이동 속도 포탑 15이고 건설 시간은 모두 3초). 키를 누르기 전에도 그 타일이 밝은 테두리로 보입니다. 포탑의 범위는 옅은 원으로 두 때에 보입니다. `E`로 종류를 바꾼 뒤 2초 동안에는 그 타일에 고른 종류의 범위가 보이고, 짓는 동안에는 짓고 있는 포탑의 자리에 그 포탑의 종류의 범위가 보입니다. 마차에서 10타일 안이어야 하고, 마차로 가는 길을 막을 수 없습니다. 세울 수 없으면 그 타일을 빨간 테두리로 표시하고 이유를 화면 아래에 알립니다. 짓는 동안 이동과 공격을 할 수 없고, 짓는 중에 `B`를 떼거나 쓰러지면 건설이 취소되고 비용을 돌려받습니다. |
| `F`를 누르고 있기 | 가까이 쓰러진 동료가 있으면 부활시키고(5초), 없으면 가까이 있는 손상된 포탑을 수리하고(1.5초에 HP 30, 자원 1), 그것도 없으면 가까이 있는 손상된 마차를 수리하고(1.5초에 HP 30, 자원 1), 그것도 없으면 가까이 있는 채집 지점에서 자원을 0.5초에 1씩 채집합니다(최대 10). 그것도 없으면 가까이 있는 무기 상자를 1.5초 걸려 엽니다(피해를 받으면 처음으로 돌아갑니다). 그동안 이동과 공격을 할 수 없습니다. 채집한 자원은 마차 곁(1.5타일 안)에 가면 자동으로 보관함에 들어가고, 쓰러지거나 스스로 방을 나가면 그 자리에 떨어지며, 살아 있는 플레이어가 가까이 가면 자동으로 줍습니다. |
| `R` | 야영지에서 준비를 켜고 끕니다. 누르고 있어도 한 번만 바뀝니다. 화면 오른쪽 위에 `R  READY`(준비하지 않았을 때)나 `R  CANCEL READY`(준비했을 때)가 나옵니다. 야영지가 아닐 때는 아무 일도 하지 않습니다. |
| `Enter` | 결과 화면에서 확인합니다. 한 번 확인하면 끌 수 없고, 누르고 있어도 한 번만 반영됩니다. 결과 화면이 아닐 때는 아무 일도 하지 않습니다. 숫자 패드의 `Enter`도 같은 키입니다. 나가기 확인 창이 떠 있는 동안에는 방을 나가는 키이므로 확인하지 않고, 같은 프레임에 `Esc`가 창을 닫아도 그 프레임의 `Enter`는 확인하지 않습니다. |
| `Esc` | 방 안에서 나가기 확인 창(`LEAVE THE ROOM?`)을 열고, 창이 떠 있으면 닫습니다. 창이 떠 있는 동안에도 게임은 멈추지 않습니다. 창에서 `Enter`(숫자 패드의 `Enter` 포함)를 누르면 방을 나갑니다. 방에 들어가기 전에는 확인 없이 곧바로 시작 화면으로 돌아옵니다. |
| `F`를 누른 순간 | 바닥의 무기나 야영지의 진열대 곁(1.75타일 안)에서 누르면 그 무기를 줍습니다. 빈 칸이 있으면 빈 칸에 들어가고, 없으면 든 무기와 바뀌어서 이전에 든 무기가 그 자리에 떨어집니다. 다만 이전에 든 무기가 시작 무기와 같은 종류(검)이면 바닥에 떨어지지 않고 사라집니다. 누르고 있어도 한 번만 줍고, 위의 부활, 수리, 채집, 상자 열기를 할 수 있는 곳에서는 줍지 않습니다. 줍을 수 있는 무기 곁에 서면 `F  TAKE SPEAR` 같은 안내가 나오고, 열 수 있는 상자 곁에서는 `F  OPEN CHEST`가 나옵니다. 상자를 여는 동안에는 `OPENING CHEST` 막대가 진행을 보여 줍니다. |

수리는 한 번(1.5초)마다 보관함에서 자원 1을 내고, 마지막 한 번이 HP를 30보다 적게 회복시켜도 같습니다. HP가 거의 없는 포탑을 가득 수리하면 자원 10이 들고(종류와 관계없이 같고, 감시탑의 건설 비용과 같습니다), 마차는 17이 듭니다. 여럿이 같은 Tick에 수리하면 번호가 작은 플레이어부터 내고, 보관함이 모자라면 나중 플레이어의 그 수리는 회복시키지 못합니다. 보관함이 비용을 낼 수 없는 동안에도 플레이어는 그 수리를 계속하고 채집으로 바뀌지 않으며, 화면 아래에 `CANNOT REPAIR: NOT ENOUGH IN THE STASH`가 나옵니다. 자원이 생기면 이 문구가 사라지고 다음 수리부터 회복시킵니다. 마차 곁의 회복은 자원을 쓰지 않습니다.

달리기 게이지는 가득 찬 막대로 4초를 달릴 수 있고, 빈 막대가 가득 차는 데 10초가 걸립니다. 서버는 이 게이지를 정수 점수로 세고 스냅샷에는 0에서 100의 백분율 하나만 싣습니다. 달리는 Tick에는 막대가 줄고, `Shift`를 뗀 Tick에는 움직이든 서 있든 막대가 찹니다. `Shift`를 누르고 있지만 달리지 못하는 동안(막대가 비었거나 제자리에 서 있을 때)에는 막대가 줄지도 차지도 않으므로, 빈 막대에서 `Shift`를 누르고 있으면 달리기와 걷기가 번갈아 나오지 않고 걷기만 합니다. 부활, 수리, 채집, 건설을 하는 동안과 쓰러졌을 때는 달릴 수 없습니다. 막대는 입장할 때, 낮이 시작될 때, 새 원정이 시작될 때, 부활한 직후에 가득 찹니다.

카메라는 내 캐릭터를 따라갑니다. 마차가 화면 밖에 있으면 마차가 있는 쪽의 화면 가장자리에 `WAGON 23`처럼 내 캐릭터에서 마차까지의 타일 수가 나옵니다.

## 검사하기

CI(`.github/workflows/ci.yml`)는 `main`에 푸시할 때와 풀 리퀘스트마다 Ubuntu 24.04에서 다음 명령을 모두 실행합니다. 저장소 폴더에서 같은 명령을 실행해서 로컬에서도 확인할 수 있습니다.

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy -p caravan_client --target wasm32-unknown-unknown -- -D warnings
cargo test --workspace
sh scripts/check-deps.sh
cd crates/client && trunk build
```

  - 스냅샷 하나는 `snapshot_size.rs`의 상황(몬스터 300마리, 포탑 40개, 플레이어 4명, 바닥의 무기 4개)에서 3,389바이트입니다. 포탑은 다섯 종류가 번갈아 서 있습니다. 포탑 하나는 종류 1바이트를 싣고, 최대 HP와 사거리와 비용은 입장 안내의 종류표(`WorldInfo::structure_kinds`)에 한 번만 있습니다. 플레이어는 고른 종류를 1바이트로 싣습니다. 소총의 사격 선이 있는 플레이어 넷과 바닥의 무기 아홉 개를 더한 가장 나쁜 경우는 3,435바이트이고, 여기에 탄환 8개를 더하면 3,491바이트입니다(한도 3,600바이트). 플레이어 한 명이 있는 `load.rs`의 실제 규칙 상태에서는 3,209바이트입니다. 몬스터 300마리가 모두 세 효과에 걸려 있어도 크기는 같습니다. 효과가 종류의 바이트에 담기므로 몬스터 하나는 그대로 9바이트이고, 종류가 기본 몬스터, 돌격병, 파괴병, 허수아비, 보스 가운데 무엇이든 같습니다(`monsters_of_every_kind_cost_the_same_nine_bytes_as_grunts`). 살아 있는 플레이어마다 버프가 2바이트이고 버프가 있든 없든 같습니다. 플레이어 넷이 모두 살아 있고 두 버프를 가진 경우는 가장 나쁜 경우보다 1바이트 큰 3,492바이트이고, 몬스터 번호가 16384 이상이면 3,730바이트입니다(한도 3,950바이트). 보스가 있는 밤의 스냅샷은 같은 상황에서 보스가 걷는 중이면 5바이트(3,394바이트), 내려찍기를 예고하는 중이면 13바이트(3,402바이트), 돌진을 예고하는 중이면 17바이트(3,406바이트), 띠를 따라 달리는 중이면 13바이트(3,402바이트), 포효하는 중이면 9바이트(3,398바이트) 큽니다. 보스의 몸은 몬스터 목록의 한 항목이고 HP가 2바이트여서 10바이트이며, 밤의 단계에 보스의 상태(최대 HP, 대상, 하는 일)가 더해집니다. 가장 나쁜 경우(플레이어 넷이 모두 살아 있고 두 버프를 가지고, 소총의 사격 선 넷, 바닥의 무기 아홉, 탄환 8개)에 보스의 돌진 예고가 더해지면 3,509바이트이고(한도 3,600바이트), 소총의 사격 선과 바닥의 무기와 탄환을 뺀 채 몬스터 번호가 16384 이상이면 3,747바이트입니다. 몬스터 번호가 16384 이상이면서 이 모든 것이 겹치고, 플레이어 넷이 모두 돌진에 밀려나는 중이고, 플레이어의 번호와 대상의 번호와 보스의 HP까지 큰 경우는 3,873바이트입니다(한도 3,950바이트).
  - 전용 서버와 부하 시험용 클라이언트 하나를 실제 소켓으로 150초 실행했을 때(`--stress --waves 100,200,300 --stats`) 몬스터는 최대 267마리였고 가장 큰 스냅샷은 3,064바이트였습니다. 1초 구간의 Tick 평균은 중앙값 0.24ms, 가장 큰 구간이 0.50ms였고, 구간 안의 가장 느린 Tick은 1.43ms였습니다. 이 실행의 플레이어는 검과 활을 들고 있어서 석궁과 소총은 실제 소켓에서 쏘지 않았습니다.

## Tick 하나의 처리 순서

`Sim::step`(`crates/rules/src/sim.rs`)은 방의 단계(`Stage`)에 따라 다른 일을 합니다. 결과 화면(`Sim::wait_for_confirmations`)에서는 세계가 멈추고, 확인 키(`Enter`)와 결과를 보여 주는 남은 시간만 봅니다. 야영지의 Tick(`Sim::practice`)은 준비 키(`R`)와 카운트다운을 먼저 정하고, 원정이 시작되지 않으면 아래 3번, 4번, 7번, 8번(`move_players`만), 10번, 11번만 부릅니다. 이때 건설은 거절되고, `E`는 지을 종류를 바꾸지 않고(4번의 `cycle_kinds`는 원정의 Tick만 부릅니다), 몬스터(허수아비)와 포탑은 행동하지 않으며, 10번과 11번이 결정한 피해는 적용하지 않고 허수아비가 맞은 기록(`Camp::note_strikes`)만 남깁니다. 다만 10번과 11번이 실은 효과는 허수아비에게 걸고(`effect::apply_debuffs`), 걸려 있는 효과와 플레이어가 받은 버프의 시간은 원정과 같이 흐르며(`effect::advance_effects`), 이때 나는 출혈의 피해는 버립니다. 원정 중의 Tick(`Sim::simulate`)은 다음 순서로 상태를 바꿉니다. 모든 공격과 피해는 같은 상태를 읽고 결정한 뒤 16번에서 한꺼번에 적용합니다.

1. `advance_phase`가 낮, 밤, 새벽의 카운트다운을 줄이고, 때가 되면 밤이나 낮을 시작하거나 몬스터를 한 마리 등장시킵니다. 낮이 시작되면 상자를 놓고 상자마다 몬스터를 세우고(`loot::start_day`), 밤이 시작되면 열지 않은 상자를 치웁니다(`loot::clear_chests`). 경고가 끝나는 Tick에는 보스를 등장시키고(`World::spawn_boss`), 보스의 단계에서는 보스가 부른 졸개를 한 마리씩 등장시킵니다(`boss::spawn_called`).
2. `Paths::sync`가 마차와 포탑으로 가는 이동 경로를 필요하면 다시 만듭니다.
3. `MonsterGrid::rebuild`가 몬스터의 위치를 격자에 넣습니다.
4. `build::cycle_kinds`가 `E`를 누른 살아 있는 플레이어의 지을 포탑의 종류를 다음 것으로 바꾸고, 이어서 `update_interactions`가 `F`와 `B`와 `G`를 처리합니다. 같은 Tick에 누른 `B`는 바뀐 종류를 짓습니다. 먼저 `G`를 누른 플레이어 가운데 Tick이 시작될 때 살아 있고 자리에 있고 하고 있는 일이 없고 다른 칸에 무기가 있는 플레이어(`loot::drops_this_tick`, 야영지에서는 아무도 해당하지 않습니다)를 정합니다. 이 플레이어는 이 Tick에 새 일을 고르지 않으므로 아래의 부활, 수리, 채집, 상자 열기, 줍기, 건설을 시작하지 않고, 다른 일이 모두 정해진 뒤에 든 무기를 버립니다(`loot::apply_drops`, 플레이어 번호 순서). 버릴 수 없는 플레이어의 `G`는 아무 일도 하지 않고 `F`와 `B`를 막지 않습니다. 부활, 포탑 수리, 마차 수리, 채집, 상자 열기의 순서로 대상을 고르고, 수리의 비용을 보관함에서 내고(플레이어 번호 순서), 건설의 시작과 거절을 판정합니다. 부활, 수리, 채집 다음에 상자 열기가 오고, `F`를 누른 순간에 더 높은 순위의 대상이 없으면 가장 가까운 바닥의 무기나 야영지의 진열대의 무기를 줍습니다(플레이어 번호 순서). 거리가 같으면 바닥의 무기가 먼저이고, 진열대에서는 이미 가진 종류를 집지 않습니다.
5. `advance_construction`이 건설을 진행하고 끝내거나 취소합니다.
6. 건설이 이동 경로를 바꿨을 수 있으므로 `Paths::sync`를 한 번 더 부릅니다.
7. `update_sprint`가 플레이어마다 이번 Tick에 달리는지 정하고 달리기 게이지를 줄이거나 채웁니다. 4번과 5번이 정한 하고 있는 일을 읽으므로 그 뒤에 부릅니다.
8. `slide_knocked`가 돌진에 맞아 밀려나는 플레이어를 한 걸음 옮깁니다. 걷는 것과 같은 충돌 규칙을 쓰고, 막혀서 나아가지 못해도 밀려나는 시간은 그대로 셉니다. 이어서 `move_players`가 플레이어를 움직입니다. 밀려나는 플레이어는 하고 있는 일이 있어서 이동 속도가 0이므로 `move_players`는 그 플레이어를 움직이지 않습니다. 한 Tick의 이동이 몸의 반지름 이상이면 반지름보다 짧은 같은 길이의 걸음으로 나누어 옮기므로, 이동 속도가 빨라도 얇은 벽을 건너뛰지 않습니다. 걸음의 수에 끝이 있도록, 가장 빠른 플레이어가 한 Tick에 몸의 반지름의 64배 이상을 움직이는 수치는 `Tuning::validate`가 거절합니다. 걷기도 달리기도 걸음이 하나이고, 달리면서 이동 속도 버프를 받으면 걸음이 둘입니다.
9. `deposit_and_pickup`이 마차 곁의 플레이어가 든 자원을 보관함에 넣고(넣은 양은 그 플레이어의 기록에 더합니다), 땅에 떨어진 자원을 줍게 합니다.
10. `use_weapons`가 `Q`를 누른 플레이어의 무기를 바꾸고, 플레이어의 공격을 결정하고, 들고 있는 무기의 전달 방식에 따라 처리합니다. 검, 대검, 창은 부채꼴 안의 몬스터를 맞히고, 활과 석궁은 탄환을 만들고, 소총은 그 자리에서 조준선 위의 처음 닿는 몬스터를 맞히고 사격 선이 끝난 자리를 플레이어의 마지막 공격에 적습니다. 공격의 쿨다운은 `Player::stats`가 돌려주고, 공격 속도 버프가 있으면 그 비율을 곱한 값입니다.
11. `advance_projectiles`가 날아가는 탄환을 한 Tick만큼 움직입니다. 탄환은 이번 Tick에 쏜 것도 움직이고, 지나간 선분에서 닿는 몬스터를 닿는 순서대로 맞힐 수 있는 수(`pierce`)만큼 맞혀서 피해를 결정하고(같은 몬스터는 한 번만 맞힙니다), 막힌 타일이 몬스터보다 가까우면 그 뒤의 몬스터는 맞히지 못하며, 막힌 타일이나 사거리의 끝에서는 피해 없이 사라집니다. 끝난 탄환은 한 Tick 더 남았다가 다음 Tick의 처음에 지워집니다. 결과 화면 동안에는 날던 탄환이 그 자리에 멈추고, 끝난 탄환은 지워집니다.
12. `towers_act`가 서 있는 포탑 가운데 몬스터에게 작용하는 포탑의 동작을 결정합니다. 감시탑은 쿨다운마다 범위 안의 가장 가까운 몬스터를 쏘고, 감속 포탑은 0.5초마다 범위 안의 모든 몬스터에게 감속을 걸기로 정하고, 스턴 포탑은 2초마다 범위 안에서 스턴에 걸릴 수 있는(스턴 중도 면역 중도 아닌) 가장 가까운 몬스터 한 마리에게 스턴을 걸기로 정합니다. 스턴을 걸 몬스터가 없으면 스턴 포탑은 쿨다운을 쓰지 않고, 같은 Tick의 스턴 포탑 둘은 서로 다른 몬스터를 고릅니다. 포탑이 몬스터까지 재는 거리는 그 몬스터의 맞는 몸의 가장자리까지이므로 보스는 일반 몬스터보다 멀리서 사거리에 들고, 스턴 포탑은 스턴에 걸리지 않는 보스를 고르지 않습니다. 피해는 피해 목록에, 피해 없이 거는 효과는 효과 목록(`Affliction`)에 모읍니다.
13. `boss::act`가 보스가 있으면 보스를 한 Tick 진행합니다. 대상을 다시 고르고, 걷는 시간이나 예고의 시간을 한 Tick 줄이고, 걷는 시간이 끝났고 대상이 8타일 안에 있으면 스크립트의 다음 행동(내려찍기, 돌진, 졸개 부르기)을 시작합니다. 예고가 터지는 Tick이면 원 안의 플레이어와 포탑과 마차에 대한 피해를 피해 목록에 더하고, 돌진하는 중이면 보스를 띠를 따라 한 Tick만큼 움직이고(보스의 걷는 몸은 걷는 것과 같은 충돌 규칙을 씁니다), 이번 Tick에 지나간 띠 안의 대상 가운데 아직 맞지 않은 대상의 피해를 피해 목록에 더하고 새로 맞은 플레이어를 밀어내기 목록(`Shove`)에 더합니다. 포효가 끝나는 Tick에는 부를 졸개를 정합니다. 보스가 없거나 마지막 밤의 끝이 보스가 아니면 아무것도 하지 않습니다. 몬스터의 이동(14번) 앞에 있으므로 예고하는 동안 보스는 걷지 않고, 플레이어의 이동(8번)이 끝난 자리에서 예고가 터집니다.
14. `monsters_act`가 몬스터의 이동과 공격을 결정합니다. 낮의 몬스터는 자리를 지키고, 밤의 몬스터는 마차로 향하며 가는 길에 무엇을 쫓는지는 종류의 `prey`가 정합니다(기본 몬스터는 가까운 플레이어나 포탑, 돌격병은 아무것도 쫓지 않고, 파괴병은 플레이어를 쫓지 않고 포탑으로 갑니다). 몬스터는 이전 Tick까지 걸린 효과로 행동합니다(감속은 걷는 속도에 곱하고, 스턴에 걸린 몬스터는 걷지도 공격하지도 않습니다).
15. `advance_effects`가 몬스터가 가진 효과와 플레이어가 받은 버프의 시간을 한 Tick 줄이고, 이번 Tick에 나는 출혈의 피해를 피해 목록의 끝에 더합니다. 몬스터와 플레이어가 행동한 뒤에 부르므로, 끝나는 효과와 버프는 마지막으로 행동을 바꾼 뒤에 풀립니다.
16. `World::apply_hits`가 이번 Tick의 모든 피해를 적용하고(보스가 맞는 포탑의 피해는 저항으로 줄이고, 플레이어가 보스에게 준 피해는 보스의 대상 고르기에 적습니다), HP가 0이 된 몬스터와 포탑을 지우고, 쓰러진 플레이어가 든 자원을 그 자리에 떨어뜨립니다. 상자를 열던 플레이어가 피해를 받으면 열기가 여기서 취소됩니다. 피해(`Hit`)는 준 쪽(`Source`: 플레이어, 포탑, 몬스터)을 담고, 몬스터의 HP를 0으로 만든 피해가 그 처치의 주인을 정합니다. 플레이어의 처치는 그 플레이어의 기록에, 포탑의 처치는 원정의 포탑 처치 수에 더합니다. 탄환은 쏜 플레이어의 것이고, 쏜 플레이어가 이미 방을 나갔으면 셀 사람이 없습니다. 같은 Tick에 여럿이 같은 몬스터를 맞히면 피해를 결정한 순서(10번, 11번, 12번, 15번)에서 HP를 0으로 만든 피해가 주인입니다. 쓰러진 플레이어의 기록(쓰러진 횟수)도 여기서 더합니다. 몬스터를 지운 뒤에는 `effect::apply_debuffs`가 이번 Tick에 맞은 몬스터 가운데 살아남은 몬스터에게 피해가 싣고 온 효과를 겁니다. 그 직후에 `effect::apply_afflictions`가 12번이 모은 효과를 같은 규칙으로 겁니다. 이 효과는 피해가 아니므로 처치의 주인, 야영지의 맞은 기록, 결과의 기록에 나타나지 않습니다. 이어서 `player::apply_shoves`가 13번이 모은 밀어내기를 적용합니다. 피해를 적용한 뒤에 부르므로 같은 Tick에 쓰러진 플레이어는 밀려나지 않고, 맞은 플레이어가 하던 일은 밀려나는 상태(`Interaction::Knocked`)로 바뀌면서 버려집니다.
17. `recover_near_wagon`이 마차 곁의 살아 있는 플레이어의 HP를 회복합니다. 피해를 적용한 뒤에 부르므로, 같은 Tick의 회복이 쓰러뜨리는 피해를 되돌리지 않습니다.
18. `advance_life_timers`가 부활을 마무리하고(부활시킨 플레이어의 기록에 더합니다) 쓰러진 플레이어의 출혈 시간을 줄입니다.
19. `finish_openings`가 열기를 마친 플레이어의 상자를 열어서 무기를 바닥에 놓습니다. 피해를 적용한 뒤에 부르므로, 열기가 끝나는 Tick에 맞은 플레이어는 열지 못합니다.
20. `hold_auras`가 서 있는 버프 포탑마다 범위 안에 있는 살아 있는 플레이어에게 버프를 줍니다. 15번이 버프의 시간을 줄인 뒤이고 16번이 쓰러짐을, 18번이 부활을 정한 뒤이므로, Tick이 끝났을 때 범위 안의 살아 있는 플레이어는 언제나 버프를 가지고, `secs`초짜리 버프는 범위를 나간 뒤 정확히 `secs`초 분량의 Tick 동안 행동을 바꿉니다. 이 호출을 15번 앞으로 옮기면 나간 뒤의 시간이 한 Tick 짧아집니다.
21. `settle_outcome`이 원정의 성공과 실패, 무리를 모두 처치했는지를 판정합니다. 마지막 밤에서는 보스가 있는 수치표이면 마지막 무리를 모두 처치한 Tick에 경고의 단계로 넘어가고(보스가 없는 수치표이면 그 Tick에 성공입니다), 보스의 단계에서 보스의 몸이 사라지면 성공입니다. 원정이 끝났으면 방이 결과 화면으로 넘어가고, 이때 원정의 요약(성공 여부, 버틴 날, 걸린 Tick, 포탑의 처치)과 방에 있는 플레이어(자리를 비운 플레이어 포함)의 기록이 결과(`Report`)로 한 번 복사됩니다.

## 키 입력 하나가 다른 플레이어의 화면에 그려지기까지

플레이어 A가 `D`를 누르면, 다음 순서를 거쳐 플레이어 B의 화면에서 A의 캐릭터가 움직입니다.

1. `crates/client/src/input.rs`의 `read_controls`가 이번 프레임의 키보드와 마우스 상태를 `Controls`로 읽습니다. 커서의 화면 위치는 지면 위치로 되돌립니다.
2. `crates/client/src/net.rs`의 `send_input`이 `Session::input_due`(`crates/client_core/src/session.rs`)를 부릅니다. `InputSender::poll`(`crates/client_core/src/input.rs`)은 서버 Tick 간격(20 Hz에서 50ms)마다 한 번 `Controls::to_input`으로 순서 번호가 붙은 `InputMsg`를 만들고, 이때 화면 기준의 WASD 방향이 지면의 이동 방향으로 바뀝니다.
3. `WsClient::send`(`crates/ws_client/src/lib.rs`)가 `encode_client`(`crates/protocol/src/codec.rs`)로 메시지를 postcard 바이트로 바꾸고 WebSocket 이진 프레임으로 보냅니다.
4. 서버의 네트워크 스레드에서 `serve_link`(`crates/ws_server/src/lib.rs`)가 프레임을 `decode_client`로 해석하고, 크기가 정해진 채널로 게임 스레드에 넘깁니다.
5. `crates/dedicated/src/main.rs`의 반복이 `GameServer::pump`(`crates/server/src/lib.rs`)를 부릅니다. `pump`는 `WsServer::poll`로 꺼낸 메시지를 `Hub::handle_message`(`crates/server/src/hub.rs`)에 넘기고, 입력은 `Room::submit_input`(`crates/server/src/room.rs`)을 거쳐 `MemberInput::accept`(`crates/server/src/input.rs`)에 쌓입니다. 이미 받은 순서 번호보다 크지 않은 입력은 여기서 버립니다.
6. Tick 시각이 되면(`crates/server/src/clock.rs`의 `TickClock::due`) `Room::tick`이 플레이어마다 `MemberInput::for_tick`으로 이번 Tick의 입력 하나를 정하고 `Sim::step`(`crates/rules/src/sim.rs`)을 한 번 부릅니다.
7. `Sim::step` 안에서 `move_players`(`crates/rules/src/player.rs`)가 이동 방향에 속도(`Player::stats`가 돌려주는 값이고, 달리는 중이면 걷는 속도에 달리기 배율을 곱한 값입니다)와 Tick 길이를 곱해서 캐릭터를 옮기고(이동이 몸의 반지름 이상이면 같은 길이의 걸음으로 나눕니다), `crates/rules/src/collision.rs`가 걸음마다 장애물과 겹친 만큼 캐릭터를 밀어냅니다.
8. `Snapshot::from_sim`(`crates/protocol/src/snapshot.rs`)이 방 전체의 상태를 전송 형식으로 바꿉니다. `Room::tick`은 같은 스냅샷을 방의 모든 접속에 보내라는 `Out::Send`를 돌려주고, `GameServer::apply`가 `WsServer::send`를 불러서 `encode_server`로 바꾼 바이트를 보냅니다.
9. B의 클라이언트에서 `pump_network`(`crates/client/src/net.rs`)가 `WsClient::poll`로 스냅샷을 받고(`decode_server`), `Session::on_event`가 스냅샷을 `SnapshotBuffer`(`crates/client_core/src/interp.rs`)에 넣습니다.
10. `advance_playback`(`crates/client/src/net.rs`)이 재생 시각을 프레임 시간만큼 앞으로 보냅니다. `SnapshotBuffer`는 가장 최근 스냅샷보다 2 Tick(100ms) 이전 시점의 위치를 그 앞뒤 스냅샷 두 개 사이에서 선형으로 보간해서 `Frame`을 만듭니다.
11. `sync_characters`(`crates/client/src/characters.rs`)가 `Frame`의 지면 위치를 `convert::placement`(`crates/client/src/convert.rs`)로 화면 위치와 z 값으로 바꿉니다. 이 변환은 `crates/client_core/src/iso.rs`의 `ground_to_screen`과 `depth`를 씁니다. Bevy가 바뀐 `Transform`대로 도형을 그리면 B의 화면에서 A의 캐릭터가 움직입니다.

## 코드를 읽는 순서

Rust와 게임 개발을 처음 공부한다면 다음 순서로 읽습니다. 규칙에서 시작해서 프로토콜, 서버, 어댑터, 클라이언트 코어, 클라이언트로 나아갑니다.

1. `crates/rules/src/tuning.rs`에서는 게임의 모든 수치가 한 구조체에 모인 모습과, `Default` 트레이트 구현, 그리고 초를 정수 Tick으로 바꾸는 `Tuning::ticks`를 봅니다.
2. `crates/rules/src/sim.rs`의 `Sim::step`은 방의 단계에 따라 Tick의 일을 나누고, 원정의 Tick(`simulate`)은 Tick 하나의 처리 순서를 나열하며, `world`만 가변 참조로 넘기고 `tuning`과 `paths` 같은 다른 필드는 `Ctx`에 공유 참조로 빌려 주는 방식이 구조체 필드를 따로 빌리는 소유권 규칙의 첫 예입니다.
3. `crates/rules/src/player.rs`의 `Life`는 데이터를 가지는 열거형의 예이고, 쓰러진 플레이어가 HP나 쿨다운을 가지는 상태를 타입으로 표현할 수 없게 만듭니다. `crates/rules/src/loadout.rs`의 `Loadout`은 무기 두 칸을 타입으로 표현합니다. 든 무기(`held`)가 `Option`이 아니라서 「칸이 둘 다 빈 상태」를 만들 수 없고, 필드가 비공개라서 상태를 바꾸는 방법이 `swap`(`Q`)과 `take`(`F`로 줍기)와 `drop_held`(`G`) 셋뿐입니다. `crates/rules/src/weapon.rs`는 공격을 두 단계(`decide`가 공격을 모으고, `deliver`가 `Delivery`의 값에 따라 전달합니다)로 나누고, 무기마다 다른 수치는 `crates/rules/src/tuning.rs`의 무기 표(`WeaponTable`) 한 행에 둡니다. `crates/rules/src/projectile.rs`는 탄환을 쏜 플레이어와 따로 세계의 개체 목록에 두고, `crates/rules/src/sweep.rs`는 한 Tick에 움직인 선분 전체를 검사해서 빠른 탄환이 얇은 몬스터를 건너뛰지 못하게 하고, 탄환과 소총의 선이 몬스터를 앞에서부터 찾는 순서(`monsters_along`)를 정합니다. 소총은 `weapon.rs`의 `shoot`가 누른 Tick에 이 함수와 막힌 타일 검사를 한 번씩 부릅니다. `crates/rules/src/stamina.rs`의 `Stamina`는 정수 하나를 새 타입(newtype)으로 감싸서, 달리기 게이지를 소수 없이 정수 점수로 세는 방법을 한 곳에 모읍니다. `crates/rules/src/effect.rs`의 `MonsterEffects`는 효과마다 필드가 하나이고 필드가 비공개라서 값을 바꾸는 길이 `apply`와 `advance` 둘뿐이므로, 스턴이 걸려 있거나 면역인 몬스터에게 스턴을 거는 것 같은 규칙 위반을 다른 파일에서 만들 수 없습니다. 같은 파일의 `PlayerBuffs`는 `Life::Alive`만 가지므로, 쓰러진 플레이어가 버프를 가지는 상태도 만들 수 없습니다.
4. `crates/rules/src/world/tiles.rs`의 `TileMap`은 어디가 막혔는지 아는 유일한 곳이고, `crates/rules/src/build.rs`는 포탑을 놓을 수 있는 조건을 한 함수(`check_site`)로 판정합니다. `crates/rules/src/expedition.rs`는 낮, 밤, 새벽의 단계를 열거형(`Phase`)으로 두고 단계를 바꾸는 곳을 두 함수로 모았으며, 낮이 시작될 때 일어나는 일은 `begin_day` 하나에 있습니다. 그 위의 단계인 야영지, 원정, 결과 화면은 `crates/rules/src/stage.rs`의 `Stage`가 열거형 하나로 두고, 단계마다 그 단계에서만 의미 있는 값을 가지며, 단계를 바꾸는 곳은 `Sim`의 25. `crates/client/src/loot.rs`는 상자와 바닥의 무기를 스냅샷의 번호 목록에 맞춰 도형으로 만들고 갱신하고, 야영지의 진열대를 입장 안내의 자리에 놓습니다. `crates/client/src/camp.rs`는 허수아비가 맞은 피해를 상태에서 숫자로 띄웁니다. `crates/client/src/effects.rs`는 부채꼴 공격과 탄환과 소총의 사격 선과 포탑의 사격과 보스가 예고한 원과 띠와 포효의 고리와 노려지는 플레이어의 표시를 상태에서 선으로 그리고, 서 있는 범위형 포탑(감속 포탑, 공격 속도 포탑, 이동 속도 포탑)의 범위와 건설 미리 보기의 범위(`caravan_client_core::range_preview`가 정하는 대로, 지을 종류를 바꾼 뒤 2초 동안과 내가 짓는 동안에만)를 `caravan_client_core::range_rings`가 정한 대로 지면 위의 타원으로 그리고, 부채꼴의 거리와 각도는 입장 안내의 무기 표에서 읽습니다. `crates/client/src/towers.rs`는 포탑의 색을 종류가 정하고(감시탑은 파랑, 감속 포탑은 하늘색, 스턴 포탑은 흰색, 공격 속도 포탑은 장미색, 이동 속도 포탑은 연두색, 짓는 중인 포탑도 같은 색의 낮은 상자), HP 막대에 쓰는 최대 HP를 입장 안내의 종류표에서 읽습니다. `crates/client/src/view.rs`, `crates/client/src/towers.rs`, `crates/client/src/supplies.rs`, `crates/client/src/characters.rs`에서는 Bevy의 개체(entity)와 컴포넌트를 만들고 갱신하는 방법을 배우며, `characters.rs`는 명단에서 알게 된 이름을 캐릭터 위에 글자(`Text2d`)로 달고 효과에 걸린 몬스터의 몸통을 효과의 색(`Palette::effects`)으로 칠하며, 그 테스트는 `MinimalPlugins`로 창 없이 Bevy 시스템을 시험합니다.
26. `crates/client/src/hud.rs`는 `caravan_client_core::Hud`가 정한 내용(무기 두 칸, `G`의 안내, 지을 포탑의 종류와 비용, 내가 받은 버프의 이름, `F`의 안내, 상자를 여는 진행 막대, 야영지의 방 코드와 준비 목록, 결과 화면의 요약과 개인별 기록의 표와 확인 인원, 보스가 오기 전의 경고 문구, 보스의 HP 막대, 나가기 확인 창)을 Bevy UI 노드에 옮깁니다. 표는 글꼴의 글자 너비가 같다는 점을 이용해서 `crates/client_core/src/hud.rs`가 칸마다 너비를 맞춘 글자 줄로 만들고, 이 파일은 그 줄들을 노드 하나에 줄바꿈으로 이어서 보여 줍니다.

## 현재의 한계

- 클라이언트 예측이 없습니다. 내 캐릭터도 서버의 스냅샷으로만 움직이므로, 키를 누른 뒤 서버까지의 왕복 시간과 보간 지연(100ms)이 지나야 화면에서 움직입니다.
- 접속이 끊기면 시작 화면으로 돌아오고 이유가 표시됩니다. 서버는 그 플레이어의 자리를 60초 동안 유지하고, 그 안에 `Enter`를 누르면 같은 캐릭터로 돌아옵니다. 클라이언트가 자동으로 다시 접속하지는 않습니다. 같은 방에 사람이 하나뿐이어도 자리가 유지되는 동안 방은 멈춰 있을 뿐 사라지지 않고, 60초가 지나면 자리와 방이 함께 없어집니다.
- 서버는 Tick마다 방 전체의 스냅샷(모든 플레이어, 몬스터, 시설, 날아가는 탄환, 상자, 바닥의 무기)을 방의 모든 접속에 보냅니다. 바뀐 부분만 보내지 않습니다.
- 브라우저 탭이 백그라운드로 가면 브라우저가 페이지의 실행을 제한해서 입력 전송이 멈춥니다. 서버는 입력 없이 10 Tick(0.5초)보다 오래 지나면 그 캐릭터를 아무것도 누르지 않은 상태로 움직이고, 3초가 지나면 그 사람을 자리를 비운 것으로 보고, 메시지 없이 30초가 지나면 접속을 닫습니다. 자리는 마지막 메시지부터 60초 동안 남습니다. 다만 같은 주소(IPv6는 같은 /64 대역)가 동시에 유지시킬 수 있는 자리는 8개까지이고(`max_held_seats_per_ip`), 한 주소에서 그보다 많은 자리가 동시에 끊기면 넘친 자리는 유지되지 않고 곧바로 없어집니다. 서버 전체에서 유지하는 자리도 128개까지이고(`max_held_seats`), 이미 128개를 유지하는 동안 새로 끊긴 자리는 유지되지 않고 곧바로 없어집니다(이미 유지 중인 자리는 그대로입니다). 약속을 어겨서(입장 전의 입력, 두 번째 입장 요청) 서버가 닫은 접속의 자리는 곧바로 없어집니다. 한도(1초의 메시지 수, 메시지의 크기, 느린 읽기)를 넘어서 닫힌 접속의 자리는 끊긴 접속처럼 유지합니다. 네트워크가 4초보다 길게 멈췄다가 풀리면 밀린 입력이 한꺼번에 도착해서 메시지 수의 한도에 닿으므로, 그 사람은 접속이 닫힌 뒤 `Enter`로 돌아와야 합니다. 접속이 닫힌 탭으로 돌아오면 시작 화면이 나와 있고, 60초 안에 `Enter`를 누르면 같은 캐릭터로 돌아옵니다.
- 서버는 TLS를 처리하지 않으므로 서버가 직접 받는 접속은 `ws://`와 `http://`뿐입니다. 친구가 `https://`로 접속하는 것은 터널(`cloudflared`)이 TLS를 끝내고 `http://127.0.0.1`로 넘기기 때문이고, `https://` 페이지에서는 브라우저가 `ws://` 접속을 막으므로 페이지와 게임 접속이 같은 터널을 지납니다. 친구는 PC 클라이언트가 아니라 브라우저로 들어옵니다.
- 서버의 기본 주소와 `trunk serve`의 주소(`crates/client/Trunk.toml`)는 `127.0.0.1`이므로, 기본 설정에서는 같은 컴퓨터에서만 접속할 수 있습니다. 다른 컴퓨터는 `sh scripts/playtest.sh`가 켠 터널의 https 링크로 접속합니다. 터널 없이 `--addr 0.0.0.0:7777`로 서버를 켜면 같은 네트워크의 컴퓨터가 `ws://`로 접속할 수 있지만, 이 방식에는 TLS가 없습니다. 모바일 브라우저와 터치 조작은 지원하지 않습니다.
- 빠른 터널은 가동 시간을 보장하지 않고 켤 때마다 주소가 바뀝니다. 스크립트를 다시 켜면 링크가 바뀌므로 방을 다시 만들어야 합니다. 플레이 도중에 터널이 끊기면 모두의 접속이 끊기고, 60초 안에 같은 링크로 돌아와야 자리가 남습니다. 스크립트를 다시 켠 뒤에는 나도 `127.0.0.1`의 페이지를 새로 고쳐야 초대 링크가 새 주소로 복사됩니다. 터널을 거치는 친구는 왕복 시간이 늘어난 만큼 조작이 늦게 보이고(클라이언트 예측이 없습니다), `127.0.0.1`로 접속하는 나는 그 지연을 직접 느끼지 못합니다.
- 터널 뒤에서는 모든 접속이 터널 프로그램의 주소(`127.0.0.1`)에서 온 것으로 보이므로, 주소마다의 한도(동시 접속 16, 유지하는 자리 8)가 나와 모든 친구에게 합쳐서 적용됩니다. 한 방은 4명까지이므로 방 하나에는 충분하지만, 동시 접속이 16을 넘는 플레이테스트는 대상이 아닙니다. 같은 이유로, 링크를 아는 사람 하나가 접속 16개를 열어 두면 다른 사람은 입장하지도 페이지를 열지도 못합니다(진행 중인 게임은 계속됩니다). 이 서버는 그 사람을 다른 사람과 구분하지 못하므로, 그런 일이 생기면 스크립트를 다시 켜서 링크를 바꿉니다. 파일 요청은 요청의 머리를 읽는 동안만 이 접속 자리를 차지하고, 파일을 보내는 동안에는 따로 둔 파일 전용 자리 16개(`max_file_responses`)를 차지합니다. 파일 전용 자리가 모두 차 있으면 새 파일 요청은 `503`을 받고, 받는 쪽이 3초(`write_timeout`) 넘게 읽지 않으면 그 요청은 끊깁니다. 계속 읽더라도 파일 하나의 응답은 「10초(`file_response_grace`) + 파일의 크기 ÷ 초당 128KiB(`file_min_bytes_per_sec`)」가 지나면 끊깁니다. 45MB의 `.wasm`은 약 6분이고, 작은 파일은 유예 10초가 대부분이므로 훨씬 느리게 받아도 끊기지 않습니다. 이 시간은 서버가 터널 프로그램에 파일을 넘기는 시간이므로, 실제로 걸리는 것은 내 컴퓨터의 올리는 회선입니다. 친구 여럿이 동시에 페이지를 열면 그 회선을 나누어 씁니다(네 명이 `.wasm`을 6분 안에 받으려면 약 4Mbit/s, 추정이고 재지 않았습니다). 그래서 느리게 받는 요청이 파일 전용 자리를 정해진 시간보다 오래 차지하지 못합니다. 이 동안에도 게임 접속은 영향을 받지 않습니다.
- `--web-dir`의 파일은 서버를 켤 때 읽습니다. 웹 클라이언트를 다시 빌드하면 서버를 다시 켜야 하고, 서버는 `.wasm` 파일을 메모리에 가지고 있습니다. `trunk serve`가 아닌 다른 정적 서버로 웹 빌드를 내주면 공개 주소 자리가 채워지지 않은 채 남아서, 그 페이지는 `ws://127.0.0.1:7777`에 접속합니다. 스크립트가 포트를 확인한 뒤 서버가 그 포트를 잡기까지의 짧은 사이에 다른 프로그램이 그 포트를 잡으면, 서버가 실패하기 전까지 터널이 그 프로그램을 공개합니다. 이때 스크립트는 링크를 출력하지 않고 터널을 끄고 끝납니다.
- 한 방의 최대 인원은 4명입니다(`crates/rules/src/tuning.rs`의 `max_players`). 가득 찬 방에 접속한 클라이언트는 거절되고 화면에 이유가 표시됩니다.
- 접속이 끊긴 자리는 접속 수의 한도(`max_links`, `max_links_per_ip`)에 들지 않으므로, 서버는 접속자가 없는 방을 주소마다 유지하는 자리의 수(`max_held_seats_per_ip`, 기본 8)와 서버 전체의 유지하는 자리의 수(`max_held_seats`, 기본 128)로 묶습니다. 주소는 IPv4는 전체이고 IPv6는 앞 64비트(/64)입니다(`crates/protocol/src/transport.rs`의 `PeerKey::of`, 접속 수를 세는 `caravan_ws_server`도 같은 함수를 씁니다). 방 전체의 수는 256개까지입니다(`max_rooms`). 끊긴 자리의 한도는 방의 한도보다 작으므로 접속자가 없는 방만으로 새 방을 막을 수 없습니다. 이 한도들은 `crates/protocol/src/limits.rs`에 있고, 방의 한도에 닿으면 새 방을 만드는 입장이 거절되고 화면에 이유가 표시됩니다. 있는 방에는 계속 들어갈 수 있습니다. 리버스 프록시 뒤에서는 모든 접속이 주소 하나로 보이므로 `max_links_per_ip`와 `max_held_seats_per_ip`를 함께 올려야 합니다.
- 방 목록이 없으므로 같은 방에 모이려면 방 코드나 링크를 서로 알려 주어야 합니다. 서버는 같은 이름을 막지 않으므로 한 방에 같은 이름이 둘 있을 수 있습니다.
- 맵은 64 x 64 타일 하나이고, 원정의 몬스터는 기본 몬스터와 돌격병과 파괴병 세 종류와 마지막 밤의 보스 하나(야영지의 허수아비는 따로), 시설은 포탑 하나(종류는 감시탑, 감속 포탑, 스턴 포탑, 공격 속도 포탑, 이동 속도 포탑), 자원은 한 종류입니다.
- 보스의 수치(HP 12,000, 걷는 속도 1.2, 포탑의 피해 10%, 내려찍기와 돌진의 예고 1.5초, 걷는 시간 3초와 HP가 절반 이하일 때 2초, 졸개 12마리)와 돌격병이 받는 포탑의 피해(25%)와 파괴병의 수치(HP 120, 속도 1.7, 포탑에 주는 피해 40, 받는 포탑의 피해 30%, 셋째 밤의 수 10과 20, 2명 이상의 방에서만 나옴)는 규칙 테스트와 모의 전투로만 정했고 사람이 한 플레이테스트로 맞추지 않았습니다. 모의 전투의 입력은 쉬지 않고 때리고 예고를 0.3초만 늦게 읽으므로 사람보다 빠릅니다. 이 입력에는 포탑을 짓는 일과 수리하는 일이 없습니다. 기본 수치(감시탑 15개)에서 모의 전투가 보스를 잡는 데 걸린 시간은 검 1명 93초, 2명 192초, 3명 159초, 4명 140초이고, 활은 90초, 179초, 134초, 119초, 창은 79초, 162초, 133초, 120초입니다. 모두 성공했고 끝났을 때 모든 플레이어가 서 있었습니다. 끝난 마차의 HP는 검이 500, 476, 468, 420이고 활이 500, 468, 468, 364이고 창이 500, 484, 468, 436입니다. 2명 이상의 방에서는 한 명이 마차를 지키므로 보스를 때리는 사람이 줄어서 시간이 길어집니다.
- 돌격병은 감시탑 하나가 사격을 여덟 번 해야 처치하므로, 감시탑이 졸개 12마리(네 명일 때)를 모두 처치하지 못하는 것으로 보입니다. 마차를 지키는 사람이 있을 때와 없을 때 끝난 마차의 HP가 다르다는 것이 근거이고, 마차를 때린 돌격병의 수는 이 저장소의 테스트가 세지 않습니다. 모의 전투에서 마차를 지키는 한 명이 있는 쪽과 없는 쪽(모두가 보스를 때립니다)의 끝난 마차의 HP는 다음과 같습니다. `패`는 마차가 부서져 실패한 것입니다. 표의 값은 한 번씩 돌린 값이고, 씨앗이나 시작 자리를 바꾼 반복은 이 표에 없습니다.
